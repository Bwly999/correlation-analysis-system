// 支柱四 / STRUCTURED EXECUTION

结构化执行与反馈机制断言

结构化执行要求将思考规划与代码修改彻底分离。所有决策必须落在规格层面，执行成果必须接受基于本地编译器、Linter 和单元测试套的自动化断言验证。

研究与计划先行 (PEV)
刻意施加 理解 → 规划 → 执行 → 验证 交互步幅。在方案设计阶段写明实现路径与潜在影响，经人类批准方可开始改码，杜绝低效修补。
增量自动测试校验
集成测试环境。利用 Vitest 在本地拉起单元测试，通过 pnpm test:unit -- <pattern>（如 `workflowStore`）进行关键业务状态层的高频断言。
自定义 Linter 教学式报错
借鉴 OpenAI 最佳实践。Linter 报错信息不仅拦截违规，还直接在输出日志中包含“修复教学方案”，使 Agent 无需二次探索即可精准自愈。
基于编译异常的自愈循环
将编译器/测试 stderr 日志以反馈回路形式重定向，注入 Agent 的交互上下文中，促使模型执行 报错感知 → 更新假设 → 再次修复 直至全绿。
