// 支柱三 / PERSISTENT MEMORY

持久化记忆与防翻车机制

在长链路、跨越数小时的编码任务中，Agent 会话往往频繁断开重启。Harness 将进度持久化在本地文件系统（制品介质）中，而非纯上下文窗口内，从而消灭 Agent 常见的翻车模式。

mode 1
一步到位（One-shotting）导致爆仓
Agent 倾向一次做完所有事，导致上下文窗口在行至一半时耗尽。重启会话时面对没有文档的半成品，只能耗费大量 Token 瞎猜历史。
mode 2
过早宣布胜利（Premature Done）
在项目后期，当部分节点实现后，Agent 会看到已有进展直接单方面宣布任务完成——即使很多复杂功能和单元测试并未真正交付。
mode 3
环境启动困难（Env Hardship）
每次新会话启动，Agent 都需要耗费数千 Token 盲目猜测如何启动开发服务器与测试套，而非立刻将智能投入在多因子系统的核心代码开发中。
// 跨会话环境重启与自检流（PROJECT REBOOT PROTOCOL）
01
定位与感知
运行 pwd 绝对路径并扫描文件，确认本地开发环境。
02
Git 与进度快照重组
读取 git log -n 5 和进度描述，建立最近改动的精确心智模型。
03
持久化任务跟踪 (JSON Formatted)
读取 task.md 或 JSON 文件，自动装载优先级最高且未完成的特性。使用 JSON 可以防止 Markdown 格式被 Agent 意外篡改。
04
本地服务器与测试拉起
触发 npm run dev 并执行一次 Vitest 单元测试，确认基础环境正常，规避带病工作。
05
增量演进
正式开始新功能实现，每次提交时持久化一份结构化进展快照。
