上下文分层与 Agent 角色特化

为防范上下文过载（Dumb Zone），项目在多因子分析系统的开发中实践了渐进式披露上下文与角色职责特化，使 Agent 始终工作在前 40% 的 Smart Zone 内。

Tier 1常驻层
全局规约: AGENTS.md / GEMINI.md
每次会话自动挂载。包含项目目录、开发命令与强制的架构分层顺序约束：Types → Config → Repo → Service → Runtime → UI。
Tier 2按需层
技能路由与角色包: SKILL.md
当存在 1% 意图相关时触发路由。如 huashu-design 引入 Slate-900 暗色 SaaS 调色盘、组件 hover 动效及无占位图约束，接管默认提示词。
Tier 3冷记忆
外部事实源与知识库 (Cold Memory)
针对复杂的 Vue Flow 拓扑编排、Pinia 架构与 Drizzle ORM，Agent 通过 grep_search 和 read_file 进行渐进式深度读取。
RE
研究 Agent (Research Role)
探索代码库、分析实现细节。例如分析 src/nodes/registry.ts 节点注册及 API 路由。拥有只读工具权限，防止文件篡改。
READ ONLY
EX
执行 Agent (Execute Role)
限定仅能修改与目标任务强关联的模块，如修改 src/components/workflow/config/ 以支持特定节点属性配置。
CONTAINED WRITE
RV
审查与垃圾回收 (Review & Clean Role)
审查代码，运行 custom linter。在前端移除因修改而失效的悬空 import 和未使用的 Pinia mutations，对抗项目熵增。
REFRACTOR & GC
