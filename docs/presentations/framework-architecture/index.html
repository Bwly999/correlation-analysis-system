Core Components · 节点体系

三大节点类型

Trigger

数据源接入

文件导入、邻居系统对接、JSON 模拟。作为分析流的起点。

Action

特征工程

去重、异常值处理、字段选择、横向合并、代码转换等。负责数据加工。

Terminal

算法分析

逻辑回归、随机森林、SHAP、Lasso 等。作为分析流的终点，输出可视化报告。

连接规则：Trigger → Action → Terminal。Terminal 不再输出，确保流程有终点，结果可预期。

我们把复杂的分析过程拆解为这三类节点。这种设计让我们未来接入新的算法（Terminal）或新的清洗逻辑（Action）变得非常简单。

Standardization · 标准化设计

声明式设计：更强的扩展性

1. 节点定义标准化

开发者只需编写一份 NodeDefinition 配置，即可自动生成 UI 配置弹窗、帮助文档和执行逻辑。极大地降低了二次开发成本。

2. 结果协议统一化

所有节点输出强制遵循 NodeResult 协议（表格、图表、指标、报告）。Viewer 组件根据协议自动匹配最佳渲染方式。

// 伪代码示例
interface NodeDefinition {
  name: string;
  properties: Property[];
  execute: (input) => Promise<NodeResult>;
}
“约定大于配置”是本系统的核心思想。通过标准化的定义和协议，我们实现了真正意义上的“插拔式”算法能力。
