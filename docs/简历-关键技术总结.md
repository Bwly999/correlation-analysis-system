# 简历用 · 关键技术总结

> 项目：多因子相关性分析系统（n8n 风格工作流编辑器 + 执行引擎 + AI Agent 分析平台）
> 技术栈：Vue 3 + TypeScript + Vue Flow + Pinia + PrimeVue + Tailwind v4 + ECharts ｜ Node.js + Fastify + Drizzle ORM + MySQL/LowDB ｜ Pyodide(WASM) ｜ Vercel AI SDK / Pi Agent SDK
> 提取自：代码、设计文档、git 历史（约 500 次提交的完整演进轨迹）

---

## 一句话定位

一个面向制造业质量分析场景的**低代码数据分析平台**：用户拖拽节点搭分析流程，系统执行并产出图文报告；并内建**三个独立 AI Agent 子系统**（工作流编排助手 / JS 节点编程助手 / Pyodide 自由分析笔记本），覆盖"显式编排"和"自由分析"两种数据科学工作范式。

---

## 简历可放的技术亮点（按重要性排序，挑 4–6 条）

### 1. 设计并落地「前端执行 + 后端调度」的 Agent 工具调用架构

提出并实现了 **FrontendBridge 模式**：后端 Agent（基于 `@earendil-works/pi-coding-agent` SDK）只负责 LLM 推理与工具调度，所有"改变世界"的动作（修改画布、执行工作流、运行 Python）都通过 `tool.execute` 事件下发到前端执行，前端再用 HTTP `tool-result` 回传结果，后端挂起的 Promise 被 resolve 后继续推理。

- 解决了"画布的真实状态在浏览器内存里、后端够不到"的核心矛盾
- 实现了**请求-响应配对**（toolCallId）、**超时续期心跳**、**Promise 挂起/恢复**、**用户级会话隔离**
- 这是该系统 Agent 能力的**基石架构**，三个 Agent 子系统全部复用同一套 FrontendBridge

> 文件锚点：`src/server/piAgent/frontendBridge.ts`、`src/stores/piAgentStore.ts:handleToolExecute`

### 2. 设计 Agent 全双工事件流协议与可控的断线恢复

为三个 Agent 子系统设计了统一的流式事件协议（标准 SSE `text/event-stream`，对齐 OpenAI/Anthropic 等主流 LLM API 格式；因原生 EventSource 不支持自定义 header 走统一 axios JWT 注入，采用 fetch + 手写 SSE 解析）：

- 统一了 `message.delta`（流式文本）、`message.thinking_delta`（思考链）、`tool.start/end`、`tool.execute`、`session.stop_diagnosis`、`follow_up_queued/drained` 等十几种事件类型
- 15s 心跳保活、`X-Accel-Buffering: no` 绕过 nginx 缓冲、连接断开自动清理
- 前端用 axios 的 `fetch` adapter + `AbortController` 消费流，并实现了**可控的断线恢复**（连接断了不靠自动重连，而是重新 GET session 快照，把消息/工具调用/停止原因全部重建——因为 Agent 会话有状态，自动重连会拿到时序错乱的流）

> 文件锚点：`src/server/http/sseStream.ts`、`src/server/piAgent/eventBridge.ts`

### 3. 基于浏览器 Pyodide (WASM) 的 Notebook Agent —— 把 LLM 解放成"带沙箱的数据科学家"

构建了一个**独立于画布的 AI 数据分析笔记本**：Agent 在浏览器内的 Web Worker 里跑 Python（Pyodide），像 Claude Code 那样"跑→看→改假设→再跑"，产出图文报告。

- **三层进程模型**：主站 ↔ iframe（COI 隔离）↔ Pyodide Worker，全用 `postMessage RPC` 通信
- **6 层纵深防御**的安全模型：WASM 沙箱 / iframe COI / Pyodide `jsglobals` 锁定（Python 拿不到 `globalThis`）/ Worker 出站能力剥夺（删 `fetch/XHR/WebSocket/indexedDB`）/ 业务超时配额 / 审计日志
- **20 项红队清单**自动化回归（写 `/etc/passwd`、`from js import globalThis`、`os.system('rm -rf /')`、死循环、OOM 等）
- 双文件系统方案（OPFS 持久层 + MEMFS Python 可见层 + 显式 sync），绕开 Pyodide 官方 `mountNativeFS` 的两个硬伤：默认不同步（需手动 `syncfs()`）+ Experimental 仅 Chromium 支持
- **bootstrap 竞态修复**：events 订阅 + 数据 ready 双条件成立才触发首轮 prompt（有 E2E 回归测试）

> 这部分是项目技术含量最高、最能体现"工程深度"的一块。

### 4. 工作流执行引擎与标准化结果协议

设计了一套 **n8n 风格的工作流系统**（约 2700 行核心 store）：

- **拓扑递归执行**：单节点执行递归跑上游、全局执行选 Terminal 节点逐个执行；支持冻结输出复用、单节点调试（复用缓存上游 / 重跑上游）、手动模拟输入、运行时输入补参
- **标准化的 NodeResult 协议**：统一 `kind`（table/matrix/report/chart/scalar...）+ `schema`（自动字段类型推断）+ `preview.viewer`（声明式渲染路由），让 ~30 个节点和所有 viewer 解耦
- **~30 个分析节点**：文件导入、数据清洗、字段塑形、聚合合并、相关性分析、VIF/PCA/ANOVA、XGBoost+SHAP、Lasso、随机森林、逻辑回归等（部分前端纯 JS 算，部分代理到后端 Python）
- **AG-Grid 虚拟滚动 + ECharts** 解决大数据量预览性能

### 5. 前后端同仓 + 双存储抽象 + 依赖注入组合根

- 服务端用 **Fastify**（含 CORS / JWT 鉴权 / 工作流用户解析 / API 打点 / COI 响应头插件），**esbuild 打包**成自包含 ESM、**tsx** 开发热更
- **双存储抽象**：同一套 `WorkflowStorageRepository` 接口，dev 用 LowDB（本地 JSON 文件），prod 用 MySQL（Drizzle ORM），通过 `WORKFLOW_STORAGE_BACKEND` 环境变量 + 工厂切换；运行历史大对象迁移到 **S3 对象存储**
- **组合根**（`bootstrap/storageCompositionRoot.ts`）做依赖注入，可注入 mock 仓储做测试
- 前端**统一 axios 请求层**，禁止业务模块裸 fetch / 手拼 baseURL

### 6. 架构演进能力（从 git 历史可见的工程判断）

- 经历过 **3 代 AI 架构**：①workflow-ai（Vercel AI SDK 直接生成 JSON 工作流，已废弃）→ ②opencode（OpenCode/MCP，已废弃）→ ③Pi Agent 主链（基于 pi-coding-agent SDK 的工具调用 Agent，当前生产方案）
- 多次果断重构：纯 Node HTTP → **Fastify 重构**、原始 SQL → **Drizzle ORM 重构**、收口旧 AI 架构并保留 404 回归测试
- 配套**评测体系**（`scripts/agentic-analysis-evaluation`、`workflow-mcp-evaluation`），用 XML 用例集自动跑 Agent 端到端验收

## 技术关键词清单（ ATS 友好，按类目）

**前端**：Vue 3 (Composition API, `<script setup>`)、TypeScript、Vue Flow（节点画布）、Pinia、PrimeVue v4、Tailwind CSS v4、ECharts / vue-echarts、AG-Grid（虚拟滚动）、VueUse、Monaco Editor、axios（统一请求层 + fetch adapter 流式）

**Python / 沙箱**：Pyodide（WASM）、Web Worker、SharedArrayBuffer + Atomics（软中断）、Cross-Origin Isolation（COOP/COEP）、OPFS（Origin Private File System）、postMessage RPC

**工程化**：Vite、Vitest + jsdom + @vue/test-utils、ESLint + Prettier、vue-tsc、Playwright E2E、unplugin-auto-import、pnpm、pm2 进程管理、Docker 本地复现

**架构能力**：低代码平台、节点式工作流引擎、拓扑执行、协议设计（标准化结果/viewer 注册）、前端执行型 Agent、纵深防御安全模型、组合根依赖注入、评测驱动开发
