## 快速上手

目标：**5 分钟跑通一条完整链路**——导入数据 → 字段筛选 → 相关性分析 → 查看报告。

> 如果你不想自己搭流程，可以直接跳到 [05-AI分析](#ai-分析分析笔记本)，把数据交给 AI 帮你分析。

---

### 第 0 步：进入系统

打开系统主页面，你会看到一个空白画布和顶部工具栏。

顶部工具栏从左到右大致是：

- **新建** — 创建一个空白工作流
- **模板** — 从内置模板开始（推荐第一次使用）
- **保存** — 保存当前工作流
- **帮助** — 应用内帮助中心
- **Pi Agent** — 打开 AI 助手面板
- **AI 分析** — 进入分析笔记本
- **文件** — 导入/导出工作流文件
- **运行历史** — 查看最近的运行记录（最近 20 条）

---

### 第 1 步：从一个模板开始（最快）

1. 点击顶部 **「模板」** 按钮。
2. 选择 **「相关性排查模板」**（最适合第一次上手）。
3. 确认后，画布上会出现一条已搭好的流程，通常长这样：

```
手动输入数据 → 字段筛选 → 单调性分析
```

模板默认用「手动输入数据」节点提供一份样例数据，所以**直接就能跑**，不需要你先准备文件。

---

### 第 2 步：运行工作流

有两种运行方式：

| 方式 | 怎么做 | 适合 |
|------|--------|------|
| **整条运行** | 点击画布工具栏的「运行」按钮 | 第一次跑通整条链路 |
| **单节点运行** | 悬浮某个节点 → 点击节点上方的 ▶ 运行图标 | 只想看某个节点改完参数后的结果 |

第一次建议直接**整条运行**。运行过程中：

- 节点边框变 **蓝色** = 正在运行
- 节点边框变 **绿色** = 运行成功
- 节点边框变 **红色** = 运行出错（鼠标悬浮可看错误）

---

### 第 3 步：查看结果

运行成功后，**悬浮绿色的节点**，点击上方出现的 **「预览」图标（眼睛）**，就会弹出该节点的结果预览。

以「单调性分析」节点为例，结果通常包含：

- **相关性排序** — 哪些因子和目标最相关
- **显著性提示** — 这个相关是否 statistically significant
- **热力图** — 多变量间的相关性全景

> 怎么读懂这些图，见 [04-结果与报告解读](#结果与报告解读)。

---

### 第 4 步：换成你自己的数据

模板用的是样例数据。要分析真实数据，把第一个节点换掉即可：

1. 右键 / 悬浮「手动输入数据」节点，删除它。
2. 从左侧节点库拖一个 **「本地文件导入」**（`file-import`）节点到画布。
3. 在节点配置里上传你的 CSV / Excel / JSON 文件。
4. 把它连到后面的「字段筛选」节点。
5. 重新运行。

> 系统也支持从看板系统直接取数，见 [附录 A-看板数据对接](#附录-a看板数据对接)。

---

### 第 5 步：调整分析参数（可选）

双击或悬浮「单调性分析」节点 → 点 **配置** 图标，打开配置弹窗。几个关键参数：

- **目标字段 (Y)** — 你想解释/预测的指标（如良率、缺陷数）
- **候选因子 (X)** — 你怀疑有影响的工艺变量
- **方法** — Pearson（线性）/ Spearman（单调）/ Kendall（秩相关），不知道选哪个就先用 Pearson

改完参数，**单节点重跑**即可秒级看到新结果（会复用上游已有数据）。

## 工作流编辑器

工作流编辑器是系统的主界面：一块画布 + 左侧节点库 + 顶部工具栏 + 底部日志栏。
你通过**拖拽节点**和**连线**搭建分析流程，系统按顺序执行并标准化输出结果。

---

### 1. 画布基础操作

| 操作 | 方式 |
|------|------|
| 添加节点 | 从左侧节点库**拖拽**到画布 |
| 平移画布 | 鼠标拖拽空白处 |
| 缩放 | 滚轮 / 触控板捏合 |
| 选中节点 | 单击节点 |
| 多选 | 框选 / Shift+点击 |
| 删除节点 | 选中后悬浮节点 → 点删除图标，或选中后 Delete 键 |

---

### 2. 节点工具栏（悬浮节点出现）

把鼠标移到任意节点上，节点上方会浮现一组操作图标：

| 图标 | 功能 | 说明 |
|------|------|------|
| ▶ 运行 | 单节点运行 | 只跑这一个节点，复用上游已有数据，秒级出结果 |
| ↻ 重跑（含上游） | 强制重跑 | 连带上游节点一起重新执行 |
| ⚙ 配置 | 打开配置弹窗 | 设置节点参数 |
| 👁 预览 | 查看结果 | 运行成功后查看该节点输出的数据/图表 |
| 📌 冻结 (Pin) | 冻结节点数据 | 冻结后，整条运行会**跳过**该节点，保留当前结果不变 |
| 复制 | 复制节点 | 连同配置一起复制 |
| 删除 | 删除节点 | — |
| ✏ 重命名 | 修改节点显示名 | 仅影响显示，不影响逻辑 |
| 连线 | 发起一条新连线 | 从当前节点拉一条线到下游 |

> **冻结（Pin）的典型用途**：某个上游数据导入节点跑一次很慢，下游你在反复调参试错。把导入节点冻结，之后每次只重跑下游，省去重复导入。

---

### 3. 连线规则

系统对节点之间的连线有严格规则，**不满足规则的连线会被拒绝**。

| 起点 \ 终点 | Trigger（触发） | Action（处理） | Terminal（终点） |
|-------------|-----------------|----------------|------------------|
| **Trigger** 数据源 | ❌ | ✅ | ✅ |
| **Action** 处理 | ❌ | ✅ | ✅ |
| **Terminal** 终点 | ❌ | ❌ | ❌ |

三类节点的角色：

- **Trigger**（触发器）— 流程的起点，负责把数据引进来（导入文件、手动输入、看板取数）。不能再向其他 Trigger 连线。
- **Action**（处理）— 中间节点，做清洗、筛选、字段处理等。可以串多个 Action。
- **Terminal**（终点）— 流程的终点，做分析和输出（相关性、模型、图表、导出）。不能再向外连线。

**简单记法：数据只能从 Trigger → Action → Terminal 单向流动，不能倒流，也不能在终点后再接节点。**

#### 多输入节点

部分 Action 节点支持**多个输入**（如「数据合并」`data-merge`），可以把多个上游节点的数据合并到一起。这类节点有多个输入槽位。

---

### 4. 运行与调试

#### 整条运行

点击画布工具栏的「运行」按钮，系统会按拓扑顺序从 Trigger 开始执行整条链路。

#### 单节点调试（推荐用于调参）

悬浮节点 → 点 ▶ 运行图标。系统**复用上游缓存**，只重跑当前节点，秒级返回结果。适合反复调整算法参数时快速验证。

运行中节点边框颜色含义：

- 🔵 蓝色（脉冲）— 正在运行
- 🟢 绿色 — 成功
- 🔴 红色 — 失败（悬浮看错误信息）

#### 停止运行

运行过程中可以点「停止」中断执行。

#### 冻结跳过

被 📌 冻结的节点，整条运行时会**自动跳过**，保留其当前输出。这是调试复杂流程时省时间的关键手段。

---

### 5. 运行历史

顶部工具栏的「运行历史」记录**最近 20 条**运行记录。每条记录显示：

- 运行时间、耗时
- 状态（成功 / 失败 / 中断）
- 点击可**查看该次运行的详情**（历史快照）

> 历史快照让你能回到某次运行查看当时的节点配置和数据，便于对比不同参数下的结果。

---

### 6. 保存与未保存提示

#### 保存

- 点击顶部 **「保存」** 按钮。
- 当工作流**有未保存的修改**时，按钮文案会变成 **「保存更改」**，提醒你存盘。
- 保存成功后会出现提示。

#### 未保存提醒

当存在未保存的改动时，在以下场景下系统会提示你是否保存：

- 切换到另一个工作流
- 新建工作流
- 关闭页面

**建议养成习惯**：改完就存，避免丢失。

#### 工作流管理

通过「文件」菜单 / 工作流管理中心可以：

- 查看所有已保存的工作流
- 复制工作流（会弹出命名框，名称有默认值）
- 删除工作流
- 导入 / 导出工作流文件

## 节点手册

节点是工作流的基本单元。每个节点做一件事：导入数据、清洗、做一次分析、或输出结果。把节点连起来，就是一条分析流程。

本手册按**职能分类**组织，共五大类：

| 分类 | 篇章 | 干什么 |
|------|------|--------|
| 导入数据 | [3-1 导入数据](#3-1-导入数据) | 把数据引进工作流（文件、手动输入、看板取数） |
| 清洗与筛选 | [3-2 清洗与筛选](#3-2-清洗与筛选) | 去重、处理缺失/异常值、编码缩放、按条件过滤 |
| 字段与结构处理 | [3-3 字段与结构处理](#3-3-字段与结构处理) | 选字段、排序、限量、多表合并、JS 自定义转换 |
| 合并与聚合 | [3-4 合并与聚合](#3-4-合并与聚合) | 分组统计、移动窗口、时间窗口 |
| 分析与导出 | [3-5 分析与导出](#3-5-分析与导出) | 相关性、模型、方差、PCA……以及结果导出 |

> 一张全表速查见 [附录 B-节点速查总表](#附录-b节点速查总表)。

---

### 节点的三类角色

每个节点属于以下三类之一（决定它**能连到哪里**，见 [02-工作流编辑器 · 连线规则](#3-连线规则)）：

| 角色 | category | 作用 | 能否再连线出去 |
|------|----------|------|----------------|
| 触发器 | `trigger` | 流程起点，引入数据 | 可连 Action / Terminal |
| 处理 | `action` | 中间步骤，加工数据 | 可连 Action / Terminal |
| 终点 | `terminal` | 分析、出图、导出 | **不能**再连线 |

---

### 关于"活跃节点"与"旧版节点"

节点库里你**能新建**的都是**活跃节点（active）**。

系统中还存在少量**旧版节点（legacy）**——它们只用于**打开历史保存的老工作流**，不会出现在新建节点库里。本手册只讲活跃节点；如果你打开一个老工作流看到不认识的节点（如单独的 `pearson`、`data-cleaning`），它的功能已被新的活跃节点取代：

| 旧版节点 | 现在用什么 |
|----------|------------|
| `pearson` / `spearman` / `kendall` | 用 `correlation-analysis`（内部可切换三种方法） |
| `data-cleaning` | 用 `data-dedup` + `data-missing-outlier` + `data-encoding-scaling` 拆分完成 |
| `chart-display` | 结果预览自带的图表能力 |
| `data-export` | 结果预览自带的导出能力 |

---

### 每个节点说明的结构

每篇分类文档里，每个节点按以下结构介绍：

- **用途** — 一句话说清这个节点干什么
- **什么时候用** — 典型场景
- **关键参数** — 只列影响结果成败的参数（常规参数看节点配置弹窗里的说明）
- **输出** — 这个节点产出什么类型的数据
- **下一步** — 结果通常连到哪类节点

---

### 3-1 导入数据

导入数据节点（`trigger` 类）是每条工作流的**起点**，负责把数据引进来。
没有导入节点，后面的节点无米下锅。

| 节点 | 显示名 | 输入 | 输出 | 适用场景 |
|------|--------|------|------|----------|
| `file-import` | 本地文件导入 | — | table | 有 CSV / Excel / JSON 文件 |
| `manual-json-import` | 手动输入数据 | — | table / json | 调试、构造最小测试样例 |
| `neighbor-system` | 看板数据对接 | — | table | 从看板系统拉取真实业务数据 |

---

#### 本地文件导入 `file-import`

**用途**：上传本地的 CSV / Excel / JSON 文件，解析成表格供后续分析。

**什么时候用**：手头已有数据文件时，这是最常用的入口。

**关键参数**：

- **文件**：选择本地文件上传。支持 CSV、Excel（.xlsx）、JSON。
- 解析在**后台任务**中执行，不阻塞界面；大文件导入期间你仍可操作画布。
- 支持查看导入进度，可中途取消。

**输出**：`table`（含字段 schema、行数摘要、轻量预览）。

**小提示**：
- 导入完成后，悬浮节点点「预览」，确认字段是否被正确识别（尤其是日期、数值类型）。
- 如果字段类型识别错了，可以在后面接「字段选择」或用算法节点里指定字段。

---

#### 手动输入数据 `manual-json-import`

**用途**：直接输入一段 JSON 文本作为数据源。

**什么时候用**：

- 调试某个分析节点时，想用最小的、可控的数据样例
- 临时拼一组测试数据验证流程
- 系统内置模板默认用它提供样例数据，保证模板开箱即跑

**关键参数**：

- **JSON 文本**：粘贴合法的 JSON。

**输出**：

- 输入是**对象数组**（如 `[{"a":1,"b":2}, {"a":3,"b":4}]`）→ 输出 `table`
- 输入是其他合法 JSON → 输出 `json`

---

#### 看板数据对接 `neighbor-system`

**用途**：从外部看板系统拉取真实生产/质量数据。

**什么时候用**：做真实业务分析时，数据来自看板系统而非本地文件。

**关键参数**：

- 先选择**产品、场景和因子全集**
- 运行时按**启动方式**（时间 / 方案 / SN / 任务令）与工序范围拉取数据

> 这个节点配置较复杂，**4 种启动方式**的详细说明见 [附录 A-看板数据对接](#附录-a看板数据对接)。

**输出**：`table`。

**注意**：
- 系统内置了**默认 mock 桥接**，覆盖涂布、辊压、分切、卷绕、装配、注液、化成、分容、PACK 等工序和 40 个因子，方便本地演示和测试，不需要真实看板也能跑。
- 若系统以 iframe 嵌入宿主页面，宿主需先传入 token 才能访问真实数据。

---

#### 下一步

数据导入后，通常先连到 [3-2 清洗与筛选](#3-2-清洗与筛选) 处理脏数据，再进入分析。

---

### 3-2 清洗与筛选

清洗与筛选节点（`action` 类）位于导入之后、分析之前，负责把脏数据处理成可分析的干净数据。
**分析结果是否可信，很大程度取决于这一步做没做好。**

| 节点 | 显示名 | 输入 | 输出 | 适用场景 |
|------|--------|------|------|----------|
| `data-dedup` | 去重 | table | table | 去掉重复行 |
| `data-missing-outlier` | 缺失/异常值处理 | table | table | 处理空值和离群点 |
| `data-encoding-scaling` | 编码/缩放 | table | table | 分类变量编码、数值标准化 |
| `data-filter` | 数据筛选 | table | table | 按条件过滤行 |

> 多因子分析建议至少做一遍「缺失/异常值处理」——离群点会严重扭曲相关性结论。

---

#### 去重 `data-dedup`

**用途**：去掉表格里的重复行。

**什么时候用**：怀疑数据有重复采集（如同一个 SN 被记录多次）。

**关键参数**：

- **去重依据**：按整行去重，或按指定字段组合去重（只看这几个字段是否相同）。
- **保留哪条**：保留首条或末条（基于当前表格顺序）。

**输出**：`table`。

---

#### 缺失/异常值处理 `data-missing-outlier`

**用途**：识别并处理空值（缺失）和离群点（异常值）。

**什么时候用**：**几乎每次分析前都建议用**。真实数据普遍有空值和录入异常，不处理会污染相关性、回归等结果。

**关键参数**：

- **目标字段**：留空 = 自动处理所有可识别字段；也可手动指定。
- **空值识别**：自动识别真实 `undefined`、`null`、空字符串，以及字符串 `"undefined"` / `"null"` 等常见空值占位。
- **异常值模式**（三选一）：
  | 模式 | 怎么用 |
  |------|--------|
  | **IQR 四分位距** | 用系数 k 控制剔除强度（k 越大越宽松） |
  | **百分比剔除** | 按百分位截断两端（如剔除前后各 1%） |
  | **手动区间** | 为指定字段配置上下限（`> 下限 且 < 上限`），多组规则按 AND 生效 |

**输出**：`table`。

**建议**：不知道选哪种异常值模式时，先用 **IQR**，它对大多数正态分布数据都合理。

---

#### 编码/缩放 `data-encoding-scaling`

**用途**：把分类变量转成数值（编码），把数值字段缩放到统一量纲（缩放）。

**什么时候用**：

- 算法要求输入是数值，但你的数据里有分类/文本字段（如"合格/不合格"、"工序A/工序B"）
- 不同字段的量纲差异巨大（如温度 vs 厚度），影响某些对量纲敏感的算法

**关键参数**：

- **缩放方式**：
  - **Z-Score 标准化**（默认）— 转成均值 0、标准差 1
  - **Min-Max 归一化** — 压缩到 [0, 1] 区间

**输出**：`table`。

---

#### 数据筛选 `data-filter`

**用途**：按一个或多个条件，过滤出满足要求的行。

**什么时候用**：

- 只分析某个工序、某个时间段、某个产品型号的数据
- 排除明显无效的记录

**关键参数**：

- **规则组合**：多条规则之间用「全部满足 (AND)」或「任一满足 (OR)」组合。
- **比较操作**：支持字符串、数值、空值等多种比较（等于、大于、包含、为空等）。

**输出**：`table`。

---

清洗完后，通常接 [3-3 字段与结构处理](#3-3-字段与结构处理) 选出要分析的字段，再进入分析节点。

### 3-3 字段与结构处理

这一类节点（`action` 类）在不改变行内容的前提下，**调整表格的结构**：选哪些字段、按什么顺序、留多少行、把多张表合成一张。

| 节点 | 显示名 | 输入 | 输出 | 适用场景 |
|------|--------|------|------|----------|
| `field-selection` | 字段选择 | table | table | 保留/排除指定字段 |
| `sort` | 排序 | table | table | 按多个优先级排序 |
| `data-limit` | 数据量限制 | table | table | 只保留前 N 或后 N 行 |
| `data-merge` | 数据合并 | 多个 table | table / tableCollection | 把多路数据合并 |
| `js-transform` | JS 代码执行 | table | table | 用自定义 JS 灵活转换 |

---

#### 字段选择 `field-selection`

**用途**：保留或排除指定的字段（列）。

**什么时候用**：

- 算法节点要求指定目标字段和候选因子前，先把无关字段清掉
- 数据列太多，只想看关注的那几列

**关键参数**：

- **模式**：包含（只留选中的）/ 不包含（排除选中的）。
- **字段选择器**：可搜索下拉多选；支持**正则搜索**（`allowRegexSearch`），适合字段名有规律的批量选择。

**输出**：`table`。

---

#### 排序 `sort`

**用途**：按字段对行排序。

**什么时候用**：想让数据按某个指标从大到小/从小到大排列，或为后续的「数据量限制」做铺垫（比如先按时间倒序，再取前 100 条）。

**关键参数**：

- **多优先级规则**：可设多级排序，越靠前优先级越高。
- **方向**：每个规则支持升序 / 倒序。

**输出**：`table`。

---

#### 数据量限制 `data-limit`

**用途**：截断表格，只保留前 N 条或后 N 条。

**什么时候用**：

- 数据量太大，算法跑得慢，先抽样验证流程
- 配合「排序」使用：先排序，再取 Top N

**关键参数**：

- **保留位置**：最前面 N 条 / 最后面 N 条。
- **数量 N**。

**输出**：`table`。

---

#### 数据合并 `data-merge`（多输入节点）

**用途**：把**多个上游节点**的数据合并成一张表。这是核心的**多输入节点**（有多个输入槽位，最少接 2 个来源）。

**什么时候用**：

- 数据散落在两张表里，需要拼到一起（如一张是工艺参数，一张是检测结果，按 SN 关联）
- 多个数据源的纵向堆叠

**关键参数（三种合并模式）**：

| 模式 | 作用 | 关键参数 |
|------|------|----------|
| **纵向追加 `append`** | 把多张表上下拼起来（行数相加） | — |
| **横向关联 `join`** | 按指定 key 把多张表左右拼起来 | `unifiedKeyName` 统一主键名；`keyMappings` 为每个来源指定各自的 mergeKey |
| **分组集合 `collection`** | 把多个来源按分组组织成集合 | — |

**横向关联要点**：

- `unifiedKeyName` 定义合并后的统一主键列名（如 `sn`）
- 执行时会**移除各来源的原始 key 字段**，只保留统一主键
- 无论数据有没有 key 匹配上，合并后的字段都是各来源字段的**并集**

**输出**：`table` 或 `tableCollection`。

---

#### JS 代码执行 `js-transform`

**用途**：用一段自定义 JavaScript 代码灵活转换表格数据，弥补内置节点的不足。

**什么时候用**：

- 需要做内置节点不支持的转换（如条件计算、字段拼接、自定义公式）
- 快速验证一个数据变换逻辑

**关键约束**：

- 代码里只暴露一个 `rows` 变量（数组对象列表，即表格数据）
- 代码**必须 `return` 一个数组对象列表**，否则报错
- 固定输出 `table`

**示例**（给每行加一个新字段 `良率等级`）：

```js
return rows.map(r => ({
  ...r,
  良率等级: r.良率 >= 0.95 ? '优' : r.良率 >= 0.9 ? '良' : '差'
}))
```

> **注意**：JS 节点同步执行，避免在里面写大循环或复杂计算，以免阻塞界面。

### 3-4 合并与聚合

> 说明：官方节点库的「合并与聚合」组(`merge-aggregate`)包含 `data-merge` 和 `data-aggregation` 两个节点。
> 其中 `data-merge` 是多输入合并节点，已放在 [3-3 字段与结构处理](#3-3-字段与结构处理)（和其它结构处理节点一起讲更顺）。
> 本篇聚焦**数据聚合** `data-aggregation`。

---

#### 数据聚合 `data-aggregation`

**用途**：对表格做汇总计算——按字段分组算统计量、做移动窗口、按时间分桶等。

**什么时候用**：

- 把明细数据按工序/批次/型号汇总成可对比的统计指标
- 算每个 SN 的平均良率、每个班次的缺陷总数
- 做时间窗口的趋势聚合

**关键参数（四种聚合模式）**：

| 模式 | 作用 | 典型用途 |
|------|------|----------|
| **行内多列合并 `row_combine`** | 把一行里的多列合并成一个新字段 | 多个分项指标合成一个综合字段 |
| **分组统计 `group_by`** | 按指定字段分组，对其它字段算统计量 | 按工序算平均厚度、按型号算良率 |
| **移动窗口 `rolling`** | 按行序做滑动窗口聚合 | 平滑波动、算移动平均 |
| **时间窗口 `time_window`** | 按时间字段分桶聚合 | 按小时/天算趋势 |

**分组统计支持的聚合方法**：

- 平均值 `mean`、求和 `sum`、数量 `count`、最大值 `max`、最小值 `min`、标准差 `std` 等

**配置要点（分组统计模式）**：

- **分组字段 `groupByField`**：按哪个字段分组（如"工序"）
- **聚合组 `aggregationGroups`**：为每个目标字段指定聚合方法和新字段名
- **输入列 `inputColumns`**：选择参与聚合的字段

**输出**：`table`（每行是一个分组的统计结果）。

---

#### 多输入合并去哪了？

如果你要**把多个上游节点的数据合并到一起**（纵向追加 / 横向关联 / 分组集合），用 `data-merge` 节点，详见 [3-3 · 数据合并](#数据合并-data-merge多输入节点)。

### 3-5 分析与导出

分析节点（`terminal` 类）是工作流的**终点**，不可再向外连线。它们消费前面清洗好的数据，产出**分析报告**（含图表与解读）。

分析节点分两类：

- **统计分析**（`stat-analysis`）：相关性、方差、共线性、主成分、因子筛查——多在前端本地执行，秒级出结果
- **模型分析**（`model-analysis`）：XGBoost、Lasso、随机森林、回归——调用后端 Python，耗时稍长

> 报告里的图怎么看，见 [04-结果与报告解读](#结果与报告解读)。

---

#### 统计分析类

| 节点 | 显示名 | 执行位置 | 输出 |
|------|--------|----------|------|
| `correlation-analysis` | 单调性分析 | 前端本地 | report |
| `vif` | VIF 共线性检测 | 前端本地 | report |
| `pca` | PCA 主成分分析 | 前端本地 | report |
| `anova` | 方差分析 | 前端本地 | report |
| `classification-factor-screening` | 分类因子筛查 | 前端本地 | report |

##### 单调性分析 `correlation-analysis`

**用途**：分析因子(X)与目标(Y)之间的单调性关系强度。系统目前的核心相关性分析节点。

**适用场景**：第一次排查"哪些因子最相关"时的首选。

**关键参数**：

- **方法 `method`**：默认 Pearson（线性相关）；可切 Spearman（单调但不一定线性，如等级/排序）、Kendall（秩相关）
  - **不知道选哪个 → 先用 Pearson**
  - 因子和目标是**等级、排序类**数据 → 用 Spearman 或 Kendall
- **X 字段 `xFields`**：候选因子（你怀疑有影响的变量）
- **Y 字段 `yFields`**：目标（你想解释/预测的指标）
- **热力图显示因子数 `heatmapTopN`** / **排行图显示因子数 `rankingTopN`**：控制图表展示的因子数量

**输出**：热力图、Top N 相关性排行、显著性提示、相关明细。

**注意**：运行前会校验字段是否存在、是否为数值类型；样本不足时报错。

---

##### VIF 共线性检测 `vif`

**用途**：诊断多个因子之间是否存在严重的多重共线性。

**适用场景**：把因子丢进回归/模型前，检查因子之间是不是高度相关（高度相关的因子会让模型不稳定、系数不可解释）。

**怎么读结果**：

- VIF 值越大，该因子与其它因子的共线性越严重
- 经验阈值：VIF > 10 通常提示严重共线性，考虑剔除

**输出**：检测摘要、VIF 排序、风险提示、字段明细。

---

##### PCA 主成分分析 `pca`

**用途**：把多个相关变量压缩成少数几个主成分，用更少的维度概括大部分信息。

**适用场景**：

- 因子太多，想降维后再分析或可视化
- 想看哪些因子倾向于"一起变化"

**怎么读结果**：

- **解释方差占比**：前几个主成分能解释多少原始信息（累计越高越好）
- **载荷 (loadings)**：每个原始变量对主成分的贡献，载荷大的变量是该主成分的主要驱动

**输出**：分析摘要、解释方差占比、字段载荷热力图、载荷明细。

---

##### 方差分析 `anova`

**用途**：单因素方差分析——判断一个分类变量（如工序、班次）对一个数值指标的影响是否显著。

**适用场景**：想知道"不同分组（如不同工序）下的指标差异，是真的有差别还是只是随机波动"。

**关键参数**：

- **目标字段 `targetField`**：要比较的数值指标
- **分组字段 `groupField`**：分类变量（按它分组）

**怎么读结果**：

- **F 值 / P 值**：P 值越小（通常 < 0.05），说明组间差异越显著
- **分组均值对比 / 分组箱线图**：直观看出哪组高哪组低

**输出**：F/P 值、分组均值、分组箱线图、分组明细。样本组太小或不均衡会给出风险提示。

---

##### 分类因子筛查 `classification-factor-screening`

**用途**：针对**分类标签**（如合格/不合格、缺陷类型）的因子筛查——找出哪些因子对区分类别最有用。

**适用场景**：目标是一个分类（而非连续数值）时，用这个节点找关键因子。

**关键参数**：

- **目标字段 `targetField`**：分类标签
- **因子 `factorNames`**：待筛查的候选因子
- **显著性水平 `alpha`**：默认 0.05
- **最大结果数 `maxResultCount`**：返回前 N 个最显著的因子

**特点**：自动区分数值因子（做差异检验）和类别因子（做关联检验）。

**输出**：显著性排行、检验明细、风险提示。

---

#### 模型分析类

> 模型分析节点**调用后端 Python 服务**执行，首次运行可能稍慢（需启动分析）。如果运行报"未找到分析模型"之类错误，见 [06-常见问题](#常见问题)。

| 节点 | 显示名 | 任务类型 | 输出 |
|------|--------|----------|------|
| `xgboost-shap` | XGBoost + SHAP | 回归 | report |
| `random-forest-feature-importance` | 随机森林特征重要性 | 回归 | report |
| `lasso` | Lasso 回归 | 回归 | report |
| `multiple-linear-regression` | 多元线性回归 | 回归 | report |
| `logistic-regression-classification` | 逻辑回归分类分析 | 分类 | report |

##### XGBoost + SHAP `xgboost-shap`

**用途**：用 XGBoost 拟合目标，再用 SHAP 解释每个因子对预测的贡献。这是**"解释结果为什么这么变"**的最强工具。

**适用场景**：已有明确目标指标，想搞清楚到底是哪些因子、在什么方向上推动了结果。

**关键参数**：

- **SHAP 趋势图数量 `maxDependencePlots`**：默认前 8 个因子画依赖图
- **建模前异常值处理**：不处理 / IQR 剔除 / 孤立森林
- **高级参数**（通常用默认即可）：树数量、学习率、树深、测试集比例、随机种子、SHAP 采样上限、自动调参策略

**怎么读结果**：

- **SHAP 蜂 swarm 图**：每个点代表一个样本，颜色代表该因子的取值高低，横轴位置代表对预测的正/负贡献
- **SHAP 柱状图（玫红色）**：因子的平均重要性排序
- **依赖图**：单个因子取值变化时，对预测的影响曲线

详见 [04-结果与报告解读 · SHAP](#结果与报告解读)。

---

##### 随机森林特征重要性 `random-forest-feature-importance`

**用途**：训练随机森林，输出各因子的**重要性排序**。

**适用场景**：候选因子很多，想先压缩范围，找出最值得关注的几个。

**输出**：特征重要性排行、累计重要性、预测值对比、结果解读提示。

---

##### Lasso 回归 `lasso`

**用途**：Lasso 回归自带特征选择——通过 L1 正则把不重要因子的系数压到 0，留下稀疏的关键因子集。

**适用场景**：因子多且有共线性，想自动筛选出真正重要的少数因子。

**怎么读结果**：

- **非零系数**：保留下来的关键因子，绝对值越大越重要，正负号代表方向
- **系数路径图**：正则强度变化时各因子系数如何收缩到 0；越晚收缩到 0 的因子越稳定
- **拟合质量**：R²、MAE、入选特征数

**注意**：Lasso 会在相关因子里选代表项，**未入选不代表业务上无影响**。

---

##### 多元线性回归 `multiple-linear-regression`

**用途**：用多个因子做线性回归，看每个因子的系数（在控制其它因子后的净影响）。

**适用场景**：因子和目标大致是线性关系，想要一个可解释的线性模型。

**输出**：模型摘要、回归系数排序、预测值对比、残差分布。

---

##### 逻辑回归分类分析 `logistic-regression-classification`

**用途**：目标是**分类**（二分类或多分类）时，用逻辑回归建模并评估分类效果。

**适用场景**：预测"合格/不合格"、"是/否缺陷"这类分类目标。

**输出**：模型摘要、分类指标、混淆矩阵、ROC 曲线（二分类）、系数解释。

---

#### 结果导出

新版本中，**导出能力内置在「结果预览」里**，不再需要单独的导出节点：

- **表格数据导出**：在任意 `table` 结果预览中，直接点导出按钮，支持 **CSV / Excel / JSON**
- **分析报告导出**：在 `report` 结果预览（ReportViewer）中，可导出**离线 HTML 报告**，含全部图表与解读
- **图表**：结果预览自带的 `table-chart-combo-viewer` 提供表格+图表组合展示

> 老工作流里可能还有独立的 `data-export` 节点，它的功能已被结果预览的导出能力取代。

## 结果与报告解读

分析节点跑完后，预览结果会以**结构化报告**形式呈现。一份报告通常由若干段落组成，本文档告诉你**每类图表/指标该怎么看**。

---

### 报告的通用结构

无论哪个分析节点，产出的报告大都由以下几种段落拼成：

| 段落类型 | 内容 |
|----------|------|
| **摘要 (Summary)** | 本次分析的关键结论、样本量、字段情况 |
| **图表 (Chart)** | 热力图、柱状图、箱线图等可视化 |
| **依赖/关系 (Dependence)** | SHAP 依赖图、回归拟合图等关系曲线 |
| **图片 (Image)** | 后端生成的完整大图（如 SHAP 整合图） |
| **风险提示 (RiskList)** | 对本次结果可信度的分级提醒 |
| **文本说明 (Text)** | 方法定义、读图指引等辅助文字 |

---

### 风险提示怎么看

报告里的「风险提示」段落用**三级颜色**标注本次结果的可信度：

| 颜色 | 等级 | 含义 | 建议 |
|------|------|------|------|
| 🔴 红色 | **高风险** | 结果可能不可信（如样本严重不足、强共线性） | 不要直接采信，需先补数据或换方法 |
| 🟡 黄色 | **需关注** | 结果有瑕疵但可参考（如样本组不均衡、缺失率高） | 结合业务判断，谨慎使用 |
| ⚪ 默认 | **信息** | 提示性的说明（如方法局限性） | 了解即可 |

> **建议**：先看风险提示再下结论。高风险提示意味着这个分析结果需要更多验证。

---

### 相关性分析报告

来源节点：`correlation-analysis`（单调性分析）

#### 相关性排序（Top N 排行）

- 按 |相关系数| 从大到小排列，**排在前面的因子与目标关系最强**。
- 相关系数范围 [-1, 1]：接近 1 强正相关，接近 -1 强负相关，接近 0 弱相关。

#### 显著性提示

- 光看相关系数大小不够，还要看**是否显著**（样本量足够、非偶然）。
- 报告会标注哪些关系是 statistically significant，哪些样本量不足。

#### 热力图

- 横纵轴都是字段，每个格子的颜色深浅代表这两个字段的相关性强弱。
- **看对角线附近的深色块**：说明这几个字段高度相关（可能存在共线性，可参考 VIF 节点进一步确认）。
- **看目标字段所在的行/列**：颜色最深的格子对应的因子，就是最相关的候选。

---

### SHAP 报告（XGBoost + SHAP）

来源节点：`xgboost-shap`。这是解释"哪些变量推动结果"的核心报告。

#### SHAP 蜂群图（swarm / beeswarm）

- 纵轴是各个因子（按重要性排序），横轴是 SHAP 值（对预测的贡献）。
- **每个点 = 一个样本**，点的颜色代表该因子的取值高低（红=高，蓝=低）。
- 读法：
  - 一行点**整体偏右** → 这个因子倾向于**提高**预测值 Y
  - 一行点**整体偏左** → 倾向于**降低** Y
  - 点**分布越宽** → 这个因子的影响越大

#### SHAP 柱状图（玫红色条）

- 每个因子的**平均绝对 SHAP 值**，代表整体重要性大小。
- **条越长，因子越重要**。这是重要性排序最直观的图。

#### 依赖图（Dependence Plot）

- 每个重要因子一张图，展示该因子取值变化时，对预测 Y 的影响曲线。
- 读法：曲线**上升**段说明该因子增大时 Y 增大，**下降**段说明 Y 减小。
- 数量由 `maxDependencePlots` 参数控制（默认前 8 个）。

> 注：SHAP 报告支持两种展示模式——前端分图表展示 / 后端完整大图展示，均支持导出（PDF 或图片）。

---

### 特征重要性报告（随机森林）

来源节点：`random-forest-feature-importance`

- **重要性排行**：因子按重要性从大到小排列。
- **累计重要性**：从最重要因子开始累加，看前几个因子能覆盖多少总重要性——通常前 20% 的因子覆盖 80% 的重要性（类似二八法则）。
- 用途：因子很多时，用它快速锁定最值得关注的几个。

---

### Lasso 报告

来源节点：`lasso`

- **非零系数**：Lasso 把不重要因子的系数压到 0，剩下的就是关键因子。绝对值越大越重要，正负号是方向。
- **系数路径图**：横轴是正则强度，曲线显示各因子系数如何随正则增强而收缩到 0。**越晚收缩到 0 的因子越稳定**；曲线剧烈交叉说明因子间可能存在替代关系。
- **拟合质量**：看 R²（越高拟合越好）、MAE（平均误差，越低越好）、入选特征数。
- ⚠️ Lasso 会在相关因子里**选代表项**，未被选中的因子**不代表业务上无影响**，只是被代表项替代了。

---

### 方差分析报告（ANOVA）

来源节点：`anova`

- **F 值 / P 值**：P 值 < 0.05 通常说明组间差异显著（不是随机波动）。
- **分组均值对比**：直接看出哪个分组高、哪个低。
- **分组箱线图**：展示每个分组的分布（中位数、四分位、离群点），比均值更能看出差异的实质。

---

### VIF 共线性报告

来源节点：`vif`

- 每个因子一个 VIF 值，**越大共线性越严重**。
- 经验：VIF > 10 提示严重共线性，建模型前应考虑剔除或合并该因子。

---

### PCA 报告

来源节点：`pca`

- **解释方差占比**：前 N 个主成分累计能解释原始数据多少比例的信息。一般希望前 2-3 个主成分能解释 70%+。
- **载荷热力图 / 载荷明细**：每个原始变量对主成分的贡献。载荷大的变量是该主成分的主要驱动——可以据此给主成分"起名字"。

---

### 逻辑回归分类报告

来源节点：`logistic-regression-classification`

- **分类指标**：准确率、精确率、召回率、F1 等。
- **混淆矩阵**：直观看出哪些类别容易被分错。
- **ROC 曲线**（二分类）：曲线越靠左上角，分类效果越好；AUC 越接近 1 越好。

---

### 结果导出

在报告预览中，可以把结果带走：

- **报告导出**：导出为离线 HTML（含全部图表与解读，可独立打开分享）
- **表格导出**：CSV / Excel / JSON
- **图表导出**：单独保存图片

详见 [3-5 · 结果导出](#结果导出)。

## AI 分析（分析笔记本）

AI 分析是一个**独立于工作流画布**的数据分析工作站。你给它**数据和目标**，AI 用 Python 自由分析，产出图文并茂的长报告。

> **和工作流编辑器的区别**：
> - 工作流（画布）管"**流程**"——节点可见、可调、可复用，适合你想自己掌控分析步骤。
> - AI 分析（笔记本）管"**洞察**"——过程透明可观察，结论是最终产物，适合你想快速得到分析结论。

---

### 1. 什么时候用 AI 分析

| 场景 | 推荐 |
|------|------|
| 想快速看一份数据的洞察，不想自己搭流程 | ✅ AI 分析 |
| 数据已经在画布某节点产出，想深挖一下 | ✅ AI 分析（可导入画布节点输出） |
| 需要可复用、可调参的标准分析流程 | 工作流编辑器 |
| 团队要复用同一套分析方法 | 工作流编辑器（保存成模板） |

**一句话**：要"结论"用 AI 分析，要"流程"用画布。

---

### 2. 启动 AI 分析

#### 入口

在主工作流界面顶部，点击 **「AI 分析」** 按钮（Notebook 启动器）。

#### 三种进入方式

弹窗会根据当前状态提供选项：

| 选项 | 含义 |
|------|------|
| **继续上次分析** | 上次的笔记本会话还在运行，点这里**秒级恢复**（不需要重启运行时） |
| **选择一个画布节点** | 把该节点的输出数据作为笔记本的输入，进入分析 |
| **空白笔记本** | 不导入数据，直接进入一个空白笔记本自己折腾 |

#### 数据来源

- **画布节点**：列表展示当前画布上可用的节点输出（含行数、列数、字段预览）。选一个，该数据会一次性灌入笔记本作为分析起点。
- **空白笔记本**：不预装数据，你可以在对话里让 AI 自己生成或你上传。

> 笔记本与画布**严格分离**：笔记本只能读取画布某节点输出作为一次性输入，**不能反向修改画布**。

---

### 3. 笔记本界面

进入笔记本后，你会看到：

- **左侧：对话区** — 你和 AI 的对话，AI 会展示它每一步在做什么（跑→看→改假设→再跑）
- **右侧：文件树 / 报告区** — AI 产出的报告和中间文件
- **顶部**：会话标题、模型切换、下载等操作

笔记本是**全屏沉浸式**界面，想回到画布需要关闭笔记本。

---

### 4. 和 AI 协作分析

#### 怎么提问

像跟一位数据科学家对话一样，给出**目标**和**关注点**。例如：

- "这份数据里，哪些工艺因子和良率最相关？帮我做个相关性分析并出图。"
- "目标字段是厚度，帮我用 SHAP 解释哪些因子在推动厚度波动。"
- "对比 A 班和 B 班的关键指标差异，判断是否显著。"

#### AI 的分析过程

AI 会在浏览器内的 Python 沙箱里**自由分析**：

- 它会自己决定跑哪些分析、画哪些图
- 每一步的过程在对话里**透明可见**，你能看到它在干什么
- 它可能反复迭代（跑→看结果→调整假设→再跑），最终收敛到结论

#### 最终产物

一个笔记本会话的最终产物 = **`reports/main.md` 报告** + **`artifacts/` 下的图表与中间数据**。

报告是图文并茂的 Markdown，包含分析结论、图表、解读。

---

### 5. 查看与导出报告

报告产出后，你可以：

| 操作 | 说明 |
|------|------|
| **查看报告** | 在笔记本右侧直接阅读 `reports/main.md` |
| **下载整个 workspace** | 打包成 **zip** 下载，含报告 + 所有图表 + 中间数据 |
| **复制 Markdown** | 把报告 Markdown 复制到剪贴板，粘贴到别处 |

> 笔记本里**不能编辑报告**——这是为了保证报告"可重跑、可追溯"的可信度。要调整结论，就让 AI 重新分析。

---

### 6. 会话管理

#### 历史会话

笔记本支持**历史会话列表**。打开笔记本（不带具体 session 参数）时，会进入会话列表页，可以看到：

- 所有历史会话（标题、最后更新时间、最近一条消息预览、状态）
- 点击进入某个历史会话继续
- 新建空白会话

#### 会话持久化

每个会话的数据按 sessionId **隔离持久化**在浏览器内（OPFS），关闭页面后再回来，会话和报告都还在。

---

### 7. 切换 AI 模型

笔记本支持在对话过程中**热切换后台模型**。

- 顶部 / 设置里有模型切换入口
- 可用模型列表由后台配置决定（如 GLM、DeepSeek 等）
- 切换后立即生效，后续对话用新模型

> 你也可以在模型配置里管理可用的模型档案（新增 / 编辑 / 删除），具体取决于后台开放了哪些模型。

---

### 8. 注意事项

- **运行环境**：AI 在浏览器内的 Python 沙箱（WebAssembly）里跑，不依赖服务器算力，但首次加载运行时需要一点时间。
- **单次执行**：单个分析步骤有时间上限（避免卡死）；会话存储有容量上限（单会话约 500MB）。
- **可信度**：AI 分析是"黑盒"性质——结论需要结合业务判断复核，尤其是涉及因果推断时。报告里的风险提示要认真看（见 [04-结果与报告解读 · 风险提示](#风险提示怎么看)）。

## 常见问题

---

### 节点之间连不上

**原因**：系统有严格的连线规则（见 [02-工作流编辑器 · 连线规则](#3-连线规则)）。

**检查清单**：

1. 是否从 **Terminal（终点）** 节点往外连？终点不能再连线。
2. 是否往 **Trigger（触发器）** 节点连？触发器只能作为起点，不能作为终点。
3. 目标节点的**输入槽位**是否已满？（多输入节点除外，普通节点只接受一个输入）

**简单记法**：数据只能 Trigger → Action → Terminal 单向流动。

---

### 运行报错「未找到分析模型」

**原因**：模型分析类节点（`xgboost-shap`、`lasso`、`multiple-linear-regression`、`random-forest-feature-importance`、`logistic-regression-classification`）需要调用**后端 Python 服务**。

**排查**：

1. 后端 Python 分析服务是否已启动？
2. 目标字段（Y）和候选因子（X）是否都已正确配置？
3. 字段是否都是数值类型？（分类目标用 `logistic-regression-classification` 或 `classification-factor-screening`）

---

### 运行报错「样本不足」

**原因**：分析节点运行前会校验样本量，样本太少无法得出可信结论。

**解决**：

- 增加数据量（扩大看板取数范围 / 导入更完整的文件）
- 减少要求的字段数量
- 检查「数据筛选」「数据量限制」是否把数据切得太少

---

### 字段类型识别错误

**表现**：本该是数值的字段被当成文本，或日期字段没被识别。

**原因**：数据里有**混合类型**或**空值占位字符串**（如 `"undefined"`、`"null"`、空格）。

**解决**：

1. 在导入节点后接一个「缺失/异常值处理」`data-missing-outlier` 节点，它会自动清理常见空值占位。
2. 用「字段选择」确认实际可用的字段。
3. 必要时用「JS 代码执行」`js-transform` 节点手动转换类型。

---

### Pearson / Spearman / Kendall 怎么选

| 场景 | 选哪个 |
|------|--------|
| 因子和目标大致**线性**相关（一个变大，另一个成正比变大/变小） | **Pearson**（默认） |
| 因子和目标是**单调但不一定线性**（如等级、排序、名次） | **Spearman** |
| 只关心**相对顺序**，样本有较多重复值，想更稳健 | **Kendall** |

**不知道选哪个 → 先用 Pearson**，看结果再决定要不要换。

---

### SHAP 图显示异常 / 只有单因子曲线

**可能原因**：

- 候选因子太少（SHAP 需要多个因子才有对比意义）
- `maxDependencePlots` 参数设得太小
- 数据异常值过多，干扰了模型

**解决**：

- 确认配置了足够的候选因子
- 调大 `maxDependencePlots`（默认前 8）
- 开启「建模前异常值处理」（IQR 或孤立森林）

---

### 大数据量导致界面卡顿

**原因**：导入或预览超大表格时，渲染开销大。

**解决**：

- 用「数据量限制」`data-limit` 节点先抽样，验证流程跑通后再用全量
- 导入节点本身已是后台解析、不阻塞主界面；卡顿多发生在**结果预览渲染**大表时
- 结果预览对大表做了**虚拟滚动**优化，但仍建议先抽样调试

---

### 工作流改了但没保存会丢吗

**不会立刻丢**，但存在风险。系统在以下场景会提示你保存：

- 切换到另一个工作流
- 新建工作流
- 关闭页面

顶部「保存」按钮在有未保存改动时会变成**「保存更改」**。**建议养成随手保存的习惯**。

运行历史会记录最近 20 次运行，可以从历史快照恢复某次运行的配置和数据。

---

### 单节点调试为什么能秒出结果

单节点运行时，系统**复用上游节点已缓存的结果**，只重跑当前节点，所以很快。

如果你想让上游也重新执行，用节点工具栏的 **「重跑（含上游）」** 而不是普通「运行」。

被 📌 **冻结**的节点在整条运行时会被跳过，保留其当前输出——调试复杂流程时用它省时间。

---

### 想合并两张表的数据

用「数据合并」`data-merge` 节点（多输入节点，见 [3-3 · 数据合并](#数据合并-data-merge多输入节点)）：

| 需求 | 模式 |
|------|------|
| 两张表上下拼起来（行数相加） | 纵向追加 `append` |
| 两张表按某个 key（如 SN）左右拼起来 | 横向关联 `join` |
| 多来源按分组组织成集合 | 分组集合 `collection` |

横向关联时，指定 `unifiedKeyName`（统一主键名）和每个来源各自的 mergeKey 即可。

---

### 数据散落在画布多个节点，怎么一起分析

两种方式：

1. 用「数据合并」`data-merge` 把它们合成一张表，再连到分析节点。
2. 用 [AI 分析](#ai-分析分析笔记本)：选择其中一个画布节点的输出作为输入，让 AI 自由分析；或开空白笔记本自己折腾。

---

### 还有问题

- 应用内「帮助中心」（顶部「帮助」按钮）有每个节点的即时说明
- 各节点配置弹窗里的参数有 tooltip 说明
- 报告段落旁通常有「读图指引」按钮

## 附录 A：看板数据对接

> 本附录简要说明「看板数据对接」`neighbor-system` 节点的使用。它是 trigger 类节点，用于从外部看板系统拉取真实业务数据。

---

### 节点定位

`neighbor-system`（看板数据对接）用于把外部看板系统的生产/质量数据引入工作流，替代本地文件导入。

---

### 配置流程

配置分两个阶段：

#### 阶段一：选择数据范围（配置时）

1. **选择产品** — 指定要分析的产品
2. **选择场景** — 指定该产品下的场景
3. **选择因子全集** — 从该产品场景的所有因子中，勾选要纳入分析的因子集合

> 因子信息包含每个因子的名称、key 和对应工序。

#### 阶段二：选择启动方式（运行时）

运行节点时，需要告诉系统**按什么方式圈定要拉取的数据**。有 **4 种启动方式**：

| 启动方式 | 怎么用 | 适合 |
|----------|--------|------|
| **按时间** | 指定时间段 + 物料类型 + 工序范围 | 按生产时段分析 |
| **按阶段方案** | 指定阶段方案列表 + 任务令类型 | 按既定方案/批次分析 |
| **按任务令** | 直接给任务令列表 | 已知具体任务令 |
| **按 SN** | 直接给 SN（序列号）列表 | 已知具体产品 SN |

> **本质**：无论用哪种启动方式，最终都是为了圈定一组 **SN List**，再按选定的因子集合去拉取这些 SN 的因子数据。

---

### SN 列表的输入方式

当用「按 SN」启动时，SN 列表支持两种输入：

- **手动输入** — 直接填写
- **文件导入回填** — 从 CSV / Excel 导入，选择对应列回填
  - 导入时**自动跳过空值**
  - **默认去重**

默认因子数：约 40 个
