# 工作流 AI 弱模型提示词设计

## 背景

当前工作流 AI 编排已经具备流式观测、失败诊断与自动修复重试能力，但在使用较弱模型时，仍容易因为提示词上下文过大、任务目标过重而出现以下问题：

- 输出不是合法 JSON
- 一次性规划过多节点和增强步骤，导致计划结构漂移
- 节点配置补全不完整，最终校验失败
- 用户在“生成中”阶段虽然能看到流式文本，但结果本身成功率偏低

本设计目标不是提升“复杂工作流一次生成上限”，而是优先提升弱模型下的首轮成功率、重试修复成功率和可解释性。

## 设计目标

- 优先生成最小可运行工作流，而不是最复杂工作流
- 降低单次提示词负荷，减少无关节点和冗余描述对模型的干扰
- 把“结构规划”和“参数补全”拆开，降低每一步的推理难度
- 保留现有流式观测、诊断、自动修复重试能力

## 方案

### 1. 精简模型可见节点目录

不再直接把完整节点定义暴露给模型，而是裁剪为提示词专用目录，只保留弱模型真正需要的字段：

- `name`
- `displayName`
- `category`
- `description`
- `inputMode`
- `minInputs`
- `maxInputs`
- `allowedNextCategories`
- `requiredConfig`
- `runtimeConfig`
- `keywords`

不再向模型透传大段 `help`、完整属性说明和过多 `assistantHints`，避免提示词冗长、注意力分散。

### 2. 两阶段编排

第一阶段：骨架规划

- 只允许输出 `createNode` 和 `connectNodes`
- 目标是选出最小节点集合、建立正确主链路、识别缺失信息
- 若信息不足，允许返回空操作，但必须附带 `questions` 或 `warnings`
- 校验时跳过必填配置完整性检查，只保留结构合法性检查

第二阶段：配置补全

- 以上一阶段已经确认的骨架为输入
- 只向模型暴露骨架中实际使用到的节点子集
- 目标是补齐最小可运行配置，不鼓励新增无关节点或复杂增强步骤
- 使用完整计划校验，确保最终返回计划可被前端安全应用

### 3. 与现有流式观测保持兼容

- 保留 `started`、`attempt_started`、`stage_changed`、`text_delta`、`diagnostic`、`completed`、`failed` 事件
- 流式界面继续展示实时进度和模型实时输出
- 两阶段过程中，阶段消息明确区分“骨架规划”和“配置补全”
- 任一阶段失败时，仍然带着失败原因和原始输出摘要进入一次定向修复重试

## 约束

- 用户可见文案保持中文
- 最终计划仍必须符合工作流连接规则与节点协议
- API Key 只允许存在于环境变量或本地运行配置中，不进入 git 追踪文件
- 若未来继续扩展提示词，不允许重新把完整节点帮助文档直接塞回模型上下文

## 验收标准

- 两阶段生成链路在单测中可覆盖成功、修复重试、超时和节点子集收敛场景
- 流式接口与前端实时观测体验不回退
- 弱模型在常见“导入数据 -> 分析 -> 输出”场景中，更稳定地产出最小可运行计划
