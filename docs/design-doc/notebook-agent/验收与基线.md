# 验收与基线

本文档定义 Notebook Agent 各阶段的验收标准、性能基线、决策汇总、未来分期路线。

---

## 1. M1 验收路径

决策 Q39：完整路径。

### 1.1 端到端场景

```
1. 用户在画布上有一个已成功执行的"数据清洗"节点（含 ~10000 行数据）
2. 用户点顶部菜单 "AI 分析笔记本"
3. NewNotebookDialog 弹出，用户从 "画布节点" Tab 选中该节点
4. 用户点 "开始分析"
5. iframe 全屏覆盖，显示 "准备 Python 环境..." 进度条
6. ≤ 90s 内 Pyodide 加载完成（首次冷启动；SW 缓存后 ≤ 5s）
7. 笔记本进入就绪态，输入框可用
8. Agent 自动进入 grill-me 风格的需求澄清，问 1-3 轮
9. 用户回答后 Agent 用 todo_write 写下计划
10. Agent 调 python_exec_inline 跑 describe / dtypes / na count
11. Agent 边分析边 plt.savefig 出图，fs_write reports/main.md
12. 文件树自动刷新（2s 轮询 + 主动事件），用户能在右栏看到新文件
13. 点击 reports/main.md → 右下预览面板渲染 Markdown，含图表
14. 用户点 "下载工作区 zip"，浏览器下载 .zip 文件，含完整 reports + artifacts + scripts + inputs
15. 用户关闭笔记本，回到画布
```

### 1.2 验收 Gate

每条都必须通过：

| # | Gate | 检查方式 |
|---|------|---------|
| 1 | 主站顶部菜单按钮可点击，弹出 dialog | E2E |
| 2 | dialog 列出当前画布上所有可用节点 | E2E |
| 3 | 选中节点 + 点 "开始分析" → iframe 出现 | E2E |
| 4 | iframe 显示加载进度，含具体阶段 / 包名 | E2E |
| 5 | 加载完成（≤ 90s 冷启动 / ≤ 5s 热启动）| 性能基线 |
| 6 | 笔记本就绪后 Agent 自动开始 grill | 运行轨迹 |
| 7 | Agent 用 ask_user 提问，UI 卡片显示选项 | E2E |
| 8 | 用户选项 → Agent 继续推理 | E2E |
| 9 | Agent 用 todo_write，TODO 面板渲染 | E2E |
| 10 | Agent 用 python_exec_inline，stdout 流式显示 | E2E |
| 11 | Agent 用 fs_write 写脚本和报告，文件树 2s 内出现 | E2E |
| 12 | Agent 出图 plt.savefig 到 artifacts/，文件树出现 .png | E2E |
| 13 | 点 reports/main.md → 预览面板显示渲染后的 Markdown，图表内联可见 | E2E |
| 14 | 点 "下载 zip" → 文件正确生成，包含全部产物 | E2E |
| 15 | 关闭笔记本 → iframe 销毁，回到画布 | E2E |
| 16 | 安全清单 20 项全过 | 自动化测试（[安全模型 §9](安全模型.md#9-红队验证清单)）|
| 17 | 性能基线全过 | 性能测试 |
| 18 | Linux + Windows 本地都能运行整套验收 | 跨平台手动验证 |

## 2. 性能基线

决策 Q40：推荐基线。

### 2.1 加载性能

| 指标 | 基线 | 测量 |
|------|------|------|
| 首次进入笔记本 → 准备就绪 | ≤ 90s | 本地服务器 + Chrome 100Mbps |
| 后续访问（SW 缓存命中）| ≤ 5s | 同上 |
| iframe HTML 首字节 | ≤ 200ms | 同源 |
| Worker 创建 | ≤ 100ms | 不含 Pyodide |
| Pyodide 解析 wasm | ≤ 8s | 取决于 CPU |
| 默认包加载 | ≤ 60s | 取决于 CPU + 包大小 |

### 2.2 执行性能

| 场景 | 基线 |
|------|------|
| python_exec_inline 简单 print | ≤ 500ms |
| python_exec_inline 第一次 import pandas | ≤ 1s |
| python_exec_inline 后续 import pandas | ≤ 50ms |
| pd.read_csv 10000 行 | ≤ 2s |
| df.describe() 10000 行 × 24 列 | ≤ 3s |
| 单次 plt.savefig 简单图 | ≤ 2s |
| Worker 崩溃后重建（不含 Pyodide 重载）| ≤ 5s |
| Worker 重建（含 Pyodide 重载，缓存命中）| ≤ 30s |

### 2.3 文件系统性能

| 操作 | 基线 |
|------|------|
| fs_read 100KB 文本 | ≤ 100ms |
| fs_write 100KB 文本 | ≤ 200ms |
| fs_list 10 个文件 | ≤ 50ms |
| fs_grep 10 个文件 (1MB 总量) | ≤ 500ms |
| OPFS 列目录（文件树轮询）| ≤ 100ms |

### 2.4 测量方法

性能测试加进 `tests/notebook-agent/performance/`，用 vitest 跑：

```typescript
test('python_exec_inline simple print should be fast', async () => {
  const start = performance.now()
  const result = await execInline('print("hello")')
  expect(performance.now() - start).toBeLessThan(500)
  expect(result.stdout).toBe('hello\n')
})
```

CI 中跑性能测试（在容器中），结果归档到时序 DB 看趋势。

## 4. 分期路线

### 4.1 M1（4 周）—— 端到端跑通

参见 [§1 验收路径](#1-m1-验收路径)。

里程碑：

- W1：PoC 跑通（Pyodide 在 Worker 内能 exec）
- W2：完整工具集 + iframe ↔ Worker RPC
- W3：UX 三栏 + 文件树 + 预览
- W4：安全清单 + 性能基线 + 跨平台验证

### 4.2 M2（3 周）—— 体验打磨与扩能

新增：

- `python_install`（micropip 白名单）
- `chart_save_echarts` + 前端交互渲染
- `data_import_from_node`（Agent 中途追加数据）
- `fs_glob` / `fs_delete`
- `python_kernel_reset` 工具
- 报告 PDF 导出（前端 print-to-pdf）
- "最近的笔记本"列表 / 跨设备恢复（OPFS 列举 + 服务端可选归档）
- 实时资源面板（Worker 内存可视化）

### 4.3 M3（按需）—— 高阶

候选：

- `call_legacy_analysis`：调既有 Python 后端的 XGBoost / Lasso 等高阶分析
- 服务端 Pyodide runtime（可选部署，应对大数据集场景）
- Session 历史浏览
- 大数据集 Arrow IPC 接入
- Permissions-Policy 收紧
- DOMPurify 替换为 trusted-types
- PII 检测中间件

## 5. 已知局限

诚实声明，避免后续被问到时反复解释：

| 局限 | 影响 | 应对 |
|------|------|------|
| 不能装任意 pip 包（M1）| Agent 用不了 xgboost 等 | sklearn 替代，M3 加 call_legacy_analysis |
| pandas 慢 1.5-3x 于 CPython | 大数据集体验差 | 单数据集 ≤ 200MB 上限，M3 评估服务端 Pyodide |
| 不能跨设备 / 跨浏览器恢复（M1）| 用户换电脑就丢历史 | M2 加 OPFS 服务端归档 |
| 报告不能编辑（产品决策）| 用户想改文字得先改 fs_write | 不打算放开，保持可重跑可信 |
| iframe 跨域加载受 COEP 阻 | 用户引入外站图片不显示 | 引入前 fs_write 到 artifacts/ |
| 单 session 单 Worker | 用户不能开多个并发分析 | 决策一致，简化复杂度 |
| 浏览器 Tab 内存上限 ~4GB | 极大数据 / 长时间 session 会卡 | 资源面板提醒，M2 加自动清理 |
| Safari 16 / Firefox 115 以下不支持 | 老浏览器用户用不了 | 启动检测 + 友好提示 |

## 6. 风险登记

| 风险 | 等级 | 缓解 |
|------|------|------|
| Pyodide OPFS 直挂在 0.27.x 不够稳定 | 中 | PoC 阶段验证；不行降级到 IDBFS-like + iframe 主动 sync |
| postMessage 200MB 上限不够用 | 低 | M2 加 Arrow IPC 多块传输 |
| Service Worker 缓存破坏 | 中 | 版本化路径 + activate 阶段清理；用户能强刷 |
| Agent 行为偏离预期（不调 todo_write 等）| 中 | system prompt 调优；M2 加运行时检查 |
| LLM API 限流 / 失败 | 高 | 错误恢复 UI；用户重发；多 provider 容灾（既有）|
| 内存泄漏 | 中 | 资源面板可见；Worker 重启兜底；M2 加自动清理触发器 |
| WASM 沙箱 0day | 低 | Pyodide / Chrome 跟版升级；不对外开放高敏感数据 |
| OPFS 数据丢失（用户清浏览器数据 / 系统级清理）| 低 | UI 提示用户及时下载；M2 加服务端归档可选 |
