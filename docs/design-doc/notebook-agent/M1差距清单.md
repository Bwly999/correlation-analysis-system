## 一、🔴 需补实现（M1 欠债，7 项）

### A1. system-message 端点 + Worker 重启通知 Agent ✅

- **现状**：`POST /api/notebook-agent/sessions/:id/system-message` 端点未实现；`workerHost.ts:432` 的 `autoRestart()` 重启 Worker 后**没有**向 Agent 上下文注入"环境已重启"提示。
- **依据**：执行模型.md §5.3、UX §8.1、架构与数据流.md §2.2.2
- **改动**：
  1. `src/server/modules/notebookAgentRoutes.ts` 新增 `POST /:sessionId/system-message`，向 session 注入 system message
  2. `workerHost.ts` 的 `autoRestart()` 在 init_done 后调用该端点
- **验收**：硬超时触发后，Agent 下一轮收到"Python 环境已重启，Workspace 文件保留"提示
- **优先级**：高

### A2. audit 端点 + 前端 auditLogger ✅

- **现状**：`POST /api/notebook-agent/sessions/:id/audit` 端点未实现；`src/notebook/runtime/auditLogger.ts` 不存在。
- **依据**：安全模型.md §8、部署与构建.md §9
- **改动**：
  1. 新增 audit 端点（持久化 worker_restart / quota_hit / 连续 5 次 tool_error / session 结束时全量 buffer）
  2. 新增 `auditLogger.ts`：ring buffer（≤500 条），记录 `exec_start/exec_done/fs_write/fs_edit/tool_error/worker_restart/quota_hit`，**只记 SHA-256 + 长度，不记代码全文/数据值**
  3. 在 workerHost / toolDispatcher / fsTools 关键节点埋点
- **验收**：触发硬超时后能在后端看到 worker_restart 审计记录
- **优先级**：高

### A3. Service Worker 缓存 Pyodide 资源 ✅

- **现状**：`src/notebook/sw.ts` 不存在；`vite.config.ts` 无 `buildNotebookSw` 插件；notebook.html 未注册 SW。
- **依据**：部署与构建.md §5、验收与基线.md §2.1（热启动 ≤5s 的关键）
- **改动**：
  1. 新增 `src/notebook/sw.ts`（scope `/notebook.html`，仅缓存 `/pyodide/v0.27/*`，版本化路径 + activate 阶段清理旧版）
  2. `vite.config.ts` 加 `buildNotebookSw` 插件（`apply: 'build'`，`closeBundle` 内 lib build 出 `dist/notebook-sw.js`）
  3. `notebook.html` 注册 SW
- **验收**：冷启动后第二次进入 ≤5s（SW 命中）
- **优先级**：高

### A4. 安全红队清单 20 项自动化测试 ✅

- **现状**：`tests/notebook-agent/security/` 不存在；e2e 只有 `notebook-bootstrap-race.spec.mjs` 一个。
- **依据**：安全模型.md §9（20 项清单）、验收与基线.md §1.2 Gate 16
- **改动**：在 `tests/notebook-agent/security/` 落 vitest + Playwright 用例，覆盖清单全部 20 项（jsglobals 锁定、路径越界、软/硬超时、OOM 重启、配额、跨 session 越界、postMessage 来源校验、schema 校验、XSS sanitize 等）
- **验收**：`pnpm test:unit -- notebook-agent/security` + `pnpm test:e2e -- notebook-agent` 全过
- **优先级**：高（M1 发布前 CI gate）

### A5. 性能基线测试 ✅

- **现状**：`tests/notebook-agent/performance/` 不存在。
- **依据**：验收与基线.md §2.4、Gate 17
- **改动**：在 `tests/notebook-agent/performance/` 落 vitest 用例，覆盖加载性能（冷/热启动、Worker 创建、wasm 解析、包加载）、执行性能（print / import pandas 首次+后续 / read_csv / describe / savefig / Worker 重建）、文件系统性能（fs_read/write/list/grep、OPFS 列目录）
- **验收**：基线阈值全过；CI 跑通
- **优先级**：中

### A6. 生产构建 COI 头注入 ✅

- **现状**：`vite.config.ts:86-112` 的 `notebookCoiHeaders()` 只 `apply: 'serve'`；生产侧（Fastify 静态服务）**没有**对应 hook。
- **依据**：部署与构建.md §3.3、安全模型.md §4.1
- **改动**：新增 `src/server/notebookHeadersPlugin.ts`（或 app.ts onSend hook），对 `/notebook.html`、`/notebook-iframe.html`、`/notebook`、`/pyodide/v0.27/*` 注入 COOP=same-origin + COEP=require-corp（pyodide 资源另加 CORP=cross-origin）
- **验收**：生产构建后访问 `/notebook.html`，DevTools Console `crossOriginIsolated === true`
- **优先级**：高

### B6. exec 后自动 sync artifacts/ 到 OPFS ✅

- **现状**：Agent `plt.savefig('artifacts/xxx.png')` 落盘到 Worker **MEMFS**，没有自动 sync 回 OPFS。导致主站文件树（轮询 OPFS）和预览面板**看不到产物**。
- **依据**：架构与数据流.md §3.4（"退化方案：MEMFS 内运行，定期 sync 到 OPFS"——口子留了但未落地）、验收与基线.md §1.2 Gate 12/13（出图 + 预览，硬依赖）
- **改动**：
  1. `workerHost.ts` exec 完成后调 `snapshotFs(['artifacts'])` 拉变更文件回主线程
  2. 主线程写入 OPFS（复用 `opfsAccess.writeFile`）
  3. 触发 `iframe.workspace_changed` 通知主站刷新文件树
- **验收**：Agent savefig 后 ≤2s 主站文件树出现 .png，预览面板能渲染
- **优先级**：高（数据流硬伤）

### B2. 前端 store：Pinia → runtime reactive ✅

- **实现**：不存在 `src/stores/notebookAgentStore.ts`。状态在 `src/notebook/runtime/notebookSessionRuntime.ts` 的 `reactive(...)`；Todo 用 `notebookTodoStore.ts` 工厂函数（非 defineStore）；主站侧会话逻辑在 `useNotebookSession.ts` 组合式。**notebook main.ts 刻意不挂 Pinia**。
- **文档写的**：`src/stores/notebookAgentStore.ts`（Pinia）
- **改**：index.md §4 表、§5.2；UX §3.1；工具集协议.md §6 路由表 todo_write 行

### B3. Worker 入口文件名 ✅

- **实现**：`src/notebook/worker/worker.ts`（+ `pyodideBoot.ts`）
- **文档写的**：`src/notebook/worker/pyodideWorker.ts`
- **改**：index.md §4 表；部署与构建.md §2.3、§4.5

### B4. eventBridge / safePayload 复用关系 ✅

- **实现**：
  - `gateway.ts:32` 导入的是 `./eventBridge.js`（**notebook 自有同名文件**，非复用 piAgent 的）
  - `safePayload.ts` 在 notebook 目录 **零引用**（notebook 不走画布数据通路，确实不需要）
  - 实际复用的是 `src/server/piAgent/frontendBridge.ts`（gateway.ts:25）—— 设计文档没列
- **文档写的**：index.md §5.1 声称复用 piAgent/eventBridge.ts + safePayload.ts
- **改**：index.md §5.1 复用清单（去掉 safePayload；eventBridge 注明"notebook 自有"；补 frontendBridge）；安全模型.md §14 去掉"后端 SSE 推送仍脱敏"的误导（实际没复用 safePayload）

### B5. 超时双层语义澄清 ✅

- **实现**（完整且正确）：
  - 前端 Worker 双层（`workerHost.ts:159-194`）：软 `timeoutMs`（默认 60s）→ 写 SAB；硬 `timeoutMs × 1.5`（90s）→ terminate + `autoRestart()`。与文档 60s/90s **完全一致**
  - 服务端兜底（`tools.ts` `PYTHON_TIMEOUT_MS=120000`）：防前端 bridge 永不回包的后端侧保险，独立一层
- **文档写的**：执行模型.md §3.1、安全模型.md §7.1 只写"软 60s / 硬 90s"，未说明这是前端 Worker 侧，也未提后端 120s 兜底
- **改**：执行模型.md §3.1 补一段说明两层关系；架构与数据流.md §2.2.2 同步

### B6-文档侧. OPFS 挂载方式回填最终选择 ✅

- **实现**（退化方案）：
  - 真实持久层 = OPFS（iframe 主线程异步读写）
  - Pyodide 可见层 = MEMFS（Worker 内虚拟 FS）
  - `bootPyodide` 只 mkdirTree 四个目录（不挂 OPFS）；`parent.import_csv` 时 OPFS + MEMFS 各写一份
  - Agent 的 fs_* 全走 OPFS；python_exec 跑在 MEMFS
  - exec 后**没有**自动 sync（→ 见一、B6 实现缺口）
- **文档写的**：架构与数据流.md §3.4 留"两条路径 PoC 定，回填本文档"的口子；安全模型.md §5.3 仍按"NODEFS 直接挂 OPFS"描述
- **改**：架构与数据流.md §3.4 写定最终方案；安全模型.md §5.3 NODEFS 描述改成 MEMFS + sync

### B7. ask_user 超时说明 ✅

- **实现**：服务端 `ASK_USER_TIMEOUT_MS = 24*60*60*1000`（24h 兜底防泄漏）；前端无超时
- **文档写的**：工具集协议.md §5.2 "M1 不做超时"
- **改**：工具集协议.md §5.2 补"服务端 24h bridge 兜底，前端无超时"

### worker 协议文档化（顺带）

- **实现**：实际协议是 `init / exec_inline / fs_write_inline / fs_snapshot / shutdown`，**没有独立 `interrupt` 消息**（中断直接走 SAB，由 pyodide.setInterruptBuffer 处理）
- **文档写的**：架构与数据流.md §2.2.1 列了 `exec_file / interrupt` 等不存在的 kind
- **改**：架构与数据流.md §2.2.1 协议结构改成实际形态
