# 数据接入

本文档定义数据如何进入 Notebook session：启动 dialog、画布节点 vs 数据源、CSV 编码、postMessage Transferable、inputs/ 目录约定。

---

## 1. 决策回顾

| 维度 | 选择 |
|------|------|
| 数据来源 | 画布节点输出 + 全局数据源（file / kanban-recording）|
| 接入时机 | **仅启动时一次**（M1） |
| 编码格式 | CSV 文本（决策 Q5）|
| 传输方式 | postMessage transferable ArrayBuffer（决策 Q4）|
| 入口形态 | 顶部菜单 + dialog 选数据来源（决策 Q22）|

M2 才考虑放开"Agent 中途追加数据"。

---

## 2. 启动流程

```
1. 用户点顶部菜单 "新建分析笔记本"
2. 主站弹出 NewNotebookDialog
   ├── Tab 1：画布节点（列出当前画布上有 NodeResult 输出的节点）
   │   └── 每行显示：节点名、类型、行数 / 列数 / kind 摘要
   └── Tab 2：全局数据源（列出 file-import / neighbor-system 已配置数据源）
       └── 每行显示：数据源名、kind、schema 摘要
3. 用户选一个 → 点 "开始分析"
4. 主站生成 notebookSessionId
5. 主站 POST /api/notebook-agent/sessions { initialDataMeta }
6. 主站把所选数据转 CSV ArrayBuffer
7. 主站把 iframe 挂到全屏容器，src="/notebook.html?session={sid}"
8. iframe handshake → 主站 postMessage('parent.import_csv', { ... }, [buffer])
9. iframe 写 OPFS /notebook/{sid}/inputs/upstream.csv
10. iframe 启动 Pyodide Worker
11. iframe 通知主站 ready → Agent 开始第一轮 ask_user
```

## 3. 数据来源类型

### 3.1 画布节点

来源：`workflowStore` 当前画布上**已成功执行**的节点。

筛选条件（决定哪些节点出现在 dialog Tab 1）：

- `node.executionStatus === 'success'`（已跑完）
- `result.kind in ('table', 'tableCollection')`（M1 仅支持表格类）
- 排除 legacy / 已禁用的节点定义

UI 展示信息（来自 `result.payload` + `result.schema`）：

| 字段 | 来源 | 示例 |
|------|------|------|
| 节点名 | `node.label` | "数据清洗-2025Q2" |
| 节点类型 | `node.type` 翻译 | "数据清洗" |
| 行数 | `result.meta.rowCount` | "12,488 行" |
| 列数 | `result.schema.fields.length` | "24 列" |
| kind | `result.kind` | `table` 或 `tableCollection` |
| 字段预览 | `result.schema.fields.map(f => f.name).slice(0, 5).join(', ')` | "userId, age, ..." |

### 3.2 全局数据源

来源：`WorkflowAiDataSourceDescriptor[]`（已经在 `src/ai/types.ts` 定义）。

```typescript
interface WorkflowAiDataSourceDescriptor {
  id: string
  kind: 'file' | 'kanban-recording'
  entryNodeType: 'file-import' | 'neighbor-system'
  label: string
  schemaSummary: WorkflowAiContextSchemaSummary
  bindingPayload: Record<string, unknown>
}
```

对 Notebook 来说：

- `file` 类型 → 直接是用户上传的 CSV / xlsx 文件，可以直接转 CSV
- `kanban-recording` 类型 → 看板录入数据，需要走 `neighbor-system` 节点的取数逻辑

具体获取数据的代码已经存在于现有 `neighborSystem.ts` / `fileImport.ts` 节点的执行逻辑中。Notebook 启动时**复用**这些 helper（不重新实现）：

```typescript
// 主站侧伪码
const result = await loadDataSourceAsNodeResult(descriptor)
// result: NodeResult<table>
const csv = papaUnparse(result.payload as Array<Record<string, unknown>>)
const buffer = new TextEncoder().encode(csv).buffer
```

## 4. CSV 编码契约

### 4.1 转码逻辑

主站侧（在主站 main 进程，不是 Worker / iframe）：

```typescript
// src/components/notebookAgent/dataSourceCsv.ts
import Papa from 'papaparse'

export const nodeResultToCsv = (
  result: NodeResult,
): { buffer: ArrayBuffer; meta: ImportMeta } => {
  // tableCollection 取第一个 group（M1 简化）
  let rows: Array<Record<string, unknown>>
  if (result.kind === 'table') {
    rows = result.payload as Array<Record<string, unknown>>
  } else if (result.kind === 'tableCollection') {
    const groups = result.payload as Array<{ name: string; data: Array<Record<string, unknown>> }>
    if (groups.length === 0) throw new Error('数据源为空')
    if (groups.length > 1) {
      // M1：仅取第一个 group 并在 meta 中提示
      console.warn('tableCollection 有多个 group，M1 仅导入第一个')
    }
    rows = groups[0].data
  } else {
    throw new Error(`不支持的 NodeResult kind: ${result.kind}`)
  }

  const csv = Papa.unparse(rows, {
    header: true,
    skipEmptyLines: false,
    quotes: false,        // Papa 自动判断
  })
  const buffer = new TextEncoder().encode(csv).buffer

  return {
    buffer,
    meta: {
      sourceKind: 'canvas-node',  // 或 'data-source'
      sourceLabel: result.meta?.label ?? '',
      rowCount: rows.length,
      columnCount: Object.keys(rows[0] ?? {}).length,
    },
  }
}
```

### 4.2 类型保留约定

CSV 不保留 JS 原生类型，所有值落地都是字符串。Agent 在 Python 端用 `pd.read_csv` 读入时由 pandas 推断类型。

**已知的边界**：

| JS 值 | CSV 文本 | Python 推断 | 备注 |
|-------|---------|------------|------|
| `42` (number) | `42` | `int64` | OK |
| `3.14` (number) | `3.14` | `float64` | OK |
| `null` / `undefined` | `` (空) | `NaN` | OK |
| `true` / `false` | `true` / `false` | `object` (str) | **Agent 需要主动转 bool** |
| Date 对象 | `2026-06-10T...` (ISO) | `object` (str) | **Agent 需要 pd.to_datetime** |
| 嵌套对象 / 数组 | JSON 字符串 | `object` (str) | M1 不推荐这种数据进 Notebook |
| 含逗号 / 引号的字符串 | `"含,的,值"` | `object` (str) | Papa 自动转义 |

**System prompt 提示 Agent**：

```
读 inputs/upstream.csv 时：
- pd.read_csv() 推断的 dtype 可能不准（bool 变 str、date 变 str）
- 进入分析前先 print(df.dtypes) 确认；必要时用 pd.to_datetime / astype 转换
```

### 4.3 容量上限

启动时灌入数据**单文件上限**：

| 维度 | 限制 |
|------|------|
| 行数 | ≤ 1,000,000 |
| 列数 | ≤ 1,000 |
| CSV 字节 | ≤ 200MB（postMessage 单次传输的合理上限）|

超限时 dialog 阻塞用户：

```
"所选数据约 380MB / 1,500,000 行，超过 Notebook 启动数据上限。
建议在画布上先做 数据筛选 / 数据采样 节点缩减规模，再启动 Notebook。"
```

不做静默截断（避免 Agent 拿到意料之外的子集）。

## 5. postMessage Transferable

### 5.1 协议位置

参见 [架构与数据流 §2.1.1](架构与数据流.md#211-协议结构)：

```typescript
{
  kind: 'parent.import_csv',
  requestId: string,
  filename: string,        // 默认 'upstream.csv'
  buffer: ArrayBuffer,     // transferable
  meta: ImportMeta,
}
```

### 5.2 主站发送

```typescript
// 主站
const { buffer, meta } = nodeResultToCsv(result)
iframe.contentWindow.postMessage(
  {
    kind: 'parent.import_csv',
    requestId: uuid(),
    filename: 'upstream.csv',
    buffer,
    meta,
  },
  '*',  // targetOrigin —— iframe 同源，可填 '*'，但更安全是显式填 origin
  [buffer],  // transferable 列表
)
```

**关键**：把 `buffer` 加入 transferable 列表（第三个参数）—— 否则会触发结构化克隆，浪费内存与时间。

发送后主站侧的 `buffer` 变为 `byteLength === 0`（所有权已转移），主站不能再使用此 ArrayBuffer。

### 5.3 iframe 接收

```typescript
// iframe 内 src/notebook/runtime/parentBridge.ts
window.addEventListener('message', async (event) => {
  if (event.source !== window.parent) return  // 来源校验
  const msg = event.data as ParentBridgeRequest
  if (msg.kind !== 'parent.import_csv') return

  // 写 OPFS
  const safePath = resolveSafePath(currentSessionId, `inputs/${msg.filename}`)
  const dirHandle = await navigator.storage.getDirectory()
  const fileHandle = await ensureNestedFile(dirHandle, safePath)
  const writable = await fileHandle.createWritable()
  await writable.write(msg.buffer)
  await writable.close()

  // 响应
  window.parent.postMessage(
    {
      requestId: msg.requestId,
      kind: 'response',
      ok: true,
      data: { path: `inputs/${msg.filename}` },
    },
    '*',
  )

  // 通知主站文件树刷新
  window.parent.postMessage(
    { kind: 'iframe.workspace_changed', paths: [`inputs/${msg.filename}`] },
    '*',
  )
})
```

### 5.4 失败处理

| 失败 | 错误 code | 处理 |
|------|----------|------|
| OPFS 配额不足 | `quota_exceeded` | iframe 返回 ok=false；主站 dialog 显示错误并允许重选数据 |
| 路径越界 | `path_out_of_workspace` | 不可能（主站固定 filename），出现说明 bug |
| ArrayBuffer 损坏 | `invalid_buffer` | 主站重试一次；仍失败则 fail-fast |

## 6. inputs/ 目录约定

### 6.1 文件命名

M1 启动时灌入的文件**固定命名为** `inputs/upstream.csv`（决策 Q21）。

理由：

- Agent 不需要列目录就能开始读
- system prompt 直接指引："数据已加载到 inputs/upstream.csv，先 pd.read_csv 看看"
- 简化启动流程

M2 放开多源后，命名约定需调整为 `inputs/<sourceKind>_<safeName>.csv`，并在 system prompt 里告知 Agent 用 fs_list 探索。

### 6.2 文件元数据

启动时除了 CSV 本身，还在 `inputs/` 下落一份**元数据描述**：

```
inputs/
├── upstream.csv
└── upstream.meta.json
```

`upstream.meta.json` 内容：

```json
{
  "sourceKind": "canvas-node",
  "sourceLabel": "数据清洗-2025Q2",
  "rowCount": 12488,
  "columnCount": 24,
  "columns": [
    { "name": "userId", "inferredType": "string" },
    { "name": "age", "inferredType": "number" },
    ...
  ],
  "importedAt": "2026-06-10T14:32:00Z"
}
```

这份元数据：

- system prompt 在初始化时让 Agent 读它（fs_read inputs/upstream.meta.json）
- Agent 据此知道列名、推断类型，不必先读 csv
- 比直接读 csv 头 10 行**信息更密**（含 rowCount 等）

## 7. Agent 初次接触数据的标准动作

System prompt 引导 Agent 在第一轮（grill-me 完成需求对齐之后）做以下动作：

```python
# Step 1: 读元数据
# fs_read inputs/upstream.meta.json
# → 获得 rowCount, columnCount, columns 列表

# Step 2: 跑基础统计
# python_exec_inline:
import pandas as pd
df = pd.read_csv('inputs/upstream.csv')
print('shape:', df.shape)
print('dtypes:')
print(df.dtypes)
print()
print('describe:')
print(df.describe(include='all'))
print()
print('na counts:')
print(df.isna().sum())
print()
print('head:')
print(df.head(5))
```

这是 Agent 形成第一印象的标准入口。Agent 后续根据用户目标决定下一步。

## 8. M2+ 演进

### 8.1 Agent 中途追加数据（M2）

新增工具 `data_import_from_node`：

```typescript
{
  nodeId: string           // 画布节点 ID
  filename?: string        // 默认 inputs/<nodeLabel>.csv
}
```

执行链路：

```
Agent → tool.execute → iframe → postMessage 给主站 → 主站读 workflowStore → 转 CSV → import_csv 回 iframe
```

### 8.2 流式 / 大数据 (M3)

启用 Apache Arrow IPC + IndexedDB 分块写入，突破 200MB postMessage 限制。Agent 写 pyarrow 读取。

### 8.3 增量数据接入 (M3)

支持画布节点重新执行后，Notebook 接收增量数据通知 → Agent 决定是否重读。
