## 3. COOP/COEP 头

决策 Q1：仅对 `/notebook.html` 开启 COI。

### 3.1 头部清单

```
Cross-Origin-Opener-Policy:   same-origin
Cross-Origin-Embedder-Policy: require-corp
```

`require-corp` 模式下，所有跨域资源必须带 `Cross-Origin-Resource-Policy: cross-origin` 头才能加载。M1 笔记本不引用任何跨域资源，安全。

### 3.2 Vite dev 配置

dev 模式下用 plugin 拦截响应：

```typescript
// vite.config.ts
const notebookCoiHeaders = (): Plugin => ({
  name: 'notebook-coi-headers',
  apply: 'serve',
  configureServer(server) {
    server.middlewares.use((req, res, next) => {
      const url = req.url ?? ''
      if (url.startsWith('/notebook.html') || url.startsWith('/pyodide/')) {
        res.setHeader('Cross-Origin-Opener-Policy', 'same-origin')
        res.setHeader('Cross-Origin-Embedder-Policy', 'require-corp')
        res.setHeader('Cross-Origin-Resource-Policy', 'cross-origin')
      }
      next()
    })
  },
})

export default defineConfig({
  plugins: [
    // ... 既有
    notebookCoiHeaders(),
  ],
})
```

注意：

- `/pyodide/` 资源也加 COI 头（同源资源在 require-corp 下不需要 CORP，但保险起见加上）
- 主站 `/`、`/api/` 等不加 COI 头，主站正常

### 3.3 生产 Fastify 配置

实现：`src/server/notebookHeadersPlugin.ts`，由 `src/server/app.ts` 在启动时调用 `registerNotebookHeaders(app)` 注册根级 `onSend` hook（全局生效，与路由注册顺序无关）。

```typescript
// src/server/app.ts
import { registerNotebookHeaders } from './notebookHeadersPlugin.js'
// ...
void registerNotebookHeaders(app)
```

头部策略（与 dev `notebookCoiHeaders` 对齐）：
- 所有响应默认 `Cross-Origin-Resource-Policy: same-origin`（不覆盖已设值）
- `/notebook.html`、`/notebook-iframe.html`、`/notebook`、`/notebook?*`、`/notebook/*`、`/src/notebook/*`、`/assets/notebook*` → 额外加 `COOP: same-origin` + `COEP: require-corp`
- `/pyodide/v0.27/*` → `CORP: cross-origin` + `COEP: require-corp`（允许 notebook 页面在 require-corp 下加载）

### 3.4 静态资源服务

生产部署时，Fastify 用 `@fastify/static` 服务 `dist/` 目录。COI 头通过上述 hook 加在静态响应上。

如果未来切到 Nginx + 静态托管，需要在 nginx.conf 加：

```nginx
location ~ ^/(notebook\.html|pyodide/) {
    add_header Cross-Origin-Opener-Policy "same-origin";
    add_header Cross-Origin-Embedder-Policy "require-corp";
    add_header Cross-Origin-Resource-Policy "cross-origin";
}
```

### 4.2 默认包列表

| 包 | 体积 | 用途 |

### 4.2.1 中文字体（matplotlib 中文渲染）

Pyodide 的 matplotlib wheel 只捆绑 DejaVu Sans 等字体，**不含任何中文字形**，画中文标签会显示为「豆腐块」，agent 只能回退英文。为此 boot 阶段会向 matplotlib 注入一个中文字体：

- **字体来源**：思源黑体（Noto Sans SC，OFL-1.1 许可，可商用）。Regular 字重 TTF，约 9 MB。下载地址：<https://fonts.google.com/noto/specimen/Noto+Sans+SC>（在页面右上角「Download family」下载 zip，取出 `NotoSansSC-Regular.ttf`）。
- **放置位置**：`ops/pyodide-runtime/v0.27.x/fonts/NotoSansSC-Regular.ttf`。该目录随 `scripts/copy-pyodide-runtime.mjs` 的 `cp(recursive)` 自动进入 `public/pyodide/v0.27/fonts/`，并由 Vite 中间件服务到 `/pyodide/v0.27/fonts/<name>`。
- **加载时机**：`pyodideBoot.ts` 的 boot 流程在 `loadPackage` 之后、删除 worker `fetch` 之前（此时 fetch 仍可用），用 `fetch('/pyodide/v0.27/fonts/NotoSansSC-Regular.ttf')` 拉取字节 → 写入 MEMFS `/fonts/` → `fontManager.addfont` + 设 `rcParams['font.sans-serif']`。利用 `sys.modules` 跨 exec 持久，注册一次后续所有 `python_exec_*` 默认中文可用。
- **优雅降级**：字体缺失（HTTP 非 200）/ fetch 失败 / Python 注册失败，一律仅打 progress 提示并跳过，不阻断 boot，保持原行为（中文显示为方块）。
- **换字体**：改 `pyodideBoot.ts` 顶部 `ZH_FONT_FILE`（文件名）与 `ZH_FONT_FAMILY`（matplotlib 识别的字体 PostScript 名）两处常量。

> 字体文件不进 git（体积大），需在准备 `ops/pyodide-runtime/` 时一并手动放入。

### 4.3 资源拷贝脚本

新增 `scripts/copy-pyodide-runtime.mjs`：

```javascript
// scripts/copy-pyodide-runtime.mjs
import { cp, mkdir, readdir } from 'node:fs/promises'
import { join, dirname } from 'node:path'
import { fileURLToPath } from 'node:url'

const __dirname = dirname(fileURLToPath(import.meta.url))
const SOURCE = join(__dirname, '..', 'ops', 'pyodide-runtime', 'v0.27.x')
const DEST = join(__dirname, '..', 'dist', 'pyodide', 'v0.27')

async function main() {
  await mkdir(DEST, { recursive: true })
  await cp(SOURCE, DEST, { recursive: true })
  const entries = await readdir(DEST)
  console.log(`[pyodide] 拷贝完成，${entries.length} 个文件 → ${DEST}`)
}

main().catch((err) => {
  console.error('[pyodide] 拷贝失败', err)
  process.exit(1)
})
```

集成到构建流程：

```json
// package.json
{
  "scripts": {
    "build": "run-p type-check \"build-only {@}\" build:server build:pyodide --",
    "build:pyodide": "node scripts/copy-pyodide-runtime.mjs"
  }
}
```

## 5. Service Worker 缓存

### 5.1 范围

- scope：`/notebook.html`
- 仅缓存 `/pyodide/v0.27/*` 资源
- 不缓存 `/api/`、`/index.html`、主站任何资源

### 5.2 实现

```typescript
// src/notebook/sw.ts
const CACHE_NAME = 'pyodide-v0.27.x'
const PYODIDE_URL_PATTERN = /\/pyodide\/v0\.27\//

self.addEventListener('install', (event: ExtendableEvent) => {
  ;(self as unknown as ServiceWorkerGlobalScope).skipWaiting()
})

self.addEventListener('activate', (event: ExtendableEvent) => {
  event.waitUntil(
    caches.keys().then((names) =>
      Promise.all(
        names
          .filter((n) => n !== CACHE_NAME && n.startsWith('pyodide-'))
          .map((n) => caches.delete(n)),
      ),
    ),
  )
  ;(self as unknown as ServiceWorkerGlobalScope).clients.claim()
})

self.addEventListener('fetch', (event: FetchEvent) => {
  const url = new URL(event.request.url)
  if (!PYODIDE_URL_PATTERN.test(url.pathname)) return  // 不接管

  event.respondWith(
    (async () => {
      const cache = await caches.open(CACHE_NAME)
      const cached = await cache.match(event.request)
      if (cached) return cached
      const response = await fetch(event.request)
      if (response.ok) {
        cache.put(event.request, response.clone())
      }
      return response
    })(),
  )
})
```

### 5.3 升级 Pyodide 的处理

Pyodide 升级时换路径前缀：

- v0.27 → `/pyodide/v0.27/`
- v0.28 → `/pyodide/v0.28/`

旧版本由 sw 自动清理（`activate` 阶段）。

### 5.4 Vite Service Worker 处理

Vite 默认不为非主入口的 ts 文件生成独立 bundle。用 `vite-plugin-pwa` 或自定义 plugin：

```typescript
// vite.config.ts
const buildNotebookSw = (): Plugin => {
  return {
    name: 'build-notebook-sw',
    apply: 'build',
    closeBundle: async () => {
      const result = await build({
        configFile: false,
        build: {
          lib: {
            entry: resolve(__dirname, 'src/notebook/sw.ts'),
            formats: ['iife'],
            fileName: () => 'notebook-sw.js',
          },
          outDir: resolve(__dirname, 'dist'),
          emptyOutDir: false,
        },
      })
      console.log('[notebook-sw] built')
    },
  }
}
```

PoC 阶段可以先不做 SW（每次重下 100MB），M1 必须实现。

## 7. 部署形态

### 7.1 私有化（最常见）

把 `dist/` 与 `dist-server/` 一起部署到客户内网：

```
nginx / Fastify 静态服务
↓
dist/index.html              ← 主站
dist/notebook.html           ← 笔记本
dist/pyodide/v0.27/...       ← Pyodide 资源
dist-server/server/index.js  ← API
```

部署机器需要：

- Node.js 20.19+ 或 22.12+
- 100MB+ 磁盘空间（pyodide 资源）
- 反向代理（可选，如 nginx）

### 7.2 Electron / Tauri 桌面打包

未来如果要做桌面应用：

- Electron：把 `dist/` 一起打进 asar，pyodide 资源走 file:// URL
- Tauri：similar，需要 Tauri 提供本地 HTTP server 模拟同源

注意：file:// 协议下 SharedArrayBuffer 不可用（COOP/COEP 不生效）。所以桌面打包必须**起本地 HTTP server**。Electron 可以用 `protocol.registerHttpProtocol`，Tauri 默认就是 HTTP 模拟。

M1 不做桌面打包；产品上仍是浏览器访问的 web 应用。

### 10.3 启动检测

iframe 启动时检测能力：

```typescript
const requirements = {
  crossOriginIsolated: typeof crossOriginIsolated !== 'undefined' && crossOriginIsolated,
  sharedArrayBuffer: typeof SharedArrayBuffer === 'function',
  opfs: 'storage' in navigator && 'getDirectory' in navigator.storage,
  worker: typeof Worker !== 'undefined',
}

const missing = Object.entries(requirements)
  .filter(([_, ok]) => !ok)
  .map(([k]) => k)

if (missing.length) {
  showFatalError(`当前浏览器不支持 ${missing.join(', ')}，请升级至最新版本`)
}
```
