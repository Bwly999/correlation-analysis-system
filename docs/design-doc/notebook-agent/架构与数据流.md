# 架构与数据流

本文档定义 Notebook Agent 的整体架构、组件层级、跨边界通信协议、OPFS 布局。

### 1.1 三个进程边界

```
[ 主站窗口 ]  ←─ postMessage RPC ──→  [ iframe 窗口 ]  ←─ postMessage ──→  [ Pyodide Worker ]
   ↓                                       ↓                                     ↓
   axios → 服务端                          axios → 服务端                       (无网络)
                                          OPFS R/W                              OPFS R/W (NODEFS)
```

| 边界 | 通信方式 | 主要载荷 |
|------|---------|---------|
| 主站 ↔ iframe | postMessage RPC | 数据灌入（CSV ArrayBuffer）、关闭信号、初始 session 元数据 |
| iframe ↔ Worker | postMessage | exec 请求 / stdout 流 / exec 结果 / 中断信号 |
| 主站 → 服务端 | axios（统一 httpClient）| Notebook Agent session HTTP 请求 |
| iframe → 服务端 | axios（统一 httpClient）| Pi SDK 消息流（SSE）、tool-result 回传 |
| Worker → 网络 | **被禁用** | —— |

## 2. 跨边界通信协议

### 2.1 主站 ↔ iframe（postMessage RPC）

主站通过 `iframe.contentWindow.postMessage` 发请求，iframe 通过 `window.parent.postMessage` 回响应。所有消息严格按 schema 校验，不允许任意扩展。

#### 2.1.1 协议结构

```typescript
// src/notebook/shared/parentBridge.ts
export type ParentBridgeRequest =
  | {
      kind: 'parent.handshake'
      requestId: string
      sessionId: string
      origin: string
    }
  | {
      kind: 'parent.import_csv'
      requestId: string
      filename: string         // 写入 inputs/<filename>.csv
      buffer: ArrayBuffer      // transferable
      meta: {
        sourceKind: 'canvas-node' | 'data-source'
        sourceLabel: string
        rowCount: number
        columnCount: number
      }
    }
  | {
      kind: 'parent.close_request'
      requestId: string
      reason: 'user_clicked_close' | 'session_completed' | 'tab_unload'
    }

export type IframeBridgeRequest =
  | {
      kind: 'iframe.ready'
      sessionId: string
    }
  | {
      kind: 'iframe.workspace_changed'
      paths: string[]          // 新增/变更的文件路径，主站文件树可据此触发刷新
    }
  | {
      kind: 'iframe.session_state'
      state: 'loading_pyodide' | 'ready' | 'agent_running' | 'agent_idle' | 'failed'
      detail?: string
    }
  | {
      kind: 'iframe.request_unload_confirm'
      hasUnsavedExec: boolean  // 是否有正在跑的 exec
    }

export type ParentBridgeResponse = {
  requestId: string
  kind: 'response'
  ok: boolean
  data?: unknown
  error?: { code: string; message: string }
}
```

#### 2.1.2 主要交互序列

**初始化**：

```
主站：iframe 创建后立即 postMessage('parent.handshake', { sessionId })
iframe：postMessage('iframe.ready', { sessionId })  → 主站显示就绪
iframe → Worker：启动 Pyodide
iframe：postMessage('iframe.session_state', { state: 'loading_pyodide' })
        ...
iframe：postMessage('iframe.session_state', { state: 'ready' })
```

**画布数据灌入**（仅启动阶段一次）：

```
主站：从 workflowStore 拿 NodeResult → 转 CSV (Papa.unparse) → ArrayBuffer
主站：postMessage('parent.import_csv', { filename: 'upstream.csv', buffer }, [buffer])
iframe：写入 OPFS /notebook/{sid}/inputs/upstream.csv
iframe：postMessage('response', { ok: true, data: { path: 'inputs/upstream.csv' } })
iframe：postMessage('iframe.workspace_changed', { paths: ['inputs/upstream.csv'] })
```

**关闭**：

```
用户点关闭按钮 → 主站：postMessage('parent.close_request', { reason })
iframe：postMessage('iframe.request_unload_confirm', { hasUnsavedExec })
主站：根据 hasUnsavedExec 决定是否弹确认框
主站：销毁 iframe DOM 节点
```

#### 2.1.3 协议约束

- 所有消息必须带 `requestId`（响应类除外，但响应必须带回原 requestId）
- 主站只接受来自 iframe 的 postMessage（验证 `event.source === iframe.contentWindow`）
- iframe 只接受来自 `window.parent` 的 postMessage（验证 `event.source === window.parent`）
- ArrayBuffer 必须用 transferable 列表传递（`postMessage(msg, [buffer])`），避免拷贝
- 协议变更必须前后端同步发版；旧版本 iframe 不识别新 kind 时主站要降级
- 单条消息体积建议 ≤ 100MB（浏览器 postMessage 大体积时会卡 GC）

### 2.2 iframe ↔ Worker（postMessage）

Worker 是 iframe 创建的 Dedicated Worker，按 sessionId 1:1 绑定。

#### 2.2.1 协议结构

```typescript
// src/notebook/worker/protocol.ts
export type IframeToWorker =
  | {
      kind: 'init'
      indexURL: string         // /pyodide/v0.27/
      packages: string[]       // 默认包列表
    }
  | {
      kind: 'exec_inline'
      execId: string
      code: string
      timeoutMs: number        // 默认 60000
    }
  | {
      kind: 'exec_file'
      execId: string
      path: string             // 相对 workspace 根
      timeoutMs: number
    }
  | {
      kind: 'interrupt'
      execId: string           // SIGINT 当前 exec
    }
  | {
      kind: 'shutdown'
    }

export type WorkerToIframe =
  | {
      kind: 'init_progress'
      stage: 'load_runtime' | 'load_packages' | 'mount_fs' | 'lock_sandbox'
      packageName?: string     // load_packages 时填具体包名
      progressPercent: number
    }
  | {
      kind: 'init_done'
    }
  | {
      kind: 'init_failed'
      error: { code: string; message: string }
    }
  | {
      kind: 'stdout'
      execId: string
      stream: 'stdout' | 'stderr'
      text: string             // 增量片段
    }
  | {
      kind: 'exec_done'
      execId: string
      status: 'ok' | 'error' | 'interrupted' | 'timeout'
      elapsedMs: number
      error?: { type: string; message: string; traceback?: string }
    }
```

#### 2.2.2 交互流

**Worker 初始化**：

```
iframe：new Worker('/notebook/worker.js')
iframe：postMessage('init', { indexURL, packages })
Worker：loadPyodide({ indexURL })
Worker：postMessage('init_progress', { stage: 'load_runtime', progressPercent: 30 })
Worker：pyodide.loadPackage(packages)
Worker：postMessage('init_progress', { stage: 'load_packages', packageName: 'numpy', ... })
Worker：mount NODEFS 到 /workspace
Worker：lockJsGlobals()  → 删除 fetch/XHR/etc
Worker：postMessage('init_done')
iframe：通知主站 'iframe.session_state', { state: 'ready' }
```

**python_exec_inline**：

```
iframe：postMessage('exec_inline', { execId, code, timeoutMs: 60000 })
Worker：创建独立 globals dict，重定向 stdout/stderr 到 buffer
Worker：runPythonAsync(code, { globals: scratchGlobals })
        ↓ 期间多次：postMessage('stdout', { execId, stream: 'stdout', text: chunk })
Worker：postMessage('exec_done', { execId, status: 'ok', elapsedMs })
iframe 同时启动 timer：60s 触发 SIGINT、90s 触发 worker.terminate()
```

#### 2.2.3 中断的两段式

由于 COI 已启用，SAB 可用：

```
iframe：发 'interrupt' 消息（仅作"已通知 Worker"标记）
iframe：Atomics.store(interruptBuffer, 0, 2)  // 真正的 SIGINT 信号
Worker：Pyodide 在下一个字节码 tick 抛 KeyboardInterrupt
Worker：返回 'exec_done', { status: 'interrupted' }
```

90s 兜底：

```
iframe：worker.terminate()
iframe：通知主站 'iframe.session_state', { state: 'failed', detail: 'kernel_killed' }
iframe：自动 new Worker(...) 并重新初始化（约 30s）
iframe：在 Pi Agent 上下文里追加 system message：
        "Python 环境已重启。如果之前定义过变量或导入过模块，需要重新执行。
        Workspace 文件保留。"
```

### 2.3 主站 / iframe ↔ 服务端

走统一 axios（`src/services/httpClient.ts`），不允许业务模块直接 fetch（项目硬约束）。

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/notebook-agent/sessions` | POST | 创建 Pi SDK session，绑定 sessionId |
| `/api/notebook-agent/sessions/:id/events` | GET | 订阅 Agent 事件流（ndjson）。仅订阅不会触发 bootstrap |
| `/api/notebook-agent/sessions/:id/ready` | POST | 前端确认 `inputs/upstream.csv` 已导入完成；与 events 订阅同时成立后才触发首轮 bootstrap（幂等） |
| `/api/notebook-agent/sessions/:id/messages` | POST | 发送用户消息（SSE 响应流 Agent 事件）|
| `/api/notebook-agent/sessions/:id/tool-result` | POST | 前端工具执行完成后回传结果 |
| `/api/notebook-agent/sessions/:id` | DELETE | 主动结束 session |

> **bootstrap 触发条件**：服务端 `tryStartNotebookBootstrap()` 仅当 `streamSubscribed`（已 GET `/events`）且 `dataReady`（已 POST `/ready`）同时成立才执行首轮 prompt，且 `bootstrapStarted` 保证只触发一次。这一约束修复了「events 订阅即触发 bootstrap，导致 agent 首轮 `fs_list inputs/` 时 CSV 尚未写入」的竞态。详见 [数据接入 §2](数据接入.md#2-启动流程) 与 `e2e/notebook-bootstrap-race.spec.mjs`。

工具执行的返回流：

```
Agent 决定调用 python_exec_inline
↓
后端 Pi SDK 触发 tool.execute 事件 → SSE 推到 iframe
↓
iframe 收到事件 → postMessage 给 Worker → Worker 执行
↓
Worker 完成 → iframe 收到 exec_done
↓
iframe POST tool-result → 后端继续推理
↓
Agent 输出文字 / 调下一个工具
```

## 3. OPFS 布局

OPFS 由浏览器同源隔离，主站和 iframe 同源时**共享同一个 OPFS**。我们约定**职责而非物理隔离**：

- **iframe 侧**：所有写操作（fs_write、Worker NODEFS 落盘）
- **主站侧**：只读（文件树展示、下载、预览）
- 两侧共用同一个 SDK（`src/notebook/shared/opfsAccess.ts`），读写 API 上层强制约束

### 3.1 目录结构

```
opfs:/notebook/
  └── {sessionId}/
      ├── inputs/                       # 启动时灌入的画布数据 / 数据源
      │   └── upstream.csv              # 默认文件名
      ├── scripts/                      # Agent 通过 fs_write 创建的 .py 脚本
      │   ├── 01_explore.py
      │   └── 02_corr.py
      ├── artifacts/                    # 执行产物
      │   ├── fig_dist.png              # plt.savefig 落盘
      │   ├── corr_matrix.csv
      │   └── chart_topk.echarts.json   # ECharts spec（M2）
      └── reports/
          └── main.md                   # 唯一报告文件
```

### 3.2 路径校验规则

任何 fs_* 工具接受的路径必须经过 `resolveSafePath`：

```typescript
// src/notebook/shared/opfsAccess.ts
const resolveSafePath = (sessionId: string, relPath: string): string[] => {
  // 拒绝绝对路径
  if (relPath.startsWith('/') || /^[a-zA-Z]:/.test(relPath)) {
    throw new Error('禁止绝对路径')
  }
  // 拒绝 .. 越界
  const segments = relPath.split(/[/\\]/).filter(Boolean)
  const stack: string[] = []
  for (const seg of segments) {
    if (seg === '.') continue
    if (seg === '..') throw new Error('禁止 .. 越界')
    stack.push(seg)
  }
  // 必须落到 inputs/scripts/artifacts/reports 之一
  const top = stack[0]
  if (!['inputs', 'scripts', 'artifacts', 'reports'].includes(top)) {
    throw new Error(`路径必须以 inputs/scripts/artifacts/reports 之一开头，得到 "${top}"`)
  }
  return ['notebook', sessionId, ...stack]
}
```

### 3.3 配额

- 单 session 配额：500MB（业务层限制）
- 浏览器全局配额：~60% × 磁盘剩余空间（不在我们控制下）
- 检查时机：每次 `fs_write` 前主动调 `navigator.storage.estimate()`，并维护 session 内已写字节数累计
- 超限处理：拒绝写入，向 Agent 返回 `quota_exceeded` 错误，提示 Agent 清理或减小写入量

### 3.4 Worker 与 OPFS 的连接

Pyodide 通过 NODEFS 挂载 OPFS 的子目录：

```python
# Worker 内启动 Pyodide 后立即执行
import os
# Pyodide 通过 emscripten 提供的 NODEFS-like API（实际是 IDBFS 或 OPFS adapter）
# 具体挂载在 Worker 侧 JS 完成：
# pyodide.FS.mkdirTree('/workspace')
# pyodide.FS.mount(pyodide.FS.filesystems.IDBFS, { ... }, '/workspace')
# 实施时按 Pyodide 0.27+ 实际可用的 FS 后端选择
```

> 实施细节：Pyodide 在浏览器中 OPFS 直挂的支持仍在演进。M1 PoC 时验证两条路径：
>
> 1. 直接 NODEFS-like 挂载到 OPFS（Pyodide 0.27+ 若已稳定支持）
> 2. 退化方案：MEMFS 内运行，定期由 iframe 侧主动 sync 到 OPFS（Worker 在每次 fs_write/savefig 后用 postMessage 把字节数据传给 iframe，iframe 写 OPFS）
>
> 选用哪条路径在 PoC 阶段确定，并回填本文档。

### 3.5 文件树同步

主站文件树通过 **2s 轮询 OPFS 列目录** 刷新（决策 Q31）：

- 主站 `useWorkspaceWatcher` composable 用 `setInterval(2000)` 调 OPFS list
- 与上次 list 对比 → diff → 局部更新 Vue 响应式状态
- iframe 在确知有变更时（fs_write 完成后）也可发 `iframe.workspace_changed` 事件触发即时刷新（不依赖此事件，仅作低延迟优化）

## 4. Session 生命周期

### 4.1 创建流程

```
1. 用户点 "新建分析笔记本"
2. 主站弹 dialog：选数据来源（画布节点 / 数据源）
3. 用户确认 → 生成 notebookSessionId（uuid v4）
4. 主站调 POST /api/notebook-agent/sessions { initialDataMeta }
   ← 后端创建 Pi SDK session（与 notebookSessionId 1:1 绑定）
5. 主站把 iframe 挂到全屏容器，src="/notebook.html?session={notebookSessionId}"
6. iframe 加载完毕 → handshake
7. 主站把所选数据源转 CSV → import_csv → iframe 写 OPFS（inputs/upstream.csv）
8. iframe 启动 Pyodide Worker（懒加载，首次 ~90s）
9. 主站建立 GET /events 事件流订阅（仅注册 listener，不触发 bootstrap）
10. import_csv 成功后，主站显式 POST /ready（失败则置 failed 态、不发 ready）
11. 服务端 streamSubscribed && dataReady 同时成立 → 触发首轮 bootstrap prompt
12. 用户开始与 Agent 对话
```

> 步骤 9 与 10 的相对顺序不固定，但两者**都必须成立**才触发 bootstrap——这是竞态修复的核心。即使 events 订阅早于 import 完成，agent 首轮动作也不会早于数据写入。

### 4.2 进行中

- 用户消息走 `POST /messages`（SSE 响应）
- Agent 工具调用 → SSE 推 `tool.execute` 事件 → iframe 路由到对应执行器（Worker / 主站 RPC / OPFS 操作）
- Agent 边执行边 fs_write，文件树轮询自动刷新
- Worker 崩溃 → iframe 自动重启 + 在 Pi Agent 上下文里追加 system message

### 4.3 关闭

- 用户点关闭：主站发 `parent.close_request`，iframe 检查 `hasUnsavedExec`
- 有正在跑的 exec → 主站弹确认 → 用户确认 → iframe 中断当前 exec → 销毁 Worker → iframe 卸载
- 主站不调 DELETE 后端（Pi SDK session 保留，下次 "继续上次的笔记本" 入口能恢复）
- M1 不实现 "恢复上次"；OPFS 文件保留但 UI 上没有列表入口

### 4.4 重新进入

M1 不做。M2 增加"最近的笔记本"列表（按 OPFS sessionId 列举）。

## 5. 失败模式与降级

| 失败 | 检测 | 降级 |
|------|------|------|
| Pyodide 加载失败（网络/资源损坏）| init_failed 事件 | iframe 显示错误 + 重试按钮；主站监听到失败可弹 toast |
| Worker 崩溃（OOM / 硬超时 terminate）| Worker exit / no-response timeout | iframe 自动 new Worker 重新初始化（30s 内）+ 在 Agent 上下文追加 system message |
| OPFS 配额耗尽 | fs_write 前 estimate 检查 | 抛 quota_exceeded → 工具调用返回错误 → Agent 收到错误后决策（清理 / 询问用户）|
| 主站 ↔ iframe 通信丢失 | iframe ready 信号 60s 未收到 | 主站显示"笔记本初始化失败"，提供"重新加载"按钮（重建 iframe）|
| 服务端 SSE 中断 | EventSource onerror | 主站显示连接断开 + 重连按钮 |
| 网络断开 | 浏览器原生检测 | iframe 内 Pyodide 已加载的话仍能继续执行；只影响 Agent 推理（无法发后端） |

## 6. 与 Pi Agent 主链的边界

Notebook Agent 与 [Pi Agent 主链](../Agent系统.md#3-pi-agent-主链) **平级、零耦合**：

| 维度 | Pi Agent 主链 | Notebook Agent |
|------|--------------|----------------|
| 入口 | `/api/pi-agent/*` | `/api/notebook-agent/*` |
| 工具集 | 画布工具（workflow_*）| Notebook 工具（python_exec_*, fs_*）|
| 前端执行端 | WorkflowApi（画布操作） | iframe 内 Worker / 主站 OPFS |
| Session 存储 | piAgent/sessionStore | notebookAgent/sessionStore |
| 复用 | runtimeFactory, modelAdapter, eventBridge, safePayload | 同左 |

**禁止**：

- 在 Pi Agent 主链注入 Notebook 工具
- 在 Notebook Agent 注入画布工具
- 共用同一个 frontendBridge 实例
- 共用同一个 sessionId 命名空间
