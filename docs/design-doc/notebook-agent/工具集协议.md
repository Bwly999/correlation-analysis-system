# 工具集协议

本文档定义 Notebook Agent 全部工具的 spec、参数、返回格式、错误约定与 prompt guidelines。

---

## 1. 工具集总览

### 1.1 M1 工具清单

| 工具 | 类别 | 执行端 | M1 必需 |
|------|------|--------|---------|
| `python_exec_inline` | 代码执行 | iframe Worker | ✅ |
| `python_exec_file` | 代码执行 | iframe Worker | ✅ |
| `fs_read` | 文件 | iframe 主线程 | ✅ |
| `fs_write` | 文件 | iframe 主线程 | ✅ |
| `fs_edit` | 文件 | iframe 主线程 | ✅ |
| `fs_list` | 文件 | iframe 主线程 | ✅ |
| `fs_grep` | 文件 | iframe 主线程 | ✅ |
| `todo_write` | 协作 | iframe 主线程 | ✅ |
| `ask_user` | 协作 | iframe 主线程（UI 卡片）| ✅ |

### 1.2 不在 M1 中的工具（M2/M3 候选）

| 工具 | 留待版本 | 原因 |
|------|---------|------|
| `python_kernel_reset` | M2 | M1 用户手动按"重启 Python 环境"按钮即可 |
| `python_install` | M2 | 默认包列表覆盖 M1 场景；放开 micropip 后再启用 |
| `chart_save_echarts` | M2 | M1 走 matplotlib savefig，足够 |
| `fs_glob` | M2 | OPFS 文件少，fs_grep 已足够 |
| `fs_delete` | M2 | M1 不让 Agent 删文件，避免误删 |
| `data_import_from_node` | M2 | M1 启动时一次性灌入，Agent 用 fs_read 读 inputs/ |
| `call_legacy_analysis` | M3 | XGBoost 等 wasm 跑不动的算法回退既有 :8000 |

### 1.3 与 Pi Agent 主链工具集的关系

**严格分离**。Notebook session 中 Agent 看不到画布工具（workflow_*），画布 session 中 Agent 看不到 Notebook 工具。

实现：

- `src/shared/notebookAgentTools.ts` 与 `src/shared/piWorkflowTools.ts` 平级独立
- 两套 spec 不通过 `getPiWorkflowToolSpecsByTarget()` 之类的统一入口枚举
- 后端 gateway 各自构建工具列表

## 2. 通用约定

### 2.1 输入参数

所有工具的参数 schema 用 Typebox 定义，与既有 piWorkflowTools 保持一致。

### 2.2 输出格式

所有工具返回 Pi SDK 的标准 ToolResult：

```typescript
interface ToolResult {
  content: Array<{ type: 'text'; text: string }>  // Pi SDK 协议要求
  details: Record<string, unknown>                  // 业务数据，前后端共享
  isError?: boolean
}
```

`content[0].text` 是 `JSON.stringify(details, null, 2)` 的结果，Agent 实际看到的是 JSON 字符串。

### 2.3 错误码

工具执行失败时，`details.error` 必须填以下结构：

```typescript
interface ToolError {
  code: string         // 错误码（见下表）
  message: string      // 中文用户可读消息
  detail?: unknown     // 可选附加信息
}
```

| code | 含义 | 触发场景 |
|------|------|---------|
| `path_out_of_workspace` | 路径越界 | 路径含 `..` 或不以 inputs/scripts/artifacts/reports 开头 |
| `file_not_found` | 文件不存在 | fs_read 找不到 |
| `quota_exceeded` | 配额超限 | session 累计写入超 500MB |
| `kernel_not_ready` | Worker 未就绪 | Pyodide 还在初始化 |
| `kernel_crashed` | Worker 崩溃 | exec 中途 Worker 异常退出 |
| `exec_interrupted` | 软中断 | SIGINT 触发 KeyboardInterrupt |
| `exec_timeout` | 硬超时 | 超过 90s 被 terminate |
| `python_exception` | Python 抛异常 | 未捕获的异常 |
| `invalid_arguments` | 参数非法 | schema 校验失败 |
| `string_not_found` | edit 字符串未找到 | fs_edit 的 oldStr 不在文件中 |
| `string_not_unique` | edit 字符串非唯一 | fs_edit 的 oldStr 出现多次 |
| `binary_file_not_supported` | 二进制文件不支持 | fs_read / fs_edit 操作 .png 等 |

## 3. 代码执行工具

### 3.1 python_exec_inline

**作用**：执行一段 Python 代码，等价于 `python -c "..."`。

**参数**：

```typescript
{
  code: string             // Python 代码（必填，1-50000 字符）
  timeoutMs?: number       // 超时（可选，默认 60000，最大 300000）
}
```

**返回 details**：

```typescript
{
  execId: string
  status: 'ok' | 'error' | 'interrupted' | 'timeout'
  stdout: string           // 完整 stdout
  stderr: string           // 完整 stderr
  elapsedMs: number
  error?: ToolError
}
```

**实现要点**：

- 每次调用创建新的 globals dict（[执行模型 §1.2](执行模型.md#12-实现规则)）
- stdout / stderr 流式推到 iframe（[执行模型 §2.2](执行模型.md#22-流式推送)）
- 同时返回完整文本给 Agent

**Prompt guidelines**（注入 system prompt）：

```
- 执行代码时调 python_exec_inline；这是无状态的，每次都要重新 import 和读数据
- 想让数据跨步骤复用，把中间结果落盘到 artifacts/，下一步重新读
- 想看大表的结构，写代码 print(df.describe()) print(df.dtypes) 而不是 fs_read 整表
- 出图必须 plt.savefig('artifacts/<语义化名称>.png', dpi=120, bbox_inches='tight')，
  并紧接着 plt.close() 释放内存
- 同样需要 import pandas as pd / matplotlib.pyplot as plt 等，每次都要写
```

### 3.2 python_exec_file

**作用**：执行 workspace 里某 .py 脚本，等价于 `python myscript.py`。

**参数**：

```typescript
{
  path: string             // 相对 workspace 的 .py 路径（必填）
  timeoutMs?: number
}
```

**返回 details**：同 `python_exec_inline`。

**实现要点**：

- 路径必须经 `resolveSafePath` 校验（仅 scripts/ 下）
- iframe 主线程从 OPFS 读取文件 → postMessage 把代码送进 Worker → 后续逻辑同 inline
- 与 inline 共享同一 import 缓存，但变量面隔离

**Prompt guidelines**：

```
- 当某段代码 (1) 较长 (2) 后续可能复用 (3) 用户可能想下载查看时，先 fs_write 到 scripts/，
  再用 python_exec_file 跑
- 临时探索性代码用 python_exec_inline，不要污染 scripts/
```

## 4. 文件工具

所有 fs_* 工具的路径**必须**经 `resolveSafePath` 校验：

- 拒绝绝对路径（`/...`、`C:\...`）
- 拒绝 `..` 越界
- 必须以 `inputs/`、`scripts/`、`artifacts/`、`reports/` 之一开头

### 4.1 fs_read

**作用**：读 workspace 文件。**对数据文件强制小截断，防止 LLM 上下文爆炸**。

**参数**：

```typescript
{
  path: string
  offset?: number          // 起始行（默认 0）
  limit?: number           // 行数上限（不传时按下面规则自动决定）
}
```

**返回 details**：

```typescript
{
  path: string
  content: string          // 实际内容（已按 limit 截断）
  totalLines: number       // 文件总行数
  truncated: boolean       // 是否被截断
  encoding: 'text'         // M1 仅支持文本；二进制返回 binary_file_not_supported
}
```

**截断规则**：

| 文件扩展名 | 默认 limit | 单行最大字符 |
|-----------|-----------|-------------|
| `.csv .tsv .parquet .arrow .feather .json .jsonl` | **10 行** | 不截断单行 |
| `.md .py .txt .js .ts .yml .yaml .toml` | **300 行** | 2000 字符 |
| 其他 | 300 行 | 2000 字符 |

> 设计意图（决策 Q24）：数据文件强制小截断，倒逼 Agent 写 Python 代码做切片/统计，而不是 dump 全表到 LLM context。这跟 Claude Code 的 Read 工具行为一致但更严格。

**单行字符上限**：被截断的行末尾追加 `... [truncated, +N chars]`。

**二进制文件**（.png / .jpg / .parquet / .arrow / 等）：

- M1 拒绝读 .png / .jpg 等图像（让 Agent 用 ls 看到文件名即可，图通过文件树预览给用户看）
- M1 允许读 .parquet / .arrow 但走 10 行截断（实际按行不太合适；M1 PoC 阶段验证：要么按 byte head 100 字节后 hex 展示要么直接拒绝；推荐**直接拒绝并提示用 pyarrow.parquet.read_table().head(10)**）

**Prompt guidelines**：

```
- 读文本文件（.md .py）默认拿前 300 行
- 读数据文件（.csv .parquet）默认只拿 10 行；要看更多用 python_exec_inline 写代码
- 想看 csv 的具体列、统计、缺失：写 python_exec_inline 跑 pd.read_csv(...).describe() / dtypes / isna().sum()
- 不要试图通过 offset/limit 翻完整张表 —— 用 Python 处理
```

### 4.2 fs_write

**作用**：写文件，整体覆盖。

**参数**：

```typescript
{
  path: string
  content: string          // M1 仅支持文本；写图必须用 plt.savefig 经 Worker 落盘
}
```

**返回 details**：

```typescript
{
  path: string
  bytes: number
}
```

**实现要点**：

- 写前调 `navigator.storage.estimate()` + 累计已写字节判断配额（500MB / session）
- 父目录不存在则自动创建
- 写完后 iframe 触发 `iframe.workspace_changed` 主动通知主站（决策 Q31 文件树 2s 轮询是兜底）

**Prompt guidelines**：

```
- 创建新脚本时 fs_write scripts/<语义化文件名>.py；其内容是完整脚本（独立运行）
- 中间产物落到 artifacts/；不要写在 inputs/（inputs 仅用于启动时的初始数据）
- 报告写到 reports/main.md；引用图表用相对路径 ../artifacts/xxx.png
- 不要 fs_write 二进制（用 python_exec_inline 里 plt.savefig 落盘）
```

### 4.3 fs_edit

**作用**：精确字符串替换式编辑文件，跟 Claude Code 的 Edit 一致。

**参数**：

```typescript
{
  path: string
  oldStr: string           // 要替换的字符串（必须在文件中且唯一）
  newStr: string
  replaceAll?: boolean     // 默认 false；为 true 时不要求唯一
}
```

**返回 details**：

```typescript
{
  path: string
  replacements: number     // 实际替换次数
}
```

**实现要点**：

- 读文件 → 计 `oldStr` 出现次数：
  - 0 次 → `string_not_found`
  - >1 次 且 `replaceAll === false` → `string_not_unique`
  - 否则替换 → 写回
- 写后路径校验同 fs_write
- 不允许跨文件 / 不允许引入新文件（要新文件用 fs_write）

**Prompt guidelines**：

```
- 修改已存在的脚本或报告用 fs_edit；它要求 oldStr 在文件中唯一存在
- 如果 oldStr 不唯一，扩大上下文（多带几行）让其唯一；不要直接用 replaceAll
- 只有"批量改同名变量"等明确需要 replaceAll 的场景才传 replaceAll=true
```

### 4.4 fs_list

**作用**：列目录。

**参数**：

```typescript
{
  path?: string            // 默认根目录
  recursive?: boolean      // 默认 false
}
```

**返回 details**：

```typescript
{
  path: string
  entries: Array<{
    name: string
    kind: 'file' | 'directory'
    size?: number          // 字节，仅 file
    modifiedAt?: string    // ISO 8601，仅 file
  }>
}
```

### 4.5 fs_grep

**作用**：在 workspace 内做 ripgrep 风格的全文搜索。

**参数**：

```typescript
{
  pattern: string          // 正则
  path?: string            // 默认整个 workspace
  fileGlob?: string        // 类似 "scripts/*.py"
  caseInsensitive?: boolean
  contextLines?: number    // 默认 0
  maxMatches?: number      // 默认 50；上限 200
}
```

**返回 details**：

```typescript
{
  pattern: string
  matches: Array<{
    path: string
    lineNumber: number
    line: string
    contextBefore?: string[]
    contextAfter?: string[]
  }>
  truncated: boolean
}
```

**实现要点**：

- 纯 JS 实现（不引入 ripgrep wasm）
- 仅扫描文本文件（.md .py .txt .csv 头部 1KB 内）；二进制文件跳过
- 单文件超过 1MB 时仅扫描前 100KB

## 5. 协作工具

### 5.1 todo_write

**作用**：维护任务清单。Agent 用此工具向用户展示自己的工作计划与进度。

**参数**：

```typescript
{
  items: Array<{
    title: string
    status: 'pending' | 'in_progress' | 'completed'
  }>
}
```

**调用语义**：**全量覆盖**——每次调用 `items` 是完整列表，前端清空旧列表后渲染新列表。

**返回 details**：

```typescript
{
  total: number
  inProgress: number
  completed: number
}
```

**约束**：

- `in_progress` 同一时刻最多 1 个（Agent 自我约束，工具不强制）
- title 长度 1-100 字符

**Prompt guidelines**（写进 system prompt）：

```
- 进入分析前先用 todo_write 写下计划（5-10 条任务）
- 每完成一个任务用 todo_write 把它从 in_progress 改 completed，并把下一个改成 in_progress
- 任务粒度："清洗数据"、"画相关性热力图"、"写流失因子小节"
  不要写成"调 fs_read"这种工具级粒度
- 整个分析过程同一时间只有一个 in_progress
```

### 5.2 ask_user

**作用**：暂停 Agent 的工作，向用户提问，等用户回答后继续。

**参数**：

```typescript
{
  question: string         // 问题文本（中文，1-300 字符）
  header: string           // 短标签（≤ 12 字符），UI 显示为 chip
  options?: Array<{
    label: string          // 选项文字（1-30 字符）
    description?: string   // 解释（≤ 80 字符）
  }>                       // 不传则纯开放式问答
  multiSelect?: boolean    // 默认 false；options 存在时才有效
  recommendedIndex?: number // 推荐项索引（UI 高亮）
}
```

**返回 details**（用户回答完成后）：

```typescript
{
  answers: Array<{
    label: string          // 用户选中的标签；自由文本时是用户输入
    isCustom: boolean      // 是否是 "其他" 选项的自定义文本
  }>
}
```

**实现**：

- iframe 收到 tool.execute → 在消息流中渲染**专用卡片**（参考 [UX 与交互 §5.2](UX与交互.md#52-ask_user-卡片)）
- 用户选完点确认 → tool-result 回送
- 用户不回答时卡片永远等待（M1 不做超时）；用户关闭笔记本时取消

**Prompt guidelines**：

```
- 进入新分析时，第一件事是用 ask_user 跟用户对齐目标
  - 用户的核心问题是什么？
  - 哪些维度优先？要哪类产物（结论 / 报告 / 图表）？
  - 数据有哪些已知特点要注意？
- 单次问 1 个问题；问题用 options 让用户快速选；自由问题留空 options
- 当代码报错且原因不明时，用 ask_user 描述现象，让用户判断
- 不要在每个细节都打断用户；只在关键决策点（这是 grill-me 的核心精神）

刨根问底访谈风格（写入 system prompt 提示词）：
{以下来自 grill-me skill}
Interview me relentlessly about every aspect of this plan until we reach a shared understanding.
Walk down each branch of the design tree, resolving dependencies between decisions one-by-one.
For each question, provide your recommended answer.
Ask the questions one at a time.
If a question can be answered by exploring the codebase, explore the codebase instead.
```

## 6. 工具执行端路由

每个工具调用进入 iframe 后，按下表路由到对应执行器：

| 工具 | 执行器 | 路径 |
|------|--------|------|
| python_exec_inline / python_exec_file | Worker | iframe → postMessage → Worker |
| fs_* | iframe 主线程 | iframe → opfsAccess.ts |
| todo_write | iframe 主线程 → Pinia store | iframe → notebookAgentStore |
| ask_user | iframe 主线程 → UI 状态 → 等用户输入 | iframe → askUserQueue |

iframe 内有一个 `toolDispatcher`：

```typescript
// src/notebook/runtime/toolDispatcher.ts
export const dispatchTool = async (
  name: string,
  params: unknown,
  toolCallId: string,
): Promise<ToolResult> => {
  switch (name) {
    case 'python_exec_inline':
    case 'python_exec_file':
      return runViaWorker(name, params, toolCallId)
    case 'fs_read':
    case 'fs_write':
    case 'fs_edit':
    case 'fs_list':
    case 'fs_grep':
      return runFsTool(name, params)
    case 'todo_write':
      return runTodoWrite(params)
    case 'ask_user':
      return waitForUserAnswer(params, toolCallId)
    default:
      throw new Error(`未知工具：${name}`)
  }
}
```

## 7. System Prompt 摘要

完整 system prompt 在 `src/server/notebookAgent/systemPrompt.ts` 落地。本文档列出**关键骨架**，方便维护时对齐。

```
你是一名资深数据分析师，工作在一个独立的 Python 笔记本工作区。

## 工作循环
1. 进入会话先用 ask_user 跟用户对齐目标（grill-me 风格的刨根问底）
2. 用 todo_write 写下分析计划（5-10 条任务）
3. 用 fs_list 看 inputs/ 里有什么数据；用 python_exec_inline 跑 describe 形成第一印象
4. 按计划执行，每完成一个任务更新 todo
5. 关键发现追加到 reports/main.md（用 fs_write / fs_edit）
6. 不确定的地方用 ask_user 问，不要硬编

## 执行规则
- python_exec_inline / python_exec_file 是无状态的：每次都要重新 import + 读数据
- 中间结果落到 artifacts/，下一步重新读
- 出图：plt.savefig('artifacts/<语义化名称>.png', dpi=120, bbox_inches='tight'); plt.close()
- fs_read 数据文件只看头 10 行；要更多信息写 Python 代码
- fs_edit 需要 oldStr 在文件中唯一；不唯一就扩大上下文带几行

## 强约束
- 你只能在本工作区操作；没有画布工具
- 报告引用图必须用 ../artifacts/xxx.png 相对路径
- 涉及统计推断必须给 p 值/置信区间
- 不要 monkey-patch 标准库
- 用中文输出

## 可用包
numpy, pandas, scipy, scikit-learn, matplotlib, seaborn, statsmodels（默认全部已 import 可用）

## 刨根问底风格（grill-me）
{完整的 grill-me prompt}
```

## 8. 工具变更与版本兼容

工具 spec 变更时遵循 [index.md §6.2 新增 Notebook 工具的步骤](index.md#62-新增-notebook-工具的步骤)。

向后不兼容变更（删字段、改语义）必须：

1. 加测试覆盖前后端 spec 一致性
2. 同步更新本文档
3. 在 `src/shared/notebookAgentTools.ts` 留至少一个 minor 版本的兼容 shim 或显式 break version

工具新增是向后兼容的；前端 iframe 收到未知工具名时返回 `unknown_tool` 错误（统一行为）。
