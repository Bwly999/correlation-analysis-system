# 节点定义与属性

本文档描述 `NodeDefinition` 接口和 `NodeProperty` 设计规则。

> 前置阅读：[节点清单](节点清单.md) — 了解现有节点
> 系统级节点定义协议（`category`、`inputMode` 等）见 `../workflow-system/节点定义协议.md`

## NodeDefinition 接口

定义位置：`src/nodes/types.ts`

```ts
export interface NodeDefinition<TInput = any, TConfig = Record<string, any>, TOutput = any> {
  name: string
  displayName: string
  icon: string
  category: 'trigger' | 'action' | 'terminal'
  description: string
  help?: NodeHelpDoc
  assistantHints?: NodeAssistantHints
  libraryGroup?: NodeLibraryGroupId
  libraryAliases?: string[]
  libraryKeywords?: string[]
  availability?: 'active' | 'legacy'
  isLegacy?: boolean
  properties: NodeProperty[]
  inputMode?: 'single' | 'multiple'
  minInputs?: number
  maxInputs?: number | null
  execute: (input: TInput, config: TConfig) => Promise<TOutput> | TOutput
}
```

### 关键字段约束

| 字段 | 约束 |
|------|------|
| `name` | 全局唯一 kebab-case，禁止随意改名 |
| `displayName` | 中文，面向最终用户 |
| `icon` | 使用已有 Lucide 图标，保证节点库可识别 |
| `category` | 与节点真实职责一致，禁止为连线方便错放类别 |
| `help` | 用户帮助的唯一数据源，至少补齐 `summary`、`whenToUse`、`inputGuide`、`outputGuide` |
| `assistantHints` | LLM 自动建节点/工作流的提示层，新增节点必须补齐最小集 |
| `libraryGroup` | 在 `helpCatalog.ts` 的 `nodeLibraryGroups` 中映射，定义文件不硬编码 |
| `libraryAliases` | 自动生成（displayName + name），`attachNodeHelp()` 中注入 |
| `libraryKeywords` | 自动从 help/assistantHints 提取，`attachNodeHelp()` 中注入 |
| `availability` | `active` 出现在节点库；`legacy` 仅历史兼容，不暴露到新建入口 |
| `properties` | 完整声明，不允许组件内硬编码补关键配置 |
| `execute()` | 必须返回可标准化到 `NodeResult` 的结果 |

### libraryGroup 映射表

`libraryGroup` 在 `helpCatalog.ts` 的 `nodeLibraryGroups` 中定义，节点定义中不直接赋值。

| libraryGroup | 分组名称 | 包含的节点 |
|-------------|---------|-----------|
| `import-data` | 导入数据 | `file-import`, `manual-json-import`, `neighbor-system` |
| `clean-filter` | 清洗与筛选 | `data-cleaning`†, `data-dedup`, `data-missing-outlier`, `data-encoding-scaling`, `data-filter` |
| `field-shaping` | 字段与结构处理 | `field-selection`, `sort`, `data-limit`, `js-transform` |
| `merge-aggregate` | 合并与聚合 | `data-aggregation`, `data-merge`, `data-profiling`† |
| `stat-analysis` | 统计分析 | `correlation-analysis`, `pearson`†, `spearman`†, `kendall`†, `anova`, `classification-factor-screening`, `vif`, `pca` |
| `model-analysis` | 模型分析 | `lasso`, `logistic-regression-classification`, `multiple-linear-regression`, `random-forest-feature-importance`, `xgboost-shap` |
| `result-output` | 结果展示与导出 | `chart-display`†, `data-export`† |

† = legacy 节点

## NodeProperty 设计规则

### 属性类型一览

| 类型 | 用途 |
|------|------|
| `string` | 文本输入 |
| `textarea` | 多行文本 |
| `number` | 数字输入 |
| `options` | 单选下拉 |
| `multi-options` | 多选下拉 |
| `boolean` | 开关 |
| `collection` | 复合结构 |
| `tree` | 树形选择 |
| `file` | 文件选择 |
| `datetime-range` | 日期时间范围 |
| `json` | JSON 编辑器 |
| `tags` | 标签输入 |
| `select-button` | 按钮式单选 |

### 设计规范

**文案**
- 所有用户可见标签、提示、占位符必须使用中文
- 文案要偏工具化、分析化，避免过度营销或口语化

**默认值**
- 优先通过 `default` 提供可运行的默认配置

**数字**
- `number` 默认按整数处理
- 只有比例、阈值、边界值等场景才声明 `numberMode: 'decimal'`
- 需要小数的按需补充 `step` 与 `maxFractionDigits`，统一交组件处理

**条件与动态**
- 用 `required` 明确关键必填项
- 用 `displayIf` 管理条件显示，不在 UI 组件里写特判
- 动态选项优先使用 `resolveOptions(context)` 或 `useUpstreamFactors`

**多选**
- `multi-options` 仅在候选为空时需要手动补值的场景启用 `forceInput`

**文本域**
- 超长 `textarea` 可通过 `textareaImport.kind = 'file-column'` 增加"从文件导入列并回填文本"能力（只改变录入体验，不改变执行协议）

**运行时输入**
- 需要运行前补录的字段才设置 `isRuntimeInput`，不要滥用

**复杂配置**
- 优先用 `collection` 组织，避免堆叠大量平铺字段
