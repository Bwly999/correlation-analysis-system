# 结果展示链路

本文档描述结果展示链路，包括 `DataDisplayPanel`、viewer 注册表、帮助体系、节点库体验和模板入口。

> 前置阅读：[结果协议](结果协议.md) — 了解 `NodeResult` 结构和 `preview` 配置

## DataDisplayPanel

`DataDisplayPanel.vue` 是统一的数据预览面板，负责：

- 标准化读取 `NodeResult`
- 表格、分组集合、报告、图表、文件的摘要预览
- 大数据量智能截断
- 编辑模式下手动输入编辑

### 预览截断策略

`DataAnalysisModal.vue` 与 `JsonViewer.vue` 的预览约束：

- 左侧预览不直接渲染完整大对象
- `table` / `tableCollection` 按行截断
- `report` / `json` 安全序列化后摘要预览（最大深度/数组项数/键数/字符串长度限制）
- "导出原始结果"始终导出完整数据
- 报告中的 JSON 结构自动转为 PrimeVue 表格展示

### DataChart

`DataChart.vue` 承担交互式图表预览：

| 数据形态 | 支持的图表类型 |
|----------|-------------|
| 单表 | 折线、散点、柱状、箱线图、正态分布 |
| 多组结果 | 箱线图、多组散点、多组柱状对比 |

首开图表优先级：
1. 本地用户设置
2. `preview.props.chartDefaults`
3. 内置启发式默认

`table-chart-combo-viewer` 额外提供"数据透视"模式。

### 结果看板

全局运行完成后自动打开 `WorkflowResultDashboardModal.vue`：

- 默认选中所有终止节点结果面板
- 若无终止节点则回退为本次执行目标中的末端结果节点
- 左侧可补选其他有结果节点，右侧多面板聚合展示
- 看板布局为会话级状态，不写入 `SavedWorkflow` 与 `ExecutionRecord`
- 标准网格：普通卡片 `360px`，图表型卡片 `420px`
- 支持浏览器全屏专注模式
- 所有 overlay 组件使用统一 `appendTo` 目标，全屏时挂载到全屏容器

### TableViewer

`TableViewer.vue` 已切换为 AG Grid Community 整表虚拟滚动预览：

- 快速搜索、排序、筛选、列拖动、列显隐/固定、批量列宽、密度切换
- 内置 CSV / Excel / JSON 导出
- 结果 viewer 功能设置按节点写入本地存储并自动恢复

### 其他入口

- 画布节点悬浮 toolbox 提供"结果预览"快捷入口

## Viewer 注册

异步 viewer 注册位于 `src/components/workflow/viewers/registry.ts`。

### Viewer 清单

| Viewer Key | 组件 | 用途 |
|-----------|------|------|
| `chart-viewer` | `ChartViewer.vue` | 历史 `chart` 结果展示 |
| `file-viewer` | `ExportViewer.vue` | 文件下载/PDF 生成 |
| `report-viewer` | `ReportViewer.vue` | 报告结果渲染，支持区块 help、图表交互控件 |
| `table-preview` | `TableViewer.vue` | AG Grid 整表预览 |
| `table-collection-preview` | `TableCollectionViewer.vue` | 分组表格集合 |
| `table-chart-combo-viewer` | `TableChartComboViewer.vue` | 图表/表格/分屏切换 |
| `json-viewer` | `JsonViewer.vue` | JSON 结构查看 |

### Viewer 约定

- 所有含 overlay 的 viewer 必须消费统一 workflow overlay host
- 结果看板中的 viewer 根节点必须遵循 `h-full + min-h-0 + overflow-hidden`
- 图表型 viewer 必须提供 `flex-1 + min-h-0` 高度链路给 VChart

这些 viewer 同时服务于：
- 节点配置弹窗中的结果详情查看
- 工作流结果看板中的多面板结果渲染

## 结果标准化入口

UI 读侧统一通过 `src/components/workflow/resultView.ts`：

| 函数 | 作用 |
|------|------|
| `normalizeWorkflowResult()` | 标准化工作流结果 |
| `getResultViewerKey()` | 获取对应 viewer key |
| `getResultRows()` | 获取表格行 |
| `getResultGroups()` | 获取分组集合 |
| `getResultReport()` | 获取报告内容 |
| `getResultChartOption()` | 获取 ECharts option |
| `getResultFileInfo()` | 获取文件信息 |
| `getResultSchemaFields()` | 获取字段 schema |
| `getResultPreviewChartDefaults()` | 获取首开图表默认值 |
| `getResultKindLabel()` | 获取结果类型中文标签 |
| `getResultPreviewSummary()` | 获取预览摘要文本 |

全局运行结束后，`workflowStore.runGlobal()` 写入 `lastRunDashboard`，UI 根据 `executionTargetIds` 和当前节点运行态构造结果看板摘要。

## 帮助体系

| 组件 | 说明 |
|------|------|
| `WorkflowHeader` | 提供全局"帮助"入口 |
| `HelpCenterModal` | 首页固定展示"3 分钟上手"；内置常见问题与节点分类索引 |
| `NodeHelpPanel` | 节点配置弹窗中的帮助面板，与帮助中心读取同一份 `NodeDefinition.help` |

关键规则：

- 节点分类索引的摘要复用 `NodeDefinition.help.summary`
- 帮助体系按固定模板组织：第 1 步导入数据 / 第 2 步数据准备 / 第 3 步分析输出

## 节点库体验

`NodeSidebar` 结构：

- **顶部类型筛选**：全部 / 数据接入 / 数据准备 / 分析输出
- **主列表**：按任务场景分组
- **搜索**：匹配 `displayName`、`help.summary`、`help.whenToUse`、`libraryAliases`、`libraryKeywords`；显示命中原因
- **快捷区**：最近使用 / 上下文推荐 / 当前可接入（连线态时）
- 上下文推荐优先读取 `assistantHints.recommendedNextNodes`

元数据以 `NodeDefinition` 为单一来源。

### 节点库分组

定义在 `src/nodes/libraryGroups.ts`：

| 分组 | 对应节点类别 |
|------|-------------|
| 导入数据 | trigger |
| 清洗与筛选 | action |
| 字段与结构处理 | action |
| 合并与聚合 | action |
| 统计分析 | terminal |
| 模型分析 | terminal |
| 结果展示与导出 | terminal |

## 工作流模板入口

### 入口位置

- `WorkflowHeader` 中的"模板"按钮
- `WorkflowManagerModal` 中的"分析模板"Tab
- "我的工作流"页顶部的"从模板创建"入口卡片

### 模板系统

- 元数据在 `src/workflow/templates.ts`
- 骨架 JSON 在 `src/workflow/template-configs/*.json`
- 模板创建逻辑统一由 `workflowStore.createWorkflowFromTemplate()` 承接

### 当前内置模板

1. **相关性排查模板** — Pearson 相关性分析
2. **关键因子筛选模板** — 随机森林特征重要性
3. **变量解释分析模板** — XGBoost SHAP
4. **看板数据对比分析模板** — 分组聚合对比

### 模板约定

- 模板 JSON 直接复用工作流导出格式：`{ name, nodes, edges }`
- 模板定位为"最小可运行骨架"
- 模板创建生成新的未保存工作流（`currentWorkflowId` 重置为 `null`）
- 重新生成节点 id 和连线 id，保留配置、位置和连线关系
- 数据入口默认使用 `manual-json-import`，提供最小样例数据
- 创建后完全处于普通编辑态
