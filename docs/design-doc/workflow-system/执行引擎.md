# 执行引擎

本文档描述工作流执行引擎的设计。执行引擎位于 `src/stores/workflowStore.ts`。

> 前置阅读：[连接规则](连接规则.md) — 了解全局运行目标选择规则

## 单节点执行

`executeNode()` 核心流程：

1. **定位节点**并补齐默认配置
2. **检查 Trigger** 是否缺少必填运行时输入
3. 若开启**手动模拟输入**，则优先消费 `manualInput`
4. **递归执行**上游节点
5. **组装输入协议**：单输入或多输入（详见[多输入协议](多输入协议.md)）
6. **调用执行**：普通节点调 `execute()`；`file-import` 走前端后台解析任务分支
7. **标准化结果**：对结果执行 `normalizeNodeResult()` 并写回节点输出

## 全局执行

`runGlobal()` 主要流程：

1. 选出 Terminal 节点；若无则退化为叶子节点（详见[连接规则](连接规则.md)）
2. 重置未冻结节点的运行态与缓存
3. 收集缺失运行时输入的 Trigger
4. 逐个执行目标节点
5. 运行结束后写入历史快照

## 运行时输入

对于必填但缺失的 Trigger 运行时参数：

- 系统记录 `pendingExecution`
- UI 通过 `RuntimeInputModal` 引导用户补录
- 支持多 Trigger 顺序补录与继续执行

### 运行时输入复用

节点级开关 `reuseLastRuntimeInputs`：

| 值 | 行为 |
|----|------|
| `false`（默认） | 不沿用上次启动参数。Trigger 成功执行后清空运行时参数，下次重新输入 |
| `true` | 保留确认过的运行时参数，后续直接沿用 |

### 运行时输入保存

节点级开关 `persistRuntimeInputs`：

| 值 | 行为 |
|----|------|
| `true`（默认） | 普通启动参数允许随工作流一起保存，并在重新加载后回填到节点配置 |
| `false` | 启动参数只在当前运行中使用；保存工作流、复制、版本快照时会自动剥离 |

### 补充约束

- `NodeConfigModal` 左侧"运行时输入"区域支持通过"应用"写回节点配置；是否进入持久化由 `persistRuntimeInputs` 控制
- 工作流保存、复制、导出、版本快照与脏检查签名都会遵循相同规则：当 `persistRuntimeInputs = false` 时剥离运行时输入
- `file` 类型的运行时输入始终不持久化，即使 `persistRuntimeInputs = true`
- `file-import` 补录完成后启动纯前端后台解析任务，通过独立任务态暴露阶段、进度、取消能力
- 后台解析阶段：读取文件 → 解析内容 → 清洗识别字段 → 整理结果
- 后台任务不进入 `SavedWorkflow`、版本快照和运行时输入持久化

## 手动模拟输入

节点支持调试模式：

- `useManualInput = true` + `manualInput`（JSON 字符串）
- 执行时直接作为节点输入，跳过上游依赖

## 单节点调试策略

两种调试策略：

| 策略 | 行为 |
|------|------|
| **调试节点** | 只重新执行当前节点，默认复用上游缓存输出 |
| **重跑上游后调试** | 沿当前链路重新执行上游节点，再执行当前节点 |

策略会写入日志。全局运行不受调试策略影响。

## 冻结输出

节点支持 `isPinned` 冻结输出：

| 场景 | 行为 |
|------|------|
| 冻结后执行 | 优先复用已有输出，不重新执行 |
| 工作流保存 | 保留被冻结节点的输出 |
| 非冻结节点保存 | 只保留结构，不保留运行态输出 |

## 停止机制

全局停止依赖 `isStopping`：

- 递归执行链主动检查中止标记
- 停止后清理 `pendingExecution`
- 若有 `file-import` 后台解析任务，触发取消并清理
