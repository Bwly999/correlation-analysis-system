# 节点体系

本文档描述工作流系统的节点分类体系。节点定义协议请见 [节点定义协议](节点定义协议.md)，连接规则请见 [连接规则](连接规则.md)。

## 节点分类

当前节点体系分为三类：

| 类别 | 角色 | 连接规则 | 示例 |
|------|------|---------|------|
| **Trigger** | 数据源/运行时入口 | Trigger → Action/Terminal | `file-import`, `manual-json-import`, `neighbor-system` |
| **Action** | 中间处理（变换/清洗/筛选/聚合/合并） | Action → Action/Terminal | `data-dedup`, `data-missing-outlier`, `data-filter`, `js-transform`, `field-selection`, `data-merge` |
| **Terminal** | 分析终点/结果输出 | 不可输出连线 | `pearson`, `spearman`, `xgboost-shap`, `lasso`, `multiple-linear-regression`, `anova`, `pca` |

### 类别详解

#### Trigger（触发器）

作为工作流的数据入口，提供原始数据或运行时输入。

- 必须位于工作流的最上游
- 支持运行时参数输入（如文件上传、JSON 手动录入）
- 示例：`file-import` 支持 CSV/Excel 文件导入，`manual-json-import` 支持手动输入 JSON 数据

#### Action（动作节点）

负责数据变换和处理，是工作流的中间环节。

- 可接收上游 Trigger 或 Action 的输出
- 输出传递给下游 Action 或 Terminal
- 典型操作：数据去重、缺失值处理、筛选过滤、字段选择、JS 转换、数据合并

#### Terminal（终点节点）

生成最终分析结果，是工作流的终点。

- 连接终点：只能接收上游输入，不能向下输出连线
- 系统全局运行时优先执行所有 Terminal 节点
- 示例：相关性分析（pearson/spearman）、特征重要性（xgboost-shap/lasso）、回归分析、PCA
