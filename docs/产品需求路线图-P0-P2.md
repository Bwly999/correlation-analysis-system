# 多因子相关性分析系统需求 Roadmap（P0 / P1 / P2）

本文档用于整理当前版本的产品需求方向，按 `P0 / P1 / P2` 分阶段归纳，便于后续逐项标记“需要 / 暂缓 / 删除 / 待细化”。

建议标记方式：

- `[ ]` 暂未确认
- `[x]` 确认需要
- `[-]` 暂缓
- `[?]` 需要继续细化

---

## 一、Roadmap 总目标

未来 3-6 个月，产品目标不是继续堆叠更多节点，而是把系统从“可拖拽的分析工作流编辑器”升级为：

`一个让用户更容易完成多因子分析、得到更可信结论、并能复用分析流程的分析工作台`

Roadmap 统一围绕以下 3 条主线推进：

1. `分析能力更丰富`
   - 从基础相关性分析扩展为支持筛选、比较、验证、解释、导出完整结论。

2. `分析结果更准确可信`
   - 不只输出数值或图表，还要让用户知道结果是否可靠、受哪些因素影响、能否支撑业务判断。

3. `分析过程更好用`
   - 让用户更顺畅地完成导数、选字段、跑分析、看结论、复用流程、排查问题。

---

## 二、P0：先把分析闭环做扎实（第 1-2 个月）

阶段目标：

让用户可以稳定完成一次可信的分析，降低“流程能跑但结果不敢信”的情况。

阶段说明：

- 当前系统已具备基础版 `data-profiling` 数据体检能力
- P0 不再单独扩展一轮完整的数据体检产品化能力
- P0 的重点改为基于现有数据体检基础，优先增强相关性分析结果的可信表达、风险提示和基础易用性

### 1. 分析前数据理解

- `[-]` 增强 `data-profiling` 节点，输出缺失率、异常值分布、字段类型识别、样本量提示
- `[-]` 增加常量字段、低方差字段、疑似无效字段提示
- `[-]` 增加目标字段候选推荐，帮助用户更快确定分析对象
- `[-]` 为数据体检结果补充更清晰的中文解释和风险说明

价值：

- 帮用户在分析前先理解数据质量
- 减少直接跑算法导致的误判

### 2. 字段选择更智能

- `[-]` 在字段选择节点中自动识别数值字段、类别字段、时间字段
- `[X]` 自动排除明显不可分析字段或给出强提示
- `[-]` 支持按字段类型筛选、搜索、分组选择
- `[-]` 在算法节点中提供推荐字段范围，减少用户误选

价值：

- 降低字段配置门槛
- 减少因字段选择错误导致的分析失败或结果失真

### 3. 相关性分析结果升级

- `[X]` Pearson / Spearman / Kendall 结果补充显著性检验信息
- `[X]` 补充样本量说明和结果稳定性提示
- `[X]` 增加相关性热力图、Top N 排名、字段切换对比
- `[X]` 增加结果解释文案，说明“为什么这个结果值得关注”

价值：

- 让相关性分析从“出结果”升级为“可读、可解释”

### 4. 结果可信提示机制

- `[X]` 对样本过少、缺失过多、异常值敏感等情况给出显式风险提示
- `[X]` 对字段高度共线、结果可能失真的情况给出提示
- `[X]` 在结果页中展示“本次分析有哪些前置风险”

价值：

- 降低用户误用结果的概率
- 提升系统输出的可信感

### 5. 单节点调试体验补齐

- `[X]` 明确区分“使用缓存调试”和“强制重跑上游”
- `[-]` 支持查看当前节点输入内容
- `[-]` 支持查看当前节点标准化输出内容
- `[X]` 优化报错信息，让用户能快速定位是参数问题、数据问题还是节点问题

价值：

- 提高分析过程中的可排查性
- 降低复杂流程调试成本

### 6. 流程基础可用性优化

- `[X]` 补齐常见空状态和中文引导文案
- `[X]` 增强节点参数校验和默认值策略
- `[X]` 优化节点配置弹窗的填写顺序和信息层次
- `[X]` 为新用户提供更明确的分析上手引导

价值：

- 降低首次使用门槛
- 提高用户完成一次分析的成功率

## 三、P1：把分析能力做厚（第 2-4 个月）

阶段目标：

让用户不只做基础相关性分析，而是开始支持筛选、比较、解释、验证等更完整的分析任务。

### 1. 新增核心分析节点

- `[X]` 多元线性回归
- `[-]` 逻辑回归
- `[X]` 随机森林特征重要性
- `[X]` 方差分析
- `[X]` PCA 主成分分析
- `[X]` VIF 共线性检测

价值：

- 扩展分析覆盖面
- 让系统从“单一分析类型”升级为“多种分析方法可选”

### 2. 分析前处理能力增强

- `[X]` 增加标准化 / 归一化能力
- `[?]` 增加分箱能力
- `[X]` 增加去重能力
- `[X]` 增加时间窗口聚合能力
- `[?]` 增加目标字段构造能力
- `[?]` 增加训练前样本筛选能力

价值：

- 提升算法输入质量
- 减少用户依赖外部工具预处理数据

当前决策：

- `分箱能力`、`目标字段构造能力`、`训练前样本筛选能力` 先保留为待细化项
- P1 先聚焦可直接服务现有分析节点的高确定性能力，不在当前版本强行展开

### 3. 分群与分层分析

- `[-]` 支持按某个维度分组后分别跑相关性分析
- `[-]` 支持按某个维度分组后分别跑回归分析
- `[-]` 支持整体结果与分群结果对比展示

价值：

- 支持更真实的业务分析场景
- 避免“整体不显著、分群后有价值”的信息被埋没

### 4. 分析结果对比

- `[-]` 支持两个分析节点结果并排对比
- `[-]` 支持不同时间段的结果对比
- `[-]` 支持不同样本范围的结果对比
- `[-]` 支持不同算法结果的差异对比

价值：

- 提高分析结论的判断效率
- 帮助用户更快看到变化和差异

### 5. 图表表达升级

- `[X]` 增加散点图矩阵
- `[X]` 增加箱线图
- `[X]` 增加分布图
- `[X]` 增加回归拟合图
- `[X]` 增加 SHAP 贡献度联动图

价值：

- 让结果更直观
- 提高复杂分析结果的可理解性

### 6. 导出能力升级

- `[-]` 导出分析摘要
- `[X]` 导出关键图表
- `[-]` 导出关键参数
- `[X]` 导出结果表格
- `[X]` 支持一键导出完整分析报告

价值：

- 让分析结果更容易进入汇报、评审、沉淀流程

## 四、P2：把产品做成可复用系统（第 4-6 个月）

阶段目标：

让用户不只是做一次性分析，而是持续复用流程、沉淀方法、追踪结果变化。

阶段说明：

- P2 的“复用”不以复杂参数化体系为前提
- 当前优先考虑通过 `配置导入 / 导出`、模板预置、结果快照分享来支撑复用
- 因此，工作流参数化、跨场景复用、历史追踪等重能力暂不进入当前周期

### 1. 分析模板体系

- `[X]` 内置相关性排查模板
- `[X]` 内置关键因子筛选模板
- `[X]` 内置变量解释分析模板
- `[-]` 内置建模前数据体检模板
- `[X]` 内置看板数据对比分析模板

价值：

- 降低搭建流程门槛
- 提高分析流程复用率

### 2. 结果摘要与结论生成

- `[X]` 自动生成中文分析摘要
- `[X]` 自动归纳最相关因子和主要风险点
- `[X]` 自动给出下一步分析建议

价值：

- 降低用户理解成本
- 让结果更容易被业务使用

### 3. 工作流复用与参数化

## 五、当前最终方向总结

本轮筛选后的最终 roadmap，核心方向如下：

1. `P0`
   - 先把相关性分析结果做得更可信、更易理解、更容易上手
   - 重点不是扩更多前置节点，而是提升现有分析链路的结果质量和交互质量

2. `P1`
   - 补齐更有价值的分析方法与关键前处理能力
   - 重点扩的是“分析深度”，不是泛化堆功能

3. `P2`
   - 通过模板、自动摘要、结果快照分享、配置导入导出，开始形成可复用的分析工作方式
   - 暂不引入更重的参数化平台能力和复杂协作体系

这一版的产品节奏更偏向：

`先把单次分析体验做扎实，再把分析方法做厚，最后做轻量复用`

---

## 六、Roadmap 使用建议

后续可以按以下方式继续推进：

1. 先由产品侧在本文档中标记每项需求是否保留
2. 再把保留项拆成版本计划或里程碑
3. 最后映射到具体节点、viewer、交互、协议和测试任务

建议特别警惕以下风险：

- 节点越来越多，但用户不知道先用哪个
- 算法越来越多，但结果仍然不够可信
- 图表越来越多，但结论不够可行动
- 工作流越来越复杂，但复用率始终偏低

因此，后续所有需求判断都建议回到一个标准：

`是否能围绕一个真实分析任务，把前处理、分析、解释、导出、复用做成闭环`
