# 多因子相关性分析系统开发任务清单（P0 / P1 / P2）

本文档基于已确认的 roadmap 继续拆分，目标是把产品方向转成可落地的开发任务清单。

使用原则：

- 本文档优先面向研发拆解，不追求完整 PRD 话术
- 每项任务尽量映射到当前仓库已有模块
- 若后续需求变化，应以本文档为中间层，再继续拆到 issue / milestone / PR

---

## 一、拆分原则

任务按 4 类组织：

1. `节点能力`
   - 新增节点
   - 现有节点能力增强

2. `结果展示与 viewer`
   - report / chart / table 展示增强
   - 分析说明、风险提示、导出展示

3. `工作流交互`
   - 节点配置
   - 调试运行
   - 引导、错误提示、空状态

4. `底层协议与测试`
   - `NodeResult`
   - 节点协议
   - viewer 注册
   - 单元测试 / 集成测试 / 文档同步

## 五、建议的开发顺序

建议按以下顺序推进，而不是完全按文档顺序并行展开：

1. `P0-1`
   - 先统一相关性节点结果结构
2. `P0-2`
   - 再升级结果 viewer
3. `P0-3`
   - 接着补风险提示机制
4. `P0-5`
   - 再补调试体验
5. `P0-6`
   - 最后收口易用性体验
6. `P1-1 / P1-2 / P1-3`
   - 以“新节点 + 结果展示 + 前处理能力”联动推进
7. `P1-4 / P1-5`
   - 图表和导出作为第二批增强
8. `P2-1 / P2-3 / P2-4 / P2-2`
   - 先做模板和复用基础，再做自动摘要
