## 版本 A：投「AI Agent 开发 / LLM 工程师」岗位（推荐主用）

> 这个版本把 Agent 能力完全前置，工作流画布弱化成一句话背景。

### 多 Agent 数据分析平台 ｜ 核心开发 ｜ 2025.01 – 至今

**项目背景**：面向数据分析场景的 AI Agent 平台，含 3 个相互独立、零耦合的 Agent 子系统（工作流编排助手 / 代码编程助手 / 浏览器自由分析笔记本），覆盖"显式编排"与"自由分析"两种 Agent 范式。**技术栈：TypeScript · Pi Agent SDK · Vercel AI SDK · Fastify · Pyodide(WASM)**

**核心工作**：

**① 设计并实现「前端执行 + 后端调度」的 Agent 工具调用架构**
- 针眼问题：工具要修改的"世界状态"（画布数据 / Python 运行时）在浏览器内存里，后端够不到。设计 FrontendBridge 模式——后端只做 LLM 推理与工具调度，工具执行经 SSE 事件下发前端、结果 HTTP 回传、toolCallId 配对 resolve 后端挂起的 Promise
- 实现请求-响应配对、超时续期心跳（长任务如跑 Python 600s，前端每 10s 续期防误杀）、用户级会话隔离；工具元数据共享 spec 单源驱动、前后端按 executorKey 注册、缺失即抛错保证一致性

**② 实现完整的 Agent 规划-执行-诊断工作循环**
- grill-me 式需求澄清（ask_user）→ todo_write 任务规划 → 无状态工具执行 → 停止原因诊断（区分正常结束 / 只读后停止 / 中断 / 失败，并引导续问）
- 支持用户插话排队、followUp 插话、continue 续跑等多种会话恢复语义；会话级记忆持久化 + 断线快照恢复

**③ 多 provider LLM 统一接入 + 标准流式协议**
- 基于 OpenAI-compatible 协议统一接入 DeepSeek / OpenAI / OpenRouter / Groq 等，从 baseUrl 推断 provider；支持对话中热切换模型
- 设计标准 SSE（`text/event-stream`）事件流，承载十几种事件类型（流式文本 / 思考链 / 工具调用 / 会话状态），因原生 EventSource 不支持自定义 header（项目要求所有请求走统一 axios 注入 JWT），采用 fetch + 手写 SSE 解析

**④ 浏览器 Pyodide(WASM) 沙箱 Agent（差异化亮点）**
- 让 LLM 在浏览器 Web Worker 内自由编写并执行 Python，像 Claude Code 那样"跑→看→改假设→再跑"，产出图文报告
- 设计 6 层纵深防御安全模型（WASM 沙箱 / iframe COI 隔离 / Pyodide jsglobals 锁定 / Worker 出站能力剥夺 / 超时配额 / 审计日志）+ 20 项红队回归（含 prompt injection、`os.system`、OOM、跨 session 越界等）

**⑤ 搭建 Agent 评测体系**
- XML 用例集驱动的端到端评测，覆盖 6 个能力维度（目标理解 / 数据画像 / 方法规划 / 工作执行 / 自修复 / 证据报告），每个用例声明 requiredTools 与 acceptance 标准，自动化回归

**架构演进**：经历 3 代 AI 架构迭代（workflow-ai 直接生成 JSON → opencode/MCP → 当前 Pi SDK 工具调用型），每次基于实测果断重构，废弃路径保留 404 回归测试。

## 版本 B：投「AI 应用开发 / 全栈 AI」岗位

> 这个版本 Agent 和全栈工程平衡，前端/后端能力也体现出来，适合看重全栈交付能力的岗位。

### AI 数据分析平台（低代码工作流 + 多 Agent 系统）｜ 全栈核心开发 ｜ 2025.01 – 至今

**项目简介**：一个 AI 数据分析平台——既提供 n8n 风格的低代码工作流（拖拽 ~30 个分析节点搭流程、拓扑执行、产出图文报告），又内建 3 个 AI Agent 子系统（自然语言编排 / 代码编程 / 浏览器 Python 自由分析）。**技术栈：Vue 3 + TypeScript + Vue Flow + Pinia ｜ Node.js + Fastify + Drizzle/MySQL ｜ Pi Agent SDK + Vercel AI SDK ｜ Pyodide(WASM)**

**AI Agent 方向**：
- 设计「前端执行 + 后端调度」的工具调用架构（FrontendBridge）：toolCallId 配对、Promise 挂起/恢复、超时续期；共享 spec 单源驱动工具注册
- 实现规划-执行-诊断 Agent 工作循环（grill 需求澄清 → todo 规划 → 无状态执行 → 停止诊断续问）
- 多 provider LLM 统一接入 + 标准 SSE 流式协议；会话持久化 + 断线快照恢复
- 浏览器 Pyodide 沙箱 Agent：6 层纵深安全模型 + 20 项红队回归；XML 驱动的 6 维度 Agent 评测体系

**工程与全栈方向**：
- 工作流执行引擎（~2700 行核心 store）：拓扑递归执行、冻结输出复用、单节点调试、标准化 NodeResult 协议（统一 ~30 个节点与多种 viewer 解耦）
- 前后端同仓：Fastify 服务端（JWT/CORS/COI 插件）、双存储抽象（LowDB/MySQL + Drizzle ORM，组合根依赖注入）、运行历史大对象上 S3
- esbuild 打包自包含 ESM、统一 axios 请求层、AG-Grid 虚拟滚动 + ECharts 大数据可视化
- 经历 3 代 AI 架构演进与多次重构（纯 HTTP→Fastify、原生 SQL→Drizzle），废弃路径保留回归测试
