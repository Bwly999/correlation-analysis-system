# 多因子相关性分析系统里程碑计划（按开发优先级排序）

本文档基于以下两份文档整理：

- `docs/产品需求路线图-P0-P2.md`
- `docs/开发任务清单-P0-P2.md`

目标不是简单按 `P0 / P1 / P2` 原顺序罗列，而是先梳理开发依赖，再压缩成适合排期的 milestone 列表。

---

## 一、任务依赖关系梳理

### 1. P0 内部依赖

#### 1.1 强依赖

- `P0-2 相关性结果 viewer 升级` 依赖 `P0-1 相关性分析节点增强`
  - 原因：viewer 需要稳定的 report 结构和字段定义，否则会反复返工

- `P0-3 分析风险提示机制` 依赖 `P0-1 相关性分析节点增强`
  - 原因：风险提示最好跟随统一结果结构进入 report / meta，不能先在 UI 层硬编码

- `P0-7 测试与文档` 依赖 `P0-1 ~ P0-6` 的实际改动
  - 原因：需要以最终协议、最终交互和最终文案为准补测试与文档

#### 1.2 弱依赖

- `P0-4 字段可分析性强提示` 与 `P0-6 配置弹窗与上手体验优化` 可以并行推进
  - 原因：都涉及节点配置体验，但一个偏规则校验，一个偏交互层级

- `P0-5 单节点调试体验增强` 可与 `P0-2` 并行
  - 原因：一个偏运行链路和日志，一个偏结果展示，代码冲突相对较少

### 2. P1 内部依赖

#### 2.1 强依赖

- `P1-2 新节点结果展示` 依赖 `P1-1 新增分析节点`
  - 原因：先有稳定输出结构，才能决定复用哪类 viewer

- `P1-4 图表能力升级` 部分依赖 `P1-1 / P1-2`
  - 原因：图表种类和数据结构要跟着节点输出与展示方案一起定

- `P1-5 导出能力升级` 依赖 `P1-2 / P1-4`
  - 原因：导出内容要以最终展示内容和图表能力为准

- `P1-6 测试与文档` 依赖 `P1-1 ~ P1-5`
  - 原因：节点清单、结果协议和 viewer 行为要在能力稳定后统一补齐

#### 2.2 弱依赖

- `P1-3 前处理节点增强` 可与 `P1-1 新增分析节点` 并行
  - 原因：前处理增强和新分析节点是两条并行主线，只需在协议层保持一致

### 3. P2 内部依赖

#### 3.1 强依赖

- `P2-1 分析模板体系` 依赖 `P0 / P1` 的核心节点和交互稳定
  - 原因：模板必须建立在稳定节点能力与配置结构之上

- `P2-2 自动结果摘要` 依赖 `P0-1 / P0-2 / P0-3` 和 `P1-2`
  - 原因：摘要生成要基于稳定的结果结构、风险结构和展示结构

- `P2-3 配置导入导出` 依赖工作流存储结构稳定
  - 原因：如果节点属性、结果结构频繁变化，导入导出兼容会反复改

- `P2-4 结果快照分享` 依赖结果展示结构和存储方案稳定
  - 原因：快照不是简单截图，而是结构化结果保存

- `P2-5 测试与文档` 依赖 `P2-1 ~ P2-4`

#### 3.2 弱依赖

- `P2-1 模板体系` 与 `P2-3 配置导入导出` 最好联动设计，但不必同一批次开发完成

### 4. 跨阶段关键依赖

- `P1` 不必等待 `P0` 全部完成，但至少要等 `P0-1 相关性结果结构` 与 `P0-6 基础配置体验` 初步稳定
- `P2` 不建议在 `P1-1 / P1-2` 之前启动，否则模板和摘要会建立在不稳定能力上
- `导出能力` 不应早于 `viewer 结构` 定稿，否则导出内容会反复调整
- `配置导入导出` 不应早于 `节点配置结构` 基本稳定，否则兼容成本会很高

## 二、优先级排序原则

排序采用以下判断标准：

1. `先做基础结构，后做展示包装`
   - 结果结构、节点协议优先于 viewer 和导出

2. `先做高频使用链路，后做增强能力`
   - 相关性分析主链路优先于新算法节点

3. `先做会影响后续返工成本的能力`
   - 节点结构、结果协议、存储结构优先

4. `先做用户立即感知价值高的能力`
   - 可信提示、可读结果、调试和配置体验优先

## 三、Milestone 列表

以下 milestone 不是严格按季度切，而是按“依赖关系 + 用户感知价值 + 返工成本”排序。

### Milestone 1：P0 基础结果结构定型

目标：

先把相关性分析主链路的结果结构定下来，给后续 viewer、风险提示、摘要、导出打底。

包含任务：

- [x] `P0-1` 相关性分析节点增强
- [x] `P0-3` 分析风险提示机制中的结果结构设计部分
- [x] `P0-4` 字段可分析性强提示中的运行前字段合法性规则

为什么排第一：

- 这是所有 P0 展示能力的底座
- 这一步不稳定，后面的 viewer、导出、摘要都会返工

完成标志：

- Pearson / Spearman / Kendall 输出结构统一
- 风险提示进入标准结果结构或约定字段
- 基础字段合法性规则可复用

### Milestone 2：P0 结果展示与配置体验上线

目标：

把结构化结果变成用户可理解、可操作的界面体验。

包含任务：

- [x] `P0-2` 相关性结果 viewer 升级
- [x] `P0-6` 配置弹窗与上手体验优化
- [x] `P0-4` 字段可分析性强提示中的配置层提示和禁用交互

为什么排第二：

- 这是用户最直接感知到“产品升级”的部分
- 依赖 Milestone 1 的稳定输出结构

完成标志：

- 相关性结果页支持热力图、Top N、字段切换、结果解释、风险展示
- 节点配置更容易填写
- 用户能在配置阶段发现明显错误字段

### Milestone 3：P0 调试闭环与稳定性收口

目标：

提升调试和排障效率，完成 P0 的可用性闭环。

包含任务：

- [x] `P0-5` 单节点调试体验增强
- [x] `P0-7` P0 对应测试与文档更新

为什么排第三：

- 这是让 P0 真正能稳定交付的收口阶段
- 适合在核心交互和结果结构稳定后统一补齐

完成标志：

- 调试与全局执行策略清晰可感知
- 常见错误信息可定位
- 测试和文档与最终行为一致

### Milestone 4：P1 分析节点扩容

目标：

补齐最有价值的新分析节点，扩大分析能力边界。

包含任务：

- [ ] `P1-1` 新增分析节点
- [ ] `P1-2` 新节点结果展示中的结果结构设计部分

建议节点顺序：

1. 多元线性回归
2. VIF 共线性检测
3. PCA 主成分分析
4. 随机森林特征重要性
5. 方差分析

为什么这样排：

- 多元线性回归 + VIF 是和当前相关性分析最自然衔接的一组能力
- PCA 是典型分析增强能力
- 随机森林和方差分析更偏补充型增强

完成标志：

- 新节点可被创建、配置、执行
- 每个节点有清晰的最小结果结构

当前进展：

- [x] 多元线性回归节点已完成
- [x] 随机森林特征重要性节点已完成
- [x] 方差分析节点已完成
- [x] VIF 共线性检测节点已完成
- [x] PCA 主成分分析节点已完成

### Milestone 5：P1 前处理增强

目标：

把最关键的分析前处理能力纳入工作流。

包含任务：

- [ ] `P1-3` 前处理节点增强

建议能力顺序：

1. 标准化 / 归一化
2. 去重
3. 时间窗口聚合

为什么排在新节点之后：

- 新节点先落地，能更明确反推前处理能力的真实需求
- 避免前处理节点先做很多，但短期没有足够分析节点消费

完成标志：

- 至少 3 项前处理能力可稳定进入当前工作流主链路

### Milestone 6：P1 图表与导出收口

目标：

把 P1 的分析结果做成可解释、可沉淀、可输出的成果。

包含任务：

- [ ] `P1-2` 新节点结果展示的界面实现部分
- [ ] `P1-4` 图表能力升级
- [ ] `P1-5` 导出能力升级
- [ ] `P1-6` P1 对应测试与文档更新

为什么排在这里：

- 这批任务高度依赖前面的节点结构和 viewer 结构
- 适合做成 P1 的统一收口

完成标志：

- 新节点有完整展示方案
- 图表能力能支持核心分析结果
- 导出能力口径明确并可用

### Milestone 7：P2 轻量复用基础

目标：

通过模板和配置导入导出，建立最小复用能力。

包含任务：

- [ ] `P2-1` 分析模板体系
- [ ] `P2-3` 配置导入导出

为什么排在自动摘要前：

- 模板和配置复用是“工作方式沉淀”的基础
- 先有复用能力，再做摘要更合理

完成标志：

- 用户可从模板快速创建流程
- 工作流可导入 / 导出复用

### Milestone 8：P2 结果沉淀与分享

目标：

把分析结果从“当前页面可见”升级成“可沉淀、可传播”。

包含任务：

- [ ] `P2-4` 结果快照分享
- [ ] `P2-2` 自动结果摘要
- [ ] `P2-5` P2 对应测试与文档更新

为什么排最后：

- 这批任务对结果结构、viewer 结构和存储方案稳定性要求最高
- 放到最后返工成本最低

完成标志：

- 结果可快照保存与查看
- 结果页可自动生成中文摘要

## 四、推荐的实际排期节奏

如果按 3-6 个月推进，建议节奏如下：

1. `第 1 阶段`
   - Milestone 1
   - Milestone 2

2. `第 2 阶段`
   - Milestone 3
   - Milestone 4

3. `第 3 阶段`
   - Milestone 5
   - Milestone 6

4. `第 4 阶段`
   - Milestone 7
   - Milestone 8

如果资源紧张，可压缩为：

1. 先完成 `Milestone 1 ~ 3`
2. 再完成 `Milestone 4`
3. 最后从 `Milestone 5 ~ 8` 中按资源择优推进

## 五、最值得优先盯住的关键路径

真正的关键路径不是全部任务，而是下面这条链：

1. `P0-1`
   - 统一相关性结果结构
2. `P0-2`
   - 让结果真正可展示、可理解
3. `P0-5`
   - 让调试和报错可排查
4. `P1-1`
   - 增加新的分析能力
5. `P1-2 / P1-4`
   - 补齐新分析能力的展示和图表
6. `P2-1 / P2-3`
   - 形成模板和复用机制
7. `P2-2 / P2-4`
   - 形成摘要和结果沉淀

如果这条链走顺，产品会逐步从：

`能跑相关性分析`

升级为：

`能做多种分析、结果可信、还能复用与沉淀`
